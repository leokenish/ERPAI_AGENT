## 3. 실제 확인한 범위

### 3.1 대화

이 요청에 제공된 현재 대화의 사용자 요구·수정·오류 보고·보이는 이미지를 읽었다. 날짜 없는 메시지는 문장 시작 또는 주제로 식별한다. 과거 응답과 실행 로그 전체가 대화 본문에 모두 제공된 것은 아니므로, 과거 구현·검증 내용은 확보한 소스·기존 MD와 대조했다. [대화 결정 발췌](references/conversation_decisions.txt)는 전체 채팅 원문이 아니다.

### 3.2 파일

접근 가능한 최신 원본을 다시 확보하여 Export·DIAG 소스의 관련 구간, 기존 설명 문서, HTML 점검기 버전·점검 로직, ZHR5 엑셀과 이미지 2개를 확인했다. 소스 관련 구간 확인은 9천여 줄 전체의 SAP 실행 감사를 뜻하지 않는다.

`ZHR5_KNOWLEDGE_KIT_20260922.zip`은 파일 목록과 선택 MD·스킬을 확인했다. 원본 PDF 4개·TXT 7개(카카오톡 5개, Summary·FAQ)를 이번 추출에서 모두 다시 분석한 것은 아니다. 키트의 기존 검증 기록을 직접 읽은 것과 원자료를 재검증한 것을 구분한다.

엑셀은 **15개 시트 중 `RawData`의 데이터 2,541행**을 집계했다. 표시용 시트의 반복 값 생략·잘림을 실제 조회 실패로 오해하지 않았다. 세부 읽기 범위는 [자료 목록 A](03_자료목록과보완사항.md)에 기재했다.

### 3.3 이번에 직접 확인된 정정

기존 맥락에 “71건 함수 확인 실패”라는 표현이 있었으나, 실제 엑셀은 **함수 API 소스 70건 + DDIC 진단 1건**이다. 이 묶음의 본문은 엑셀에 따라 정정했다. 과거 인계서는 원본을 보존하므로 표현이 남아 있으며 현행 통합 시 이 정정을 우선한다. 출처: [결과 엑셀](attachments/results/ZHR5_result_uploaded_20261007.xlsx) `RawData!J2:J2542`, 구성요소 C열, [파생 집계](examples/ZHR5_result_facts_derived.json).

- 해당 엑셀을 만든 실행의 정확한 도구 버전·실행 시각, 대응하는 전체 원본/수정 패키지 ZIP 및 당시 SAP 내용.
- ZWEB 전체 추출 ZIP, 초기 GitHub 통신 테스트 ABAP 원본·ICM 로그 전문.
- 현재 대화에서 파일 경로 오류로 열리지 않는 다수 캡처 원본. 확보한 두 PNG 외의 최신 UI 캡처.
- 키트의 원본 업무 PDF·카톡 전문 재분석, 최신 규정 효력·담당자 승인.

파일을 찾지 못했다고 존재하지 않는다고 단정하지 않았다. 문서에 이름만 남은 파일은 확보·포함으로 표시하지 않는다.

## 5. 상태와 근거를 읽는 규칙

| 표기 | 의미 |
|---|---|
| 제안 | 논의된 아이디어. 코드·운영 존재를 보장하지 않음 |
| 결정 | 사용자 지시 또는 확정된 방향 |
| 구현 확인 | 접근 가능한 소스·문서에서 반영을 확인함 |
| 검증 기록 | 문서나 사용자 결과에 특정 검증 기록이 있음. 범위·버전 제한 있음 |
| 이번 재확인 | 이번에 파일을 읽거나 실제 집계한 내용 |
| 운영 확인 | 지속 운영의 증거가 있을 때만 사용. 현재 대부분 해당 없음 |
| 미확인 | 근거 부족·원본 미확보·실행 미수행 |

소스 파일을 작성했다고 SAP 검증 완료로 쓰지 않는다. 규정과 대화, 소스의 구현, 사용자 실행 보고도 서로 다른 근거다. 현재 결정은 과거 제안보다 우선하지만 코드·실행이 따라왔는지 따로 확인한다.

## 6. 다른 프로젝트 자료와의 통합

중복 가능 범위는 Codex Desktop 시작, Git clone/publish, `AGENTS.md`, 스킬·업무 지식 관리, Actions·하네스, 패키지별 에이전트 협업이다. 여기서는 **이 프로젝트가 실제 요구하고 전달한 방식**을 기록했으며 범용 제품 매뉴얼을 대체하지 않는다.

통합자는 최신 운영 저장소·날짜·버전을 대조하여 중복 설명을 합치되, SAP_BASIS 700 제약, 읽기 전용 결정, 원본 보존, 상태 구분, 업무 문서의 시점·출처는 생략하지 않아야 한다. ERP MCP·Obsidian·Node.js·KBS 도메인 운영은 다른 프로젝트에서 확인할 입력이다.

원본 사본에는 사내 객체명·시스템 식별·사용자 식별 등의 업무 정보가 있을 수 있다. 이 패키지는 팀 내부 교육 자료이며 공개 배포 전 별도 검토가 필요하다. 인증값을 새로 넣지 않았고 예시는 대체값을 사용했다. 기존 원본 자체는 수정하지 않았다.

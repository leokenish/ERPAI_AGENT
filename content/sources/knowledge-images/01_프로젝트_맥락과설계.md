# 카카오톡에서 추출한 업무맥락 — 프로젝트 맥락과 설계

- 프로젝트명: 카카오톡에서 추출한 업무맥락
- 대화 주제: TXT·이미지 연계와 업무맥락 MD 보완
- 정리 기준일: 2026-10-08, Asia/Seoul
- 추출 묶음 버전: 1.0
- 읽기 전제: [00_README.md](00_README.md)의 확인 범위·상태 구분을 적용한다.

## 1. 배경, 기존 문제, 목표

사용자는 AI 에이전트가 업무를 이해하도록 업무 주관부서 담당자와의 카카오톡 대화를 TXT로 추출해 업무파일을 MD화했다고 설명했다. 대화 텍스트는 잘 들어갔지만 첨부 이미지는 읽지 못했다는 점이 한계였다. 사용자가 추가로 발견한 단서는 카카오톡에서 받은 이미지에 날짜와 시간이 표시된다는 것이었다. [D1]

사용자의 질문은 이미지마다 대화 위치를 수작업으로 지정하지 않고, 이미지 묶음과 TXT를 함께 제공하면 AI가 대략 어느 대화에서 쓰였는지 추정해 더 정확한 업무맥락을 만들 수 있는지였다. 단순 이미지 설명이 아니라 **업무 협의의 맥락 복원**이 목적이다. [D1]

제안된 해결 방향은 시간 기반 후보 탐색과 내용 대조를 함께 수행하고, 그 근거를 MD에 남기는 것이다. 다만 실제 이미지가 어떤 내용을 담았는지, TXT만으로 작성한 MD에 어떤 오해가 생겼는지는 이 대화에서 구체적으로 입증되지 않았다. ‘이미지가 없어서 오답이 발생했다’는 별도의 사례를 만들어 넣지 않는다. [D1, D2]

## 2. 대상 업무와 범위

### 2.1 이번 프로젝트의 직접 범위

- 업무 담당자와의 대화에서 요청·설명·합의·처리 이력을 읽어내는 일.
- TXT에서 빠진 이미지 정보를 원본 이미지와 대조하여 보완하는 일.
- 출처가 추적되는 업무맥락 MD를 만드는 방법.
- 이미지 연결의 불확실성과 완료 여부를 구분하는 방법. [D1, D2]

D1은 구체적인 개발 패키지나 업무유형을 명시하지 않았다. 관련 자료 후보가 근로시간·시간외 업무를 다룬다는 이유만으로, D1의 모든 대상 파일을 ZHR5 자료라고 확정하지 않는다.

### 2.2 이번 추출에서 수행하지 않는 일

웹사이트 구현, 서버 설치, GitHub push는 사용자가 명시적으로 제외했다. SAP 로직·데이터 변경, 운영 지급·정산·결재 처리, 스킬 설치·갱신, 이미지의 실제 대화 연결 실행도 하지 않았다. 이번 작업은 교육용 자료 추출이다. [D3]

|---|---|---|

| 기존 결과물 | 업무 MD를 만들었다는 사용자 보고 [D1] | 파일명·폴더·본문·버전 미확인 |
| 이미지 시각 | 날짜와 시간이 나온다는 사용자 관찰 [D1] | 채팅의 전송 시각인지, 파일명인지, 파일 속성인지, 촬영 시각인지 미확인 |
| AI 환경 | AI 에이전트를 사용했다고 설명 [D1] | 사용 제품·모델·이미지 읽기 방식·오류 로그 미확인 |

| 교육 포털 계획 | MD 원본, HTML·CSS·JavaScript, GitHub, Mac·Codex Desktop, Node.js, 사내망·KBS 도메인 [D3 §1] | 계획이며 이 프로젝트에서 구축된 환경은 아님 |

날짜·시간만으로 연결하지 말아야 한다는 점은 D2에서 이미 지적됐다. 파일 생성·수정 시각이 다운로드나 복사 과정의 시각일 수 있으므로 먼저 의미를 확인한다. 이 문서에서는 특정 카카오톡 버전의 파일명 규칙이나 메타데이터 보존 동작을 새로 단정하지 않는다. 해당 환경의 실물 비교가 남아 있다. [D2]

## 4. 구성 요소별 역할과 연결 관계

아래는 D2의 제안을 교육용으로 구조화한 것이다. 구현된 시스템 구성도가 아니다.

| 구성 요소 | 제공하는 근거 | 연결 대상 | 하지 않는 일 |
|---|---|---|---|
| 대화 TXT | 발화자, 날짜·시간, 사진 표시, 질문·답변 | 이미지 후보 및 협의 사안 | 사진 표시만으로 이미지 내용을 제공하지 않음 |
| 이미지 원본 | 실제 화면·문구·표·숫자 | TXT의 앞뒤 설명 | 화면 상태만으로 최종 업무정책이나 처리 완료를 입증하지 않음 |
| 시각 출처 기록 | 전송·촬영·다운로드 등 시각의 종류와 확인 근거 | 시간대 비교 | 종류가 불명확한 시각을 전송 시각으로 바꾸지 않음 |
| 연결 기록 | 대화 구간과 이미지의 후보·근거·확신도 | 검수와 MD 작성 | 모든 이미지를 강제로 한 대화에 배정하지 않음 |
| 기존 MD | 이미 정리한 업무맥락 | 이미지 보완 전후 비교 | 원문보다 우선하는 확정 근거로 취급하지 않음 |
| 담당자 검수 | 애매한 후보 판단, 요청·합의의 의미 확인 | 지식 승인 상태 | 파일을 만들었다는 사실만으로 검수 완료 처리하지 않음 |
| 보완 MD | 확인된 내용, 출처, 미확인 사항 | 에이전트 참고·교육 포털 | SAP 운영 데이터나 실제 구현을 자동 변경하지 않음 |

연결 기록은 TXT·이미지·기존 MD가 만나는 지점이다. 기존 MD에서 출처가 약한 항목은 원문으로 돌아가 확인하고, 확인할 수 없는 부분은 미확인 상태로 유지한다. [D2, S1; 연결 기록 형식은 이번 교육 초안에서 구체화]

## 5. 입력 → 처리 → 출력 흐름

### 5.1 실제 보고된 흐름

카카오톡 대화 → TXT 추출 → 업무 MD 작성까지는 사용자가 수행했다고 보고했다. 이미지 반영은 이 과정에서 되지 않았다. 실제 파일과 작업 로그를 확인한 것은 아니다. [D1]

### 5.2 제안된 보완 흐름

| 단계 | 입력 | 처리 | 출력 | 현재 상태 |
|---|---|---|---|---|
| 1. 자료 접수 | TXT, 원본 이미지, 기존 MD | 대상 범위·파일명·누락 확인 | 입력 목록 | 제안 [D2] |
| 2. 시간 의미 확인 | 이미지 시각과 메시지 시각 | 전송 시각과 다운로드 등 다른 시각 구분 | 시각 종류·확인 근거 | 제안 [D2] |
| 3. 후보 대화 찾기 | 사진 표시와 앞뒤 메시지 | 시간·대화 흐름별 후보 구간 구성 | 후보 목록 | 제안 [D2] |
| 4. 이미지 판독 | 이미지 실물 | 화면명·수치·오류 문구 등 읽기 | 관찰 사실·판독 불가 표시 | 제안 [D2] |
| 5. 내용 대조 | 후보 구간과 관찰 사실 | 일치·충돌·복수 후보 검토 | 연결 근거·확신도 | 제안 [D2] |
| 6. 지식 보완 | 연결 결과·기존 MD | 사실·요청·합의·결과 구분 | 보완 MD 초안 | 제안 [D2] |
| 7. 검수 | 초안과 원문 | 사람이 연결·해석·미확인 상태 확인 | 검수 기록·수정 사항 | 이번 교육 초안의 절차 구체화, 미실행 |

이미지가 여러 장이면 대화 구간별로 나누어 검토하는 방안이 D2에 제시됐다. 한 장씩 대응되는 관계만 가정하지 않는다. 여러 이미지가 한 사안을 설명하거나 한 이미지가 다른 시점에 다시 언급될 가능성은 실제 자료에서 판단할 항목이다. [D2; 다대다 기록은 교육용 보완 제안]

## 6. 사람·AI·프로그램의 역할

| 주체 | 담당할 작업 | 확인·승인이 필요한 경계 |
|---|---|---|
| 사용자·자료 소유자 | 대상 TXT·이미지·기존 MD 지정, 자료 제공, 시각 표시 화면 설명 | 어떤 대화방 자료인지, 사내 교육에 공유할 수 있는지 |
| AI | 대화 읽기, 이미지 관찰, 연결 후보·근거 작성, MD 초안 보완 | 판독 불가, 애매한 연결, 정책 해석, 최신성은 확정하지 않음 |
| 업무 주관부서 담당자 | 요청·합의·완료의 실제 의미와 적용 대상 검수 | 과거 협의가 현재도 유효한지 |
| 파일 처리 프로그램 | 필요 시 목록·행번호·중복·링크 등의 기계적 검사 | 자동 추출값을 의미상 정답으로 간주하지 않음 |
| 통합 담당자 | 다른 프로젝트와 출처·용어·상태 대조, 포털 콘텐츠 편집 | 원본·교육본·웹 배포물의 역할 혼합 방지 |

D2는 특정 OCR 엔진, 자동 매칭 프로그램, API, 데이터베이스를 선정하지 않았다. 프로그램 역할은 교육용 구현 후보일 뿐, 설치된 도구 목록이 아니다.

## 8. 검토 후 제외한 대안과 실패한 시도

| 항목 | 실제 확인 내용 | 제외·실패 여부 |
|---|---|---|
| TXT만 이용한 MD | 사용자가 이미 만들었다고 보고 | 폐기된 것은 아님. 이미지 근거가 빠진 보완 대상 [D1] |
| 이미지 날짜·시간만 이용 | 사용자 질문의 출발 단서 | D2에서 단독 사용의 위험을 설명했지만 별도 방식 비교 시험은 없음 |
| TXT의 사진 표시로 내용 복원 | 표시를 위치 후보로 쓰자는 제안 | 실물 없이 내용까지 복원할 수 있다고 제안한 것이 아님 [D2] |
| 모든 이미지를 자동 확정 연결 | 확인된 제안·실행 없음 | 이번 교육 초안에서는 미연결·복수 후보를 허용하도록 제한 |
| 특정 OCR·벡터DB·임베딩·MCP로 해결 | 이 대화에서 선정·비교 기록 없음 | 평가해서 탈락한 대안으로 쓰면 안 됨 |

확인된 실패 경험은 ‘첨부 이미지를 읽지 못했다’는 사용자 보고뿐이다. 파일 형식, 도구 지원, 접근권한, 업로드 누락, 해상도 중 무엇이 원인이었는지는 알 수 없다. 이 중 하나를 원인으로 단정하지 않는다. [D1]

## 9. 사용자 피드백에 따른 변화

| 단계 | 요구·피드백 | 정리 방향의 변화 |
|---|---|---|
| 기존 작업 | 대화 TXT를 업무 MD로 작성 | 텍스트 중심 지식화 [D1] |
| 부족함 제기 | 대화는 들어갔지만 첨부 이미지는 읽지 못함 | 이미지 근거를 포함하는 보완 필요성 제기 [D1] |
| 추가 단서 | 받은 이미지에 날짜·시간이 표시됨 | 시간과 내용으로 대화 연결을 검토 [D1, D2] |
| 이번 요청 | 팀 교육용으로 목적·변경·실패·출처를 보존 | 방법 안내를 상태·근거가 있는 통합 입력 자료로 재구성 [D3] |

이 변화는 요구와 설계 범위의 변화다. 기존 MD가 실제 수정됐거나 이미지 인식 문제가 해결됐다는 뜻은 아니다.

## 10. 현재 방안과 과거 방안

- 과거 작업: TXT에서 업무맥락 MD 작성. 사용자 보고이며 결과물 미검증. [D1]

### 13.2 실제 자료가 있어야 가능한 검증

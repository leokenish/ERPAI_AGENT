- JSON schema_version: `1.0`
- 확보 수준: **partial — 확인 가능한 공개 발화의 원문은 보존했으나, 프로젝트 전체 원문과 업무 입력 자료는 일부 미확보**

## 1. 이 묶음에서 배울 수 있는 것

사용자는 업무 주관부서와의 카카오톡 대화를 TXT로 추출해 업무맥락 MD를 만들었으나, 첨부 이미지가 반영되지 않았다고 보고했다. 이미지의 날짜·시간과 대화 내용을 대조해 이를 보완하는 방안을 논의했고, 이후 해당 과정을 교육 포털용 자료로 추출하도록 요구했다.

이 묶음은 그 목적·요청·답변·확인 범위의 조정·문서 생성·파일 검증을 보존한다. **실제 이미지 매칭 성공 기록이나 ERP 변경 실습은 없다.** 그 공백을 성공 사례로 채우지 않았다.

## 5. 원문·해설·실습의 구분

1. `messages.content_markdown`: 실제 공개 발화. 당시 예시·단정적 표현·오류를 원문 안에서 고치지 않았다.
2. `episodes.commentary_markdown`: 이번에 작성한 교육 해설. 원문 채팅 말풍선과 다른 스타일로 보여준다.
3. `episodes.exercise_markdown`: **교육용 재작성 프롬프트**와 확인 방법. 실제 사용자 발화가 아니다.
4. `assets/20261008_validation_excerpt.md`: 도구 응답 발췌 및 명시적인 변경 요약. 사용자 발화도 전체 실행 로그도 아니다.
5. 기존 MD: 당시 작성된 요약·교육 문서. 원문 대화의 대체물이 아니다.

원문 `kwc-m002`의 시간외 단가 사례와 ‘연결 확신도: 높음’은 가상 예시다. 실제 매칭 성공·업무정책 확정으로 표시하면 안 된다. 해당 원문은 그대로 보존하고 학습 1에서 이 제한을 설명한다.

## 6. 마스킹과 원본 보존

발화 10개에는 이번 마스킹 대상이 없어 `redacted=false`다. 과거 첨부 MD 4개 중 2개에 등장하는 개인 이름은 `[담당자A]` 등의 별칭으로 바꿨다. 두 나머지 MD는 확보 원본과 바이트 동일하다.

원본 ZIP 자체는 수정하지 않았다. 포함한 과거 ZIP은 마스킹된 MD를 다시 묶은 사본으로 파일명과 설명에 표시했다. 마스킹 위치와 원본·사본 해시는 별도 기록한다. 명시적 마스킹 외에 과거 MD의 내용·상태·판단을 몰래 정정하지 않았다.

## 7. UI 통합 시 읽는 규칙

- `sequence`가 대화의 정렬 기준이다. null 시각을 현재 시각이나 자정으로 바꾸지 않는다.
- `kwc-*`는 자체 ID다. 실제 플랫폼 ID로 표시하지 않는다.
- `episodes.message_refs`로 핵심 구간을 표시하되 전체 대화 보기도 제공한다.
- 첨부는 `asset_ids`→`assets.path`로 연다. 원문 발화 안에 있는 당시 sandbox 링크는 보존된 역사적 링크이므로 포털 파일 링크로 그대로 사용하지 않는다.
- `path`는 이 묶음의 최상위 폴더를 기준으로 한 상대경로다. ZIP을 그대로 둘 경우 최상위 폴더명을 앞에 붙인다.
- `availability=unavailable`이면 다운로드 링크를 만들지 않고 ‘원본 미확보’를 표시한다.
- 구성도 연결은 `knowledge`, `codex`, `feedback`, `portal`만 사용했다. `codex`는 지침·스킬을 활용한 정리, `feedback`은 검수 기준의 설명 범위다. 실제 데스크탑 환경 실행이나 담당자 검수 완료로 표현하지 않는다.
- 일반 파일 검사를 `diag`에 연결하지 않았다. 이 프로젝트에서 DIAG 프로그램을 수행한 증거가 없기 때문이다.

## 8. 제출 전 확인의 범위

JSON 파싱, 필수 필드, ID 중복, 발화 순서, 참조 무결성, 첨부 존재, 마스킹, 문서 링크, ZIP 파일 일치를 검사했다. 결과는 `assets/validation-report.json`에 있다. 자동 검사는 전사 원문의 의미적 정확성이나 업무정책의 진실성을 보장하지 않는다. 발화는 현재 표시된 텍스트와 수동 대조했으며, 플랫폼 export와의 기계적 비교는 원본 export 미확보로 수행하지 못했다.

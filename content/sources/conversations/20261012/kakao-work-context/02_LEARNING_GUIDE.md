# 실제 대화를 따라가는 교육 과정

- 프로젝트명: 카카오톡에서 추출한 업무맥락
- project_id: `kakao-work-context`
- 추출일: 2026-10-12, Asia/Seoul
- 학습 자료: [실제 발화 10개](03_CONVERSATION_TRANSCRIPT.md), [UI 연결 JSON](conversation-data.json)

이 단원에서는 자료 누락을 발견하고 AI에게 요구를 구체화하며, 확인 가능한 결과와 미확인 부분을 나누는 과정을 배운다. 실제 이미지 매칭 성공 사례를 재현하는 단원은 아니다. 문서·JSON 검수는 제공 파일로 가능하고, 이미지 매칭 실습에는 추가 원본이 필요하다.

## 1. TXT의 이미지 누락을 문제로 정의하기 — kwc-e01

### 1.1 학습 목표

기존 결과의 부족한 점을 구체적으로 설명하고, 새로 발견한 단서를 AI에게 제공한다. 이미지 연결과 업무 사실 판단을 분리한다.

### 1.2 들어오기 전 상황과 준비물

사용자는 업무 대화를 TXT로 추출하고 MD를 만들었다고 보고한 상태였다. 교육생은 자기 업무의 TXT·기존 MD·원본 이미지를 준비해야 실제 실습을 할 수 있다. 이 묶음에는 그 업무 원본이 없다.

### 1.3 관련 실제 발화

`kwc-m001 → kwc-m002`. 구성도: `knowledge`.

### 1.4 사용자가 요구한 핵심

대화 텍스트는 들어갔지만 이미지가 읽히지 않았다는 한계를 알리고, 이미지 날짜·시간을 이용해 대화 위치를 추정해 MD를 더 정확하게 만들 수 있는지 물었다. 일반적인 “더 잘 정리해줘”보다 입력과 누락을 구체적으로 제시했다.

### 1.5 AI의 대응과 결과물

AI는 시간·사진 표시·이미지 내용·전후 맥락을 함께 대조하는 설계, 지식카드 예시, 후속 요청 프롬프트를 답변으로 제공했다. 이 단계에서 실제 이미지 연결표나 보완 MD 파일을 만든 것은 아니다.

### 1.6 오류·누락 또는 중요한 판단

실제로 보고된 누락은 이미지 미반영이다. 원인과 해결 결과는 없다. “가능해”라는 답변과 ‘확신도 높음’이라는 예시를 성공 검증으로 읽지 않는다. 기존 답변을 몰래 고치지 않고 해설에서 이 한계를 설명한다.

### 1.7 추가 설명과 수정이 필요했던 이유

날짜·시간만으로는 전송 시각인지 파일 저장 시각인지 알 수 없기 때문이다. 또 오류 화면에서 관찰한 값이 정상 업무 기준을 뜻하지 않을 수 있다. 자료의 시간 의미와 업무 상태를 별도 확인해야 한다.

### 1.8 다음 단계로 넘어갈 근거

보완 설계가 제시됐다는 근거는 있다. 매칭 성공 근거는 없다. 실제 매칭을 이어가려면 원본·시각 확인 화면·정답 연결이 필요하다. 대화의 다음 단계는 매칭 실행이 아니라 교육자료 추출 요청으로 전환됐다.

### 1.9 자기 업무 실습

**교육용 재작성 프롬프트** — 실제 사용자 발화가 아니다.

```text
내 업무의 대화 TXT·이미지·기존 MD를 확인해줘.
기존 결과에서 빠진 이미지 근거를 보완하려고 해.
이미지의 날짜·시간이 무엇을 뜻하는지 확인하고,
TXT의 사진 표시·앞뒤 발화·이미지 속 화면명과 값을 대조해줘.
각 연결의 근거·경쟁 후보·미확인 사항을 남겨줘.
관찰 사실, 담당자 요청, 합의, 완료보고, 실제 검증을 분리해줘.
원본을 수정하거나 ERP에 반영하지 마.
```

### 1.10 결과 확인과 흔한 실패

사람이 확인한 표본 연결과 비교한다. 실제 이미지가 없으면 이 단계의 실습을 완료했다고 표시하지 않는다. 사진 표시만으로 이미지 내용을 지어내거나, 파일 수정 시각만으로 자동 확정하거나, AI의 자기평가를 정답으로 사용하는 것이 흔한 실패다.

### 1.11 관련 자료

JSON의 `kwc-a-source-txt`, `kwc-a-source-md`, `kwc-a-source-images`는 모두 원본 미확보다. 실제 캡처를 대신할 생성 이미지는 제공하지 않는다. 당시 예시는 `kwc-m002`에서 볼 수 있다.

## 2. 교육 추출의 범위와 근거를 구체화하기 — kwc-e02

### 2.1 학습 목표

### 2.2 들어오기 전 상황과 준비물

이미지 연계 설계는 있었지만 실제 성공 결과는 확인되지 않았다. 사용자는 여러 프로젝트를 합칠 교육 포털을 계획했다. 현재 프로젝트명, 확보한 대화·파일, 제출 형식을 준비한다.

### 2.3 관련 실제 발화

`kwc-m003 → kwc-m004 → kwc-m005 → kwc-m006`. 구성도: `knowledge`, `codex`, `portal`.

### 2.4 사용자가 요구한 핵심

MD 4개와 ZIP을 지정하고, 출처·실제 확인 범위·실패·수정·검증 상태를 보존하도록 했다. 웹 구현·서버 설치·push는 제외했다. 이 긴 요구문도 JSON에서 축약하지 않았다.

### 2.5 AI의 대응과 결과물

AI는 관련 파일을 확인하되 타 프로젝트 자료를 현재 프로젝트 실적으로 포함하지 않겠다고 설명했다. 정제 TXT 4개는 같은 기존 MD인지 확인되지 않아 참고 후보로 남겼다. 이 판단은 이후 README와 자료목록에 반영됐다.

### 2.6 오류·누락 또는 중요한 판단

검색 결과가 관련 있어 보인다는 사실과 실제 대상 파일임을 확인한 사실은 다르다. 후보 일부만 읽은 결과를 전체 분석으로 표시하면 교육생이 잘못된 근거 수준을 배우게 된다.

### 2.7 추가 설명과 수정이 필요했던 이유

통합 대상에는 GitHub·MCP·Obsidian 등 많은 프로젝트가 있지만 이 대화방에서는 그것들의 실제 구현을 다루지 않았다. 따라서 교육 주제를 채우기 위해 관련 일반 설명이나 타 프로젝트 작업을 추가하면 원문 맥락이 왜곡된다.

### 2.8 다음 단계로 넘어갈 근거

자료가 불완전해도 확인 가능한 범위로 우선 완성하고 부족한 점을 목록에 남기라는 사용자 지시가 있었다. 이는 누락을 숨길 권한이 아니라 한계를 표시하며 문서를 완성할 근거다. [kwc-m003]

## 3. 문서를 생성하고 검증의 한계를 밝히기 — kwc-e03

### 3.1 학습 목표

AI의 “만들었다·확인했다”라는 보고를 실제 파일·도구 결과와 비교하고, 업무 검증까지 과장하지 않는다.

### 3.2 들어오기 전 상황과 준비물

산출물 구조와 확인 범위를 정한 뒤 MD를 만드는 단계다. 이번 묶음에 포함한 이전 MD 4개, 마스킹 ZIP, 검사 발췌로 파일 검수 실습을 할 수 있다.

### 3.3 관련 실제 발화

`kwc-m007 → kwc-m008 → kwc-m009`. 구성도: `knowledge`, `feedback`, `portal`.

### 3.4 사용자가 요구한 핵심

앞선 `kwc-m003`에서 파일 간 상태·용어·버전의 일관성, 상대경로와 ZIP 포함 파일의 일치, 실제 다운로드 파일을 요구했다. 새로운 검증 지시 발화를 만들어 덧붙이지 않는다.

### 3.5 AI의 대응과 결과물

AI는 연결 확신도와 업무 상태를 구분한 MD 4개를 작성하고 링크·압축 검사 뒤 ZIP을 전달했다. 실제 파일 내부 버전은 1.0이다. 이 파일은 처음 사용자에게서 보고된 선행 업무 MD와 다른 교육 산출물이다.

### 3.6 오류·누락 또는 중요한 판단

전달 전 파일 작업에서 불필요한 외국어 문장과 링크 앵커를 수정한 기록이 있다. 이를 사용자 지적 대화로 복원하지 않는다. 검사 결과는 링크 13개와 ZIP 구조·바이트 일치이며 실제 업무 이미지의 판독·매칭 결과는 아니다.

### 3.7 추가 설명과 수정이 필요했던 이유

학습자는 ‘검증 완료’라는 문구만 보고 업무 규칙과 매칭 정확도도 검증됐다고 이해할 수 있다. 검증 대상·방법·결과와 남은 검증을 따로 적어야 한다.

### 3.8 다음 단계로 넘어갈 근거

파일 생성과 전달은 실제 ZIP·MD 및 도구 검사 결과로 확인된다. 담당자가 사용·검수했다고 보고한 발화는 없다. 이후 사용자는 대화 원문을 UI에 활용하도록 교육 자료 형식을 확장했다.

### 3.9 자기 업무 실습

**교육용 재작성 프롬프트**

```text
생성한 문서의 상대경로, 필수 파일, 출처와 상태 표기를 확인해줘.
ZIP의 포함 파일이 실제 문서와 일치하는지 검사해줘.
검증 보고는 파일 구조 검사와 실제 업무 검증으로 나눠줘.
실행하지 않은 검사는 미실행으로 남겨줘.
```

이 묶음으로 할 실습:

1. 과거 README에서 다른 MD 3개를 연다.
2. 검사 발췌에서 무엇이 PASS였는지 찾는다.
3. 이미지 매칭·담당자 검수의 근거가 있는지 찾아 ‘없음’을 설명한다.
4. 원본 해시와 교육용 사본 해시가 다른 이유를 마스킹 기록에서 확인한다.

### 3.10 결과 확인과 흔한 실패

파일·링크 검사와 이미지·업무 검증을 구분할 수 있으면 된다. 개인정보 마스킹 사본을 원본과 바이트 동일하다고 주장하면 안 된다. 또한 MD 안에 쓰인 ‘확인됨’을 현재 ERP 동작 보장으로 사용하면 안 된다.

## 4. 실제 대화를 채팅 UI용 데이터로 보존하기 — kwc-e04

### 4.1 학습 목표

원문 전체를 보존하면서 핵심 구간·해설·실습·파일을 따로 연결한다. 확인하지 못한 대화를 요약으로 복원하지 않는다.

### 4.2 들어오기 전 상황과 준비물

MD 4개로 된 기존 교육 산출물이 있었다. 이번 사용자는 실제 요청·응답·수정 과정을 말풍선으로 보여주기 위해 JSON 구조를 제시했다. 현재 보이는 원문과 실제 확보 파일이 준비물이다.

### 4.3 관련 실제 발화

`kwc-m010`. 구성도: `knowledge`, `portal`. 이전 문서 요구와 비교할 때 `kwc-m003`도 함께 읽는다.

### 4.4 사용자가 요구한 핵심

확인 가능한 대화의 순서와 원문을 보존하고, 교육용 핵심 구간은 별도로 선정하라고 했다. 원문 오류의 은밀한 수정 금지, 미확인 값 null 처리, 명시적 마스킹, 원본 미확보 첨부의 재생성 금지, 참조 검증도 요구했다.

### 4.5 AI의 대응과 결과물

이번 결과는 원문 10개가 들어 있는 `threads`, 4개의 `episodes`, 11개의 `assets` 항목이다. 첨부 등록 11개 중 8개는 실제 포함 파일이고 3개는 원본 미확보 항목이다. 이번 완료 보고를 과거 발화로 추가하지 않고, 생성 결과와 검사 기록은 별도 문서·첨부로 제공한다.

### 4.6 오류·누락 또는 중요한 판단

과거 MD의 요약을 사용자와 AI가 실제 주고받은 문장처럼 바꾸면 교육의 근거가 사라진다. 도구 응답도 사용자 발화로 넣지 않는다. 원문 말풍선 안의 예시는 그대로 보존하고 설명은 바깥의 교육 해설로 둔다.

### 4.7 추가 설명과 수정이 필요했던 이유

텍스트 요약과 채팅 UI는 다른 구조를 요구한다. 발화 역할·순서·원문 여부·첨부·학습 단계 참조가 있어야 교육생이 대화의 진행 과정을 따라갈 수 있다. 이는 현재 요청의 목표이며, 보이지 않는 다른 대화방의 사이트 피드백을 이곳의 정정 발화로 추가하지 않는다.

### 4.8 다음 단계로 넘어갈 근거

현재 파일의 JSON 파싱·참조·첨부·ZIP 검사는 검증 보고서로 확인한다. 다음 단계인 UI 구현·사내 웹서비스 배포는 별도 작업이며 이 묶음으로 완료된 것이 아니다. 실제 사용자 사용 보고도 아직 없다.

### 4.9 자기 업무 실습

**교육용 재작성 프롬프트**

```text
확인 가능한 공개 사용자–AI 발화를 순서대로 보존해줘.
원문·발췌·요약을 구분하고, 플랫폼 ID가 없으면 자체 ID라고 밝혀줘.
정확한 시각이 없으면 timestamp를 null로 남겨줘.
교육 해설과 재작성 프롬프트를 실제 발화와 분리해줘.
학습 단계는 발화 ID를 참조하고 실제 파일을 첨부 ID로 연결해줘.
미확보 첨부는 unavailable, path=null로 두고 재생성하지 마.
JSON 파싱, 중복 ID, 참조 대상, 실제 파일 경로를 검사해줘.
```

제공 JSON으로 실행할 수 있는 읽기 전용 확인 예시다. Python 3가 필요하며 특정 제품 설치 명령은 아니다. 아래 명령은 ZIP 최상위 폴더에서 실행한다.

```bash
python3 -m json.tool conversation-data.json > /dev/null
```

### 4.10 결과 확인과 흔한 실패

JSON 문법 통과만으로 완료하지 않는다. 모든 `message_refs`, `asset_ids`, `related_message_ids`가 존재하는지 확인하고 `included` 파일을 실제로 연다. 미확보 항목의 파일을 임의 생성하거나 null 시각을 추정값으로 채우지 않는다. 현재 묶음에서는 sequence 1~10이 연속이며 핵심 구간 밖 발화도 남아 있어야 한다.

## 5. 실습 완료와 추가 자료가 필요한 지점

| 실습 | 현재 묶음으로 가능한가 | 완료 판단 |
|---|---|---|
| 요구·제안·완료보고 구분 | 가능 | 관련 발화 ID와 근거 수준을 설명 |
| 원문과 교육 해설 구분 | 가능 | 메시지와 episode의 역할 구분 |
| JSON·참조·첨부 검수 | 가능 | 제공된 구조 검사와 실제 파일 확인 |
| 실제 이미지 내용 판독 | 불가 | 원본 이미지 필요 |
| 실제 대화·이미지 매칭 정확도 평가 | 불가 | TXT·이미지·정답 대응표 필요 |
| 최신 업무정책·ERP 실행 검증 | 불가 | 현행 규정·담당자 확인·실행 환경 필요 |

현재 확인되는 최종 방식을 따라 할 때는 **다중 근거 대조, 상태 구분, 원본 보존, 미확인 표시**를 적용한다. 이 최종 문서화 방식을 ‘실제 매칭 성능까지 검증된 알고리즘’이라고 부르지 않는다.

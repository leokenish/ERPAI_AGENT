# 코드 검증 및 적용

## 현재 범위: 비교에서 지원 웹자산 반영까지

최신 확보 소스는 **DIAG 0.7.1 / Export 0.4.1**입니다. 초기 읽기 전용 방침에서, 사용자가 승인한 **기존 MIME·BSP Layout의 선택 저장·활성화**로 확장됐습니다. ABAP·DDIC와 BSP 다른 탭은 진단 범위를 유지합니다. 웹자산 행이 보인다는 사실과 반영 가능한 대상이라는 사실은 다릅니다.

| 단계 | 별도로 확인하는 근거 |
|---|---|
| 비교·반영 가능 판정 | 객체 유형·baseline·현재 서버 변경·선택 범위 |
| 저장 | 실제 새 저장 여부, 미활성본 상태, CTS 하위 작업 |
| 활성화 | 선택 페이지 실행 결과, 다른 페이지·공통 정의와의 구분 |
| 사후 조회 | 활성본의 내용과 기대한 내용 일치 여부 |
| 업무 확인 | 브라우저의 실제 업무 동작·권한·데이터 |

### 확인된 성공: DIAG 0.6.11의 단일 BSP 사례

![DIAG 0.6.11 · 기존 I 버전 재사용, 페이지 활성화와 사후 검증 화면. 최신 0.7.1 시험 화면이 아닙니다.](assets/conversations/kbs-erp-export-diag-agents/export-diag-progress-asset-016.png)

사용자는 **기존 미활성 I 버전 재사용 → 해당 페이지 활성화 → 사후 검증** 화면을 제공했고, SE80에서도 제대로 반영됐다고 확인했습니다. `REUSED_VERIFIED`는 이번 실행에서 새로 저장했다는 뜻이 아닙니다. 전체 MIME·최초 저장·원복·브라우저 업무 동작 또는 최신 0.7.1의 성공까지 확대하지 않습니다.

[성공 화면과 SE80 확인 전문](#/conversations/kbs-erp-export-diag-agents/E28-confirmed-bsp-next-scope) · [SO2 XML 실물로 가정을 정정한 과정](#/conversations/kbs-erp-export-diag-agents/E26-so2-layout-evidence)

다음 검증은 수정하지 않은 새 BSP 한 앱 ZIP을 0.7.1로 비교한 뒤, 승인된 작은 변경과 원복을 각각 확인하는 것입니다. 아래 0.4.5 캡처와 과거 XLSX는 당시 진단 사례로 보존합니다.

## 세 자료를 구분하기

**원본**은 추출 시점에 보존한 baseline, **추출본**은 현재 ZIP의 작업 파일, **SAP**는 진단 시 읽은 현재 저장소 내용입니다. 비교 방향에 따라 신규·누락의 의미가 달라집니다.

| 표시 | 기준 | 대상 |
|---|---|---|
| 추출본 / 원본 | 추출 시점 원본 | 현재 추출본 |
| SAP / 원본 | 추출 시점 원본 | 현재 SAP |
| 추출본 / SAP | 현재 SAP | 현재 추출본 |

본문은 전체 바이트로 비교합니다. 빈 파일은 ‘존재’, 읽기 실패는 ‘미확인’, 대상 부재는 비교 방향에 따라 ‘신규·누락’으로 구분합니다.

## 파일 비교와 SAP 검사는 별개

| 축 | 확인하는 질문 |
|---|---|
| SAP 조회 결과 | 현재 자료를 읽었는가? |
| 활성 버전 근거 | 읽은 내용이 활성 버전이라는 근거가 있는가? |
| 문법형식 검증 | 해당 조건에서 문법·형식을 검사했는가? |

본문 일치, 활성 버전 근거, 문법, 실제 업무 결과를 각각 확인합니다.

## 과거 사례: DIAG 0.4.5 읽기 전용 결과화면

사용자 제공 **DEVHUB DIAG 0.4.5 · 읽기 전용** 실행 캡처 2장입니다. 실행 일자는 미확인이며, 과거 XLSX와 별도 자료입니다.

### 요약에서 확인할 것: 비교 범위와 검사 축

![사례 1 · DIAG 0.4.5 요약과 파일 목록. A는 파일 비교 합계, B는 변경 필터 적용 전 전체 SAP 검증 결과입니다. 확대 창에서 원본 크기로 볼 수 있습니다.](assets/images/diag-045-summary.png)

| 화면 영역 | 캡처에서 읽은 값 | 해석 |
|---|---|---|
| A · 추출본/원본 | 변경없음 8, 합계 8 | 이 범위의 추출본 8개는 기준 원본과 같습니다. |
| A · SAP/원본 | 신규 3, 수정 8, 합계 11 | 현재 SAP 쪽에 원본과 다른 내용이 있습니다. |
| A · 추출본/SAP | 누락 3, 수정 8, 합계 11 | SAP 기준으로 추출본에 없는 3개와 다른 8개가 표시됩니다. |
| B · SAP 검증 | 전체 2,541건, 변경 필터 적용 전 | A는 선택 범위, B는 전체 결과를 집계합니다. |
| 하단 목록 | SAP 조회·활성 버전·문법형식 검증이 별도 열 | 각 검사 열의 결과를 따로 확인합니다. |

### 상세에서 확인할 것: 세 버전의 다른 줄

![사례 2 · ZHR_52TM_AWART_LIST의 원본·추출본·SAP 상세 비교. 원본과 추출본은 같고 SAP에 추가된 줄은 초록 영역으로 표시됩니다.](assets/images/diag-045-three-way.png)

| 확인 순서 | 이 화면에서 읽을 내용 |
|---|---|
| 1 · 비교 방향 | 추출본/원본은 변경없음, SAP/원본과 추출본/SAP는 수정입니다. |
| 2 · 바이트 | 원본 16,719 bytes, 추출본 16,719 bytes, SAP 16,939 bytes입니다. 크기와 실제 줄 차이를 함께 봅니다. |
| 3 · 초록 행 | SAP의 228–233행에만 내용이 있고 원본·추출본에는 `(없음)`으로 표시됩니다. SAP 쪽 신규가 추출본/SAP에서는 누락으로 보이는 사례입니다. |
| 4 · 생략 행 | 세 버전이 같은 221줄·273줄은 접어 표시합니다. |
| 5 · 별도 검증 | 우측에는 조회 성공·활성 버전 확인·문법 사전검사 통과가 각각 표시됩니다. 이는 이 항목에 대한 화면의 결과입니다. |

> **읽고 판단하기** · 이 사례의 결론은 “현재 추출본과 SAP가 다르다”입니다. 어떤 버전이 업무적으로 맞는지, SAP의 추가 줄을 반영할지는 변경 이유와 담당자 검토를 통해 판단합니다.

## 과거 XLSX 결과에서 배우기

2026-10-07 업로드된 `RawData` 2,541행의 재집계입니다. 실제 실행 버전과 날짜는 미확인입니다.

[실제 DIAG 결과 엑셀 다운로드](downloads/ZHR5_result_uploaded_20261007.xlsx)에서 각 행의 비교·검사 결과를 직접 확인해 보세요.

- **1440행:** 크기는 모두 3,210 bytes, 내용은 SAP 대비 수정입니다. 변경 필드 확인에는 원문 XML이 필요합니다.
- **828행:** 세 비교는 변경없음, API 소스와 활성 Include 대조는 불일치입니다. 실제 활성 상태는 추가 확인합니다.
- **활성 확인 실패 71건:** 함수 API 70건 + DDIC 진단 1건.
- **검사 미수행 10파일:** SAP에 새로 있고 추출본에는 없는 파일입니다.

## 과거 호환 오류: 0.4.4에서 0.4.5로

0.4.4의 날짜·시각 인수 타입 오류를 해결하도록 0.4.5에서 네 곳을 STRING으로 변환했습니다. 0.4.5 실행 캡처는 확보했으며, 소스·실행본 일치와 JSON 출력은 추가 확인 대상입니다.

![DIAG 0.4.4 날짜 인수 타입 오류 캡처](assets/images/diag-044-type-error.png)

0.4.4 이후 A는 선택 범위, B는 필터 전 전체 결과를 집계합니다. 개발 환경에서 입력·상세·F3 복귀·JSON을 확인한 뒤 상태를 갱신합니다.

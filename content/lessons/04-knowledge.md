# 업무 지식·스킬

## TXT에서 빠진 근거 채우기

카카오톡 TXT·첨부 이미지·기존 MD를 대조해 업무 협의의 근거를 정리합니다. 이 과정에서는 실제 TXT 사례로 요청·합의·완료를 구분합니다.

## 시간은 후보, 내용은 근거

이미지의 전송 시각과 파일 저장 시각을 구분합니다. 화면명·오류 문구·수치·앞뒤 발화가 일치하는지 함께 확인합니다.

| 확인 항목 | 기록할 내용 |
|---|---|
| 원본 | TXT 파일·대화 구간·이미지 파일명 |
| 시각 | 전송·촬영·다운로드 등 시각의 의미 |
| 관찰 | 이미지에서 직접 읽은 내용 |
| 연결 판단 | 후보·근거·확신 수준·경쟁 후보 |
| 업무 상태 | 요청·검토·합의·완료보고·검증 |
| 적용 범위 | 대상 업무·기간·조건 |

## 실제 카카오톡 TXT를 업무지식으로 정리하기

이번에는 사용자 제공 **`SRC-11.txt`**를 사용합니다. 대화 범위는 **2026-08-24~2026-09-21**, 저장 시각은 **2026-09-22 10:20:26**입니다. 저장일과 사안의 발생일·적용일을 구분합니다. 교육본에서는 사람 이름과 사번을 제외하고 역할 또는 사례 A로 표기했습니다.

### 사례 A · 교대근무 시간과 기본 입력값이 다른 이유

**상황:** 교대근무표에는 00:00–09:00인데 시간외 입력 화면은 18:00–24:00을 기본값으로 보여 준다는 문의가 들어왔습니다.

| 대화 순서 | 원문에서 확인한 내용 | 업무지식에 남길 상태 |
|---|---|---|
| 8/24 15:58 · 문의 | 근무표와 입력 기본값이 다르다는 사용자 보고 | 관측 증상 · SRC-11, 8–10행 |
| 16:22–16:27 · 확인 | 담당자는 스케줄을 확인하고 개인 IAM 설정이 우선 반영된다고 설명 | 담당자 설명 · 16–26행 |
| 16:31–16:40 · 협의 | 설정 삭제 또는 우선순위 변경을 묻고, IAM을 지우도록 안내하겠다고 합의 | 안내 합의 · 27–34행 |
| 이후 확인 | 실제 IAM 삭제 후 결과 화면은 제공 TXT에서 확인되지 않음 | 결과 검증 미확인 |

대화에는 다음 발화가 있습니다. 발신자 이름은 교육 목적에 맞게 역할로 바꿨습니다.

> **시스템 담당 · 2026-08-24 16:27**
> “IAM 설정이 되어있으면 이게 우선으로 들어가네요;”
> — SRC-11.txt, 26행

> **업무 담당 · 2026-08-24 16:40**
> “그럼 IAM을 지우라고 할게요! ㅋㅋ”
> — SRC-11.txt, 32행

**관찰한 현상·담당자 설명·안내 합의·검증 결과**를 따로 기록하면 다음 업무 질문에 재사용할 수 있습니다.

### MD로 바꾼 결과

```markdown
# 교대근무 시간외 입력 기본값과 IAM 설정
- 상태: 과거 담당자 설명·안내 합의 / 실무자 검토 전
- 출처: SRC-11.txt, 2026-08-24, 8–34행
- 대상: 교대근무자 사례 A의 시간외 입력 기본값
- 현상: 근무표 00:00–09:00, 입력 기본값 18:00–24:00
- 당시 설명: 개인 IAM 설정이 스케줄보다 먼저 반영된다고 설명함
- 합의: 사용자에게 IAM 설정 삭제를 안내하기로 함
- 미확인: 실제 삭제·재조회 결과, 현재 코드의 우선순위
- 이미지: 18·23행에 사진 표시만 있음. 원본 이미지 미제공
- 후속 검증: IAM 유무에 따른 입력값을 담당자가 비교
```

[실제 사례의 업무지식 MD 받기](downloads/src-11-iam-case.md)

### 사례 B · “처리했다”의 범위를 구분하기

같은 TXT의 9/16–9/18 대화에는 신규 입력 단가와 과거 입력 내역을 구분하는 사례가 있습니다.

| 시점 | 대화 근거 | 남겨야 할 판단 |
|---|---|---|
| 9/16 13:30–13:38 | 신규 입사 사례의 단가 문제와 9월 이후 내역 확인 요청 · 329–345행 | 확인·조치 요청 |
| 9/17 09:50 | 개별 등급 변경 완료 발화 · 348행 | 해당 조치의 완료보고 |
| 9/18 16:13–16:33 | 신규 입력은 9,240원, 과거 입력은 아직 수정되지 않았다는 발화와 다음 주 처리 예정 · 351–363행 | 과거 내역은 완료가 아닌 예정 |

이 사례의 상태는 ‘개별 등급 변경 완료, 과거 내역 정정 예정’입니다. 현재 업무 적용 시에는 최신 기준과 처리 결과를 확인합니다.

### TXT의 ‘사진’을 채우는 다음 단계

사진·엑셀 원본은 미확보입니다. 확보 후 **발화 시각 → 화면 내용 → 사례 문장**을 대조해 미확인 항목을 보완합니다.

## 가상 사례로 구분하기

10:00에 “화면 A의 값이 100으로 보인다”, 10:02에 “120이어야 하는지 확인해 달라”, 10:05에 “확인하겠다”는 대화가 있다고 가정합니다. 이미지에는 100이 보이고 파일 수정 시각은 18:00입니다.

- 관찰값: 100.
- 확인 요청값: 120.
- 처리 상태: 확인 예정.
- 파일 수정 시각: 18:00, 실제 전송 시각은 추가 확인.

위 상황은 교육용 가상 사례입니다.

## 따라 하기: 한 사안부터 보완

1. 대화 TXT, 원본 이미지, 기존 MD의 대상 범위를 정합니다.
2. 이미지에 표시된 시각이 무엇을 뜻하는지 확인합니다.
3. AI가 연결 후보와 근거를 적게 합니다.
4. 애매한 연결은 미확인으로 남기고 담당자가 검수합니다.
5. 기존 MD에서 바뀐 문장과 새 근거를 함께 기록합니다.

```text
TXT와 이미지, 기존 MD를 함께 읽고 동일 사안의 연결 후보를 찾아줘.
전송 시각과 파일 시각을 구분하고, 이미지 관찰 사실·담당자 요청·
최종 합의·완료보고·실제 검증을 나눠줘.
연결이 애매하면 후보와 이유를 남기고 확정하지 마.
기존 MD를 보완할 문장과 근거 위치를 먼저 제시해줘.
```

# 업무 맥락 만들기

## 1. 왜 코드 밖의 자료가 필요한가

프로그램을 읽으면 어떤 조건에서 값이 계산되는지 찾을 수 있습니다. 그러나 “왜 이 조건을 만들었는가”, “담당자들은 어떤 예외를 합의했는가”, “예전 요청은 취소됐는가”는 코드에 다 들어 있지 않습니다. 이 이유를 모르면 AI가 동작을 설명해도 실제 업무 질문에는 틀리게 답할 수 있습니다.

실제 프로젝트에서도 추출 파일에는 코드와 구조만 있으니 규정·매뉴얼·사용자 의견을 더해야 한다는 요청이 나왔습니다. 업무 맥락을 만든다는 것은 **당시의 상황, 적용 대상, 판단 이유, 바뀐 이력을 근거와 함께 남기는 것**입니다.

여기서 만드는 결과물은 짧은 요약 한 장이 아닙니다. 다음 담당자와 AI가 원래 문서로 돌아가 확인할 수 있는 주제별 업무 문서입니다.

## 2. 어떤 문제를 겪었는가: 대화를 줄이면 중요한 차이가 사라집니다

메신저의 “처리했습니다”는 모든 문제가 끝났다는 뜻이 아닐 수 있습니다. 개인 설정만 바꿨고 과거 자료는 다음 주에 고치기로 했을 수도 있습니다. “이렇게 바꾸면 어떨까요?”라는 제안을 확정 규정으로 저장하는 것도 위험합니다.

첨부에도 빈틈이 있었습니다. 카카오톡 TXT를 업무 문서로 만들었지만 이미지가 반영되지 않았다는 사용자 지적이 나왔습니다. TXT의 ‘사진’ 표시는 이미지 내용이 아닙니다. 파일 저장 시각만으로 사진을 발화와 연결하면 나중에 다운로드한 시간을 실제 전송 시각으로 오해할 수 있습니다.

그래서 **발화 순서·후속 정정·이미지의 실제 내용**을 함께 확인하고, 확보하지 못한 자료는 미확인으로 남기는 방식을 택했습니다.

## 3. 어떻게 정리하기로 했는가: 원문·업무 지식·절차를 나누기

| 자료 | 여기서 찾는 것 | 정리할 때 놓치지 않을 것 |
|---|---|---|
| 규정·지침 | 공식 기준과 적용 조건 | 효력일·대상·예외 |
| 매뉴얼·양식 | 실제 입력과 처리 절차 | 입력값·승인 흐름·예외 처리 |
| 사용자 대화 | 문의·불편·협의·정정의 이유 | 요청·합의·완료보고·재발의 구분 |
| 회의록 | 결정과 미결 사항 | 결정 주체·기한·후속 확인 |
| 이미지·엑셀 | 화면의 관찰값과 계산 근거 | 원본 위치·단위·표시값·읽지 못한 부분 |

원본은 그대로 두고 업무별 설명을 MD로 작성합니다. Markdown은 제목·표·링크를 넣는 텍스트 문서 형식이라 검색과 변경 비교가 쉽습니다. 다만 읽기 좋은 TXT를 확장자만 MD로 바꾼다고 지식이 좋아지지는 않습니다. **출처와 조건을 구조화하는 작업이 핵심**입니다.

업무 지식은 “무엇을 근거로 답하는가”, 스킬은 “그 근거를 어떤 순서로 찾고 판단하는가”입니다. 규정마다 스킬을 하나씩 만드는 대신, 규정·협의는 지식에 두고 읽는 절차를 스킬로 연결합니다.

## 4. 어떻게 만드는가: 한 사안을 끝까지 따라 읽기

1. 원본에 ID를 붙이고 파일명·대화 기간·문서일·검토 범위를 기록합니다. 업로드일과 규정 효력일은 나눕니다.
2. 한 질문과 관련된 앞뒤 대화를 읽습니다. 최초 요청 뒤에 취소·정정·추가 조건이 있는지 확인합니다.
3. 문장을 관찰 사실, 담당자 설명, 요청, 합의, 완료보고, 실제 검증으로 나눕니다.
4. 이미지가 있으면 화면명·수치·오류 문구와 발화를 대조합니다. 시각은 연결 후보를 찾는 단서로 사용합니다.
5. 주제별 MD에 결론·조건·출처 위치·미확인 사항을 적습니다. 기존 문서와 충돌하면 양쪽 근거와 시점을 남깁니다.
6. INDEX와 관련 업무지도에서 새 문서로 찾아갈 링크를 연결합니다.

```text
이 대화 TXT와 확보된 첨부에서 시간외 입력 기본값에 관한 사안을 정리해 주세요.
문의, 담당자 설명, 합의, 완료보고, 실제 결과 확인을 나눠 주세요.
후속 정정까지 읽고 각 문장에 원문 파일·시각·행 또는 페이지를 적어 주세요.
이미지는 전송 시각과 파일 저장 시각을 구분하고 내용으로도 대조해 주세요.
없는 첨부나 애매한 연결은 미확인으로 남겨 주세요.
원본은 유지하고 기존 업무 MD·INDEX에서 보완할 부분을 작성해 주세요.
```

위 문장은 교육용 요청 예시입니다. 대상 업무와 자료 이름을 자기 업무에 맞게 바꿉니다.

## 5. 실제 사례: 같은 대화에서 다른 결론을 구분하기



이번에는 사용자 제공 **`SRC-11.txt`**를 사용합니다. 대화 범위는 **2026-08-24~2026-09-21**, 저장 시각은 **2026-09-22 10:20:26**입니다. 저장일과 사안의 발생일·적용일을 구분합니다. 교육본에서는 사람 이름과 사번을 제외하고 역할 또는 사례 A로 표기했습니다.

### 5-1. 사례 A · 교대근무 시간과 기본 입력값이 다른 이유

**상황:** 교대근무표에는 00:00–09:00인데 시간외 입력 화면은 18:00–24:00을 기본값으로 보여 준다는 문의가 들어왔습니다.

| 대화 순서 | 원문에서 확인한 내용 | 업무지식에 남길 상태 |
|---|---|---|
| 8/24 15:58 · 문의 | 근무표와 입력 기본값이 다르다는 사용자 보고 | 관측 증상 · SRC-11, 8–10행 |
| 16:22–16:27 · 확인 | 담당자는 스케줄을 확인하고 개인 IAM 설정이 우선 반영된다고 설명 | 담당자 설명 · 16–26행 |
| 16:31–16:40 · 협의 | 설정 삭제 또는 우선순위 변경을 묻고, IAM을 지우도록 안내하겠다고 합의 | 안내 합의 · 27–34행 |
| 이후 확인 | 실제 IAM 삭제 후 결과 화면은 제공 TXT에서 확인되지 않음 | 결과 검증 미확인 |

대화에는 다음 발화가 있습니다. 발신자 이름은 교육 목적에 맞게 역할로 바꿨습니다.

> **시스템 담당 · 2026-08-24 16:27**
> “IAM 설정이 되어있으면 이게 우선으로 들어가네요;”
> — SRC-11.txt, 26행

> **업무 담당 · 2026-08-24 16:40**
> “그럼 IAM을 지우라고 할게요! ㅋㅋ”
> — SRC-11.txt, 32행

**관찰한 현상·담당자 설명·안내 합의·검증 결과**를 따로 기록하면 다음 업무 질문에 재사용할 수 있습니다.

### 5-2. MD로 바꾼 결과

```markdown
# 교대근무 시간외 입력 기본값과 IAM 설정
- 상태: 과거 담당자 설명·안내 합의 / 실무자 검토 전
- 출처: SRC-11.txt, 2026-08-24, 8–34행
- 대상: 교대근무자 사례 A의 시간외 입력 기본값
- 현상: 근무표 00:00–09:00, 입력 기본값 18:00–24:00
- 당시 설명: 개인 IAM 설정이 스케줄보다 먼저 반영된다고 설명함
- 합의: 사용자에게 IAM 설정 삭제를 안내하기로 함
- 미확인: 실제 삭제·재조회 결과, 현재 코드의 우선순위
- 이미지: 18·23행에 사진 표시만 있음. 원본 이미지 미제공
- 후속 검증: IAM 유무에 따른 입력값을 담당자가 비교
```

[실제 사례의 업무지식 MD 받기](downloads/src-11-iam-case.md)

### 5-3. 사례 B · “처리했다”의 범위를 구분하기

같은 TXT의 9/16–9/18 대화에는 신규 입력 단가와 과거 입력 내역을 구분하는 사례가 있습니다.

| 시점 | 대화 근거 | 남겨야 할 판단 |
|---|---|---|
| 9/16 13:30–13:38 | 신규 입사 사례의 단가 문제와 9월 이후 내역 확인 요청 · 329–345행 | 확인·조치 요청 |
| 9/17 09:50 | 개별 등급 변경 완료 발화 · 348행 | 해당 조치의 완료보고 |
| 9/18 16:13–16:33 | 신규 입력은 9,240원, 과거 입력은 아직 수정되지 않았다는 발화와 다음 주 처리 예정 · 351–363행 | 과거 내역은 완료가 아닌 예정 |

이 사례의 상태는 ‘개별 등급 변경 완료, 과거 내역 정정 예정’입니다. 현재 업무 적용 시에는 최신 기준과 처리 결과를 확인합니다.

### 5-4. TXT의 ‘사진’을 채우는 다음 단계

사진·엑셀 원본은 미확보입니다. 확보 후 **발화 시각 → 화면 내용 → 사례 문장**을 대조해 미확인 항목을 보완합니다.

## 6. 한계와 다음 방향: 정리한 문장도 다시 확인할 수 있어야 합니다

위 사례에서 확인한 것은 대화에 남은 당시 설명과 합의입니다. IAM 삭제 후 화면이 정상화됐는지, 과거 단가가 실제로 정정됐는지는 제공 TXT만으로 확정할 수 없습니다. 과거의 금액과 담당자 설명을 현재 모든 직원에게 적용하는 규칙으로 사용하지 않습니다.

이미지 자동 연결도 완료된 기능으로 볼 수 없습니다. 실제 원본 이미지 묶음과 연결 결과를 확보해 검토해야 합니다. 자료가 없을 때 그럴듯한 내용을 채우는 대신, “어느 화면의 어느 결과가 필요하다”고 구체적으로 남깁니다.

첫 문서가 완성되면 다른 사람이 그 문장만 보고도 적용 조건을 이해하고 원문을 찾을 수 있는지 확인해 보세요. [업무 근거 기록 양식](downloads/knowledge-record.md)을 활용할 수 있습니다. 문서가 늘어났을 때 찾아가는 방법은 다음 [06. 업무 지도 만들기](#/learn/maps)에서 다룹니다.

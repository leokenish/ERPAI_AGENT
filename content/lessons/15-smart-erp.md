# 스마트 ERP 메인화면 개편

## 익숙한 기능을 보존하며 첫 화면 바꾸기

기존 ERP의 메뉴·결재·공지·관련서식 연결을 유지하면서 메인화면의 배치·배경·글꼴을 개선한 활용 사례 16번이다. 시안 제작에서 실제 소스와 프리뷰, 전달물 점검으로 이어지는 동안 요청이 어떻게 구체화됐는지 살펴본다.


## 마지막 명시적 요구가 현재 기준

| 변화 | 현재 기준과 의미 |
|---|---|
| 초기 팀 일러스트에서 서버 인프라 시안으로 | 이전 방향을 현재 디자인으로 되살리지 않음 |
| 중앙 패널 제거·결재 링크 이동 | 후속 배치 결정을 최종 시안보다 우선 |
| 큰 화면의 회색 여백 수정 | 전체 창 대응. 사용자의 해당 프리뷰 확인과 최신본 수용은 구분 |
| 랙·케이블의 반복 보정 | 마지막에 지정한 부분만 수정하고 주변의 승인된 배치를 보존 |
| S-Core Dream 적용 | v9 구현 기준. 글꼴 적용과 SAP 제공·실제 기능 검증은 별도 |

## 현재 상태: v9 소스·프리뷰 근거, SAP 검증 대기

최신 네 MD에는 원본 2,486개 경로 중 누적 7개를 변경한 내용과 로컬 화면·글꼴 시험 기록이 정리돼 있다. 해당 문서에서 확인한 파일 비교와 보관된 로컬 시험까지의 기록이며, 운영 서버에 반영한 결과는 아니다. 실제 업무 지표 집계와 알림게시판 연계도 남아 있다.

![v9 1900×932 로컬 프리뷰 기록. 실제 SAP 화면이나 운영 반영 증거가 아니다.](assets/images/smart-erp-v9-preview.jpg)

## 전달 ZIP도 검증 대상

공유 대화의 v9 전체 ZIP은 끝 디렉터리가 없어 일반적인 압축 해제가 실패한다. 이번 수록 과정에서도 같은 보관본의 실패를 확인했다. 내부 파일 일부가 정상이어도 전체 전달물이 정상이라고 표시할 수는 없다.

별도로 확보한 프리뷰·변경 보고서와 최신 네 MD는 관련 자료에서 내려받을 수 있다. 불완전한 전체 v9 ZIP은 정상 반영 패키지로 제공하지 않는다. 다음 작업은 디자인을 다시 만드는 것보다 **완전한 전달 패키지를 확보하고 검사하는 것**이다.

## 따라 하기: 서로 다른 완료를 분리하기

1. 구현된 화면·소스의 버전과 기준 원본을 적는다.
2. 로컬 프리뷰에서 시험한 기능과 실제 SAP에서 확인해야 할 기능을 나눈다.
3. 사용자의 확인 발언이 어느 화면과 동작에 관한 것인지 표시한다.
4. 전체 ZIP과 내부 ZIP을 각각 검사한다.
5. 운영 지표·권한·세션·실제 결재·게시판 연결에서 남은 확인 사항을 기록한다.

## 네 MD와 가치 성찰

[자료실](#/library/smart-erp)에 최신 intent·spec·plan·insight를 수록했다. 최신 insight는 업무 환경을 세심하게 가꾸는 가치와, 별도 개편이 조직에 필요한 이유가 충분히 입증됐는지를 나누어 살펴본다. 만드는 사람의 만족과 이용자의 경험이 같다고 가정하지 않는 학습 사례다.

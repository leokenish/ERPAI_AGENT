# 근로시간 AI 에이전트 구축

## 무엇을 만들었는가

근로시간의 **업무 기준·협의 이유·소스 위치**를 함께 찾는 환경이다. 이를 위해 업무 지식, 에이전트가 자료를 읽는 절차, Obsidian 지도를 연결했다.

지도에서 문서를 클릭하면 관련 링크와 말풍선이 나타난다. ‘본문 읽기’를 누르면 새 창에서 내용을 읽을 수 있고, ‘MD 받기’로 원문을 내려받을 수 있다. 빈 곳을 클릭하거나 Esc를 누르면 선택이 해제된다.

바깥 선은 그룹별 MD 링크를, 선택한 문서의 화살표는 탐색 방향을 뜻한다. ‘모든 개별 연결선’을 선택하면 전체 링크를 볼 수 있다.

## 폴더를 역할로 읽기

| 역할 | 실제 위치 | 유지할 내용 |
|---|---|---|
| 공통 지침·작업 절차 | AGENTS.md, .agents/skills/ | 범위, 근거 규칙, 작업별 읽는 순서 |
| 구축·유지 가이드 | docs/ | 출처 장부, 설치, 근거 원칙, 피드백 정책, 갱신 방법 |
| 업무 지식 | knowledge/ | 규정·절차·협의·FAQ·용어·미확인 질문·코드 연결 후보 |
| Obsidian 업무 지도 | maps/의 목차와 topics/ | 질문에서 업무·근거·소스 설명을 찾아가는 경로 |
| 소스 설명 MD | maps/sources/ | 객체·화면·함수·데이터의 설명, 참조 위치, 확인 수준 |
| 피드백·평가 | harness/feedback/, tests/, evals/ | 무엇을 정정했고 어떤 질문으로 다시 확인하는지 |
| 시작점·양식·추출 안내 | README.md, templates/, exports/의 MD 등 | 시작 안내와 반복해서 쓰는 기록 형식 |

`harness/feedback/`의 정정 기록은 같은 오류가 되풀이되는지 살펴볼 회귀 질문과 연결해 관리한다. 자동 평가를 실제로 실행했는지는 결과 기록에서 확인한다.

## 따라 하기: 누적시간 표시를 질문한다면

1. **업무를 고른다.** `maps/topics/selective.md`에서 선택근무와 누적표시의 범위를 찾는다.
2. **이유를 확인한다.** `knowledge/processes/selective-cumulative-display.md`를 읽고 누적표시·소정 충족·대휴 발생이 어떻게 다른지 구분한다.
3. **코드 설명으로 이동한다.** `knowledge/code-map/working-time.md`와 소스 설명 MD에서 구현 위치를 찾고, 문서가 어디까지 확인한 내용인지 읽는다.
4. **정정 이력을 읽는다.** `harness/feedback/FB-20261008-001.md`에서 용어 혼동을 보완한 이유와 함께 바꾼 문서를 확인한다.
5. **같은 오류가 다시 생기는지 확인한다.** `tests/business-qa.md`의 Q39–Q41을 읽는다. 기대 답변과 대조한 결과, 독립 평가 결과, SAP 실행 결과는 각각 구분한다.

교육용 요청 예시는 다음과 같다.

```text
ZHR5 선택근무의 누적근로시간 표시와 대휴 발생 기준을 구분해 설명해 주세요.
업무 지도에서 관련 지식을 찾고, 후속 정정과 적용 시점을 함께 확인해 주세요.
문서에 기록된 코드 위치와 확인 수준을 제시하고, 미확인 사항을 따로 정리해 주세요.
이번 요청에서는 SAP 변경이나 소스 수정을 수행하지 마세요.
```

## 앞으로 관리할 것은 연결과 근거다

새 원문이 들어오면 출처·시점·버전을 등록하고 관련 지식·색인·지도·피드백·회귀 질문을 갱신한다. 스킬에는 작업 절차를, 지식 문서에는 업무 내용을 기록한다.

교육용 유지보수 요청 예시는 다음과 같다.

```text
새 자료와 기존 지식을 비교해 적용 대상·시점·후속 정정을 구분해 주세요.
원문을 보존하고 관련 업무 지식, 색인, 업무 지도와 피드백 기록을 갱신해 주세요.
영향받는 회귀 질문과 아직 확인하지 못한 항목을 함께 정리해 주세요.
기존 소스와 파일 경로를 임의로 바꾸지 말고, 변경 이유와 검증 범위를 보고해 주세요.
```

## 확인 수준을 함께 읽기

문서를 읽을 때는 기준일과 검토 범위를 함께 확인한다. 저장소에는 초기 초안과 이후 보완한 문서가 함께 있기 때문이다.

수집 기준은 커밋 `520ac77046f54d589bdcd49003ee41d0a803022f`의 MD 783개이며, 빈 문서 2개가 포함돼 있다. 수집·검토 대상은 MD 문서와 링크다. 본문에 적힌 인라인 경로는 별도 참조로 표시한다.

전체 MD ZIP은 원래 폴더 구조를 유지한다. 비MD 참조는 ‘이번 수집 범위 밖’으로 표시한다. 이후 변경은 새 스냅샷을 가져와 다시 빌드하는 방식으로 반영한다.

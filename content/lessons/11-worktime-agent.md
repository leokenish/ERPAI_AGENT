# 근로시간 AI 에이전트 구축

## 무엇을 만들었는가

이 프로젝트의 목적은 근로시간 질문에 답할 때 **업무 기준과 과거 협의 이유, 관련 소스 위치를 함께 찾는 환경**을 만드는 것입니다. 규정·매뉴얼·담당자 대화에서 만든 업무 지식을, 에이전트의 읽는 절차와 Obsidian의 연결 지도에 결합했습니다. Markdown을 모아 모델 자체를 재학습한 것은 아닙니다.

위 전체 지도에서 작은 네모 하나가 MD 한 개입니다. 그룹별 색상으로 역할을 구분하고, 마우스를 올리면 해당 네모만 살짝 강조됩니다. 클릭하면 전체 구조를 유지한 채 관련 문서·연결선·제목과 경로가 담긴 말풍선이 고정됩니다. 말풍선의 ‘본문 읽기’와 ‘MD 받기’를 눌러 내용을 확인할 수 있습니다. 다른 노드를 클릭하면 선택이 바뀌고, 빈 곳을 클릭하거나 Esc를 누르면 해제됩니다. 그룹 이름을 누르면 해당 영역이 확대되고 ‘전체 맞춤’으로 돌아올 수 있습니다.

기본 화면의 바깥 선은 실제 MD 링크를 그룹별로 묶은 것입니다. ‘모든 개별 연결선’을 켜면 문서 사이 링크 전체를 표시합니다. 선택한 문서의 화살표는 문서 탐색 방향이며 프로그램 실행 순서가 아닙니다. 아래 따라 하기 순서는 교육을 위해 선정한 읽기 경로입니다.

## 폴더를 역할로 읽기

| 역할 | 실제 위치 | 유지할 내용 |
|---|---|---|
| 공통 지침·작업 절차 | AGENTS.md, .agents/skills/ | 범위, 근거 규칙, 작업별 읽는 순서 |
| 구축·유지 가이드 | docs/ | 출처 장부, 설치, 근거 원칙, 피드백 정책, 갱신 방법 |
| 업무 지식 | knowledge/ | 규정·절차·협의·FAQ·용어·미확인 질문·코드 연결 후보 |
| Obsidian 업무 지도 | maps/의 목차와 topics/ | 질문에서 업무·근거·소스 설명을 찾아가는 경로 |
| 소스 설명 MD | maps/sources/ | 객체·화면·함수·데이터의 설명, 참조 위치, 확인 수준 |
| 피드백·평가 | harness/feedback/, tests/, evals/ | 무엇을 정정했고 어떤 질문으로 다시 확인하는지 |
| 시작점·양식·추출 안내 | README.md, templates/, exports/의 MD 등 | 시작 안내와 반복해서 쓰는 기록 형식 |

`harness/feedback/`에는 실제 피드백 기록이 있습니다. 평가 질문 파일이 있다는 사실만으로 자동 평가기가 실행되었다고 볼 수는 없습니다. 이 과정에서는 지식 정정과 회귀 질문을 연결하는 관리 절차로 설명합니다.

## 따라 하기: 누적시간 표시를 질문한다면

1. **업무를 고릅니다.** `maps/topics/selective.md`에서 선택근무와 누적표시의 범위를 찾습니다.
2. **이유를 확인합니다.** `knowledge/processes/selective-cumulative-display.md`에서 누적표시·소정 충족·대휴 발생을 구분합니다.
3. **코드 설명으로 이동합니다.** `knowledge/code-map/working-time.md`와 소스 설명 MD에서 문서가 적어 둔 위치와 확인 수준을 읽습니다. 실제 코드를 이번 교육 화면에서 다시 분석한 것은 아닙니다.
4. **정정 이력을 읽습니다.** `harness/feedback/FB-20261008-001.md`에서 용어 혼동을 보완한 이유와 함께 바꾼 문서를 확인합니다.
5. **같은 오류의 재발을 확인합니다.** `tests/business-qa.md`의 Q39–Q41을 읽습니다. 기대 답변을 읽고 대조한 결과와 독립 평가·SAP 실행 결과를 구분합니다.

교육용 요청 예시입니다. 실제 과거 대화를 복원한 문장이 아닙니다.

```text
ZHR5 선택근무의 누적근로시간 표시와 대휴 발생 기준을 구분해 설명해 주세요.
업무 지도에서 관련 지식을 찾고, 후속 정정과 적용 시점을 함께 확인해 주세요.
문서에 기록된 코드 위치와 확인 수준을 제시하고, 미확인 사항을 따로 정리해 주세요.
이번 요청에서는 SAP 변경이나 소스 수정을 수행하지 마세요.
```

## 앞으로 관리할 것은 연결과 근거다

새 자료는 원문을 보존하고 출처·시점·버전을 등록합니다. 관련 업무 지식을 수정한 다음 색인, 업무 지도, 미확인 질문, 변경 이력과 회귀 질문을 함께 확인합니다. 새 대화 전체를 SKILL.md에 붙이지 않습니다. 스킬은 작업 절차를 맡고, 업무 내용은 지식 문서가 맡습니다.

교육용 유지보수 요청 예시입니다.

```text
새 자료와 기존 지식을 비교해 적용 대상·시점·후속 정정을 구분해 주세요.
원문을 보존하고 관련 업무 지식, 색인, 업무 지도와 피드백 기록을 갱신해 주세요.
영향받는 회귀 질문과 아직 확인하지 못한 항목을 함께 정리해 주세요.
기존 소스와 파일 경로를 임의로 바꾸지 말고, 변경 이유와 검증 범위를 보고해 주세요.
```

## 확인 수준을 함께 읽기

사용자가 구축한 에이전트의 GitHub 문서 묶음을 교육에 연결했습니다. 저장소 안에는 초기 초안과 이후 보완 문서가 함께 있습니다. 오래된 ‘미검증’ 설명이나 특정 날짜의 ‘VERIFIED’를 모든 문서·현재 운영 상태로 확대하지 않습니다. 각 문서의 시점과 검토 범위를 확인하십시오.

이번 포털은 커밋 `520ac77046f54d589bdcd49003ee41d0a803022f`의 MD 783개를 기준으로 합니다. 빈 MD 2개도 목록에 남겼습니다. 소스 코드·웹 자산·원래 PDF/TXT·SAP 운영환경은 수집하거나 재검증하지 않았습니다. 문서의 일반 링크와 Wikilink를 연결에 사용하고, 인라인 코드에 적힌 경로는 별도 참조로 구분합니다. 앵커·비MD 원본의 실제 내용 확인은 범위 밖입니다.

MD 전체 ZIP은 원래 폴더 구조를 유지합니다. 비MD 자료로 향하는 링크는 다운로드 묶음에 대상이 없으며, 포털에서는 ‘이번 수집 범위 밖’으로 표시합니다. GitHub의 이후 변경은 자동으로 반영되지 않습니다. 새 MD 스냅샷을 가져와 다시 빌드해야 합니다.

# 업무일지 타임라인 개발

## 보고서를 조직의 기억으로 읽기

매주 취합한 금주·차주 업무계획을 나란히 보는 데서 출발해 **어느 시기에 어떤 업무가 이어졌고 원문에는 무엇이 적혀 있었는지** 탐색하는 프로젝트입니다. 첨부한 「업무일지 TIMELINE 보고.html」에서 가상 시연과 실제 자료 화면을 구분해 가져왔습니다.

초기 가상 시연과 현재 화면은 데이터와 표시 기간이 다릅니다. 같은 업무의 동일 조건 전후 비교가 아니라 설계가 구체화된 흐름으로 읽습니다.

## 실제 자료가 바꾼 기준

| 출발점 | 확인한 자료와 요청 | 바뀐 기준 |
|---|---|---|
| 부서·담당자 중심 | 실제 HML의 국·업무 구조 | 연도→국→업무로 탐색, 담당자는 있는 경우 표시 |
| 업무별 MD 파일 | 장기 기록과 반복 갱신 | HML 원본 + JSONL 카드 + JSON 색인, MD는 명세·가이드 |
| 제목이 같으면 같은 업무 | 문맥으로 연결 요청 | 제목·본문·시점 규칙과 표본 맥락 검토, 추론 근거 보존 |
| 가지가 복귀하면 완료 | 보고에 나타나는 관측의 한계 | 다음 조직 보고서의 미언급과 실제 완료를 구분 |

ERP 웹 고도화, 근태 시스템 고도화, DR 서버 작업은 서로 다른 가지로 읽습니다. 같은 단어가 있다는 이유만으로 합치지 않습니다.

## 가지와 사건을 읽는 법

반복 언급된 업무는 주차별로 이어집니다. **다음에 존재하는 조직 보고서에서 미언급되면 줄기로 복귀**하며, 조직 보고서 자체가 없는 주는 자료 공백입니다. 마지막 보고에서 이어진 업무는 후속 기록을 기다리는 상태입니다. 가지 길이를 실제 사업 기간, 복귀를 완료 승인으로 해석하지 않습니다.

노란 사건 박스는 업무를 당시 상황과 함께 읽기 위한 단서입니다. 한 주에 세 건 이상이면 더보기로 펼치고 원문 근거를 확인합니다. 자동 선별된 사건 목록은 공식 연표가 아닙니다.

## 밀도와 가독성의 균형

WORK ARCHIVE에서 WORK TIME LINE으로 이름을 바꾸고 가지형 SVG 아이콘과 S-Core Dream을 사용했습니다. 현재 구간에 해당하는 가지만 배치하고, 세로 스크롤과 전체 기간 미니맵을 함께 제공합니다. 가지 끝단의 페이드는 줄기·주차·사건의 의미를 지우지 않는 범위에서 적용합니다.

이전 시연에도 미니맵은 있었습니다. 기존 기능을 새 성과로 세기보다 기록 규모가 커졌을 때 무엇을 읽기 쉽게 바꿨는지 살펴봅니다.

## 자료 규모와 다음 검토

보고서에는 **617개 HML, 원문 조직 61개, 관측 카드 367,156개, 추론 업무 그룹 136,103개, 사건 109개**가 기록되어 있습니다. 수록 보고주간은 2014-12-29부터 2026-10-19까지이며 2014년은 한 주입니다. 처리 개수는 의미 연결의 정확도 검증 결과가 아닙니다.

업무 카드 주저장은 국·연도·월별 JSONL이며 카드 수만큼 MD 파일을 만들지 않습니다. 수집 매크로의 날짜 파일명·다운로드 추적·페이지 전환 후 재개를 보완했고 수백 HML 다운로드 성공 보고가 있습니다. `update.py`는 신규 HML로 임시 재구성·검사 후 manifest를 최종 반영하는 흐름이며, 자동 예약 실행의 구현을 뜻하지는 않습니다.

5주 표본의 맥락 검토와 전 기간 규칙 기반 추출을 구분합니다. 잘못 연결한 사례와 끊어진 사례를 함께 검토하고, 자료 접근 권한·운영 책임·최신 화면 수용을 확인하는 것이 다음 단계입니다.

자료: 사용자 첨부 「업무일지 TIMELINE 보고.html」, 기존 공유 대화와 프로젝트 MD 4종. 전체 업무 의미와 조직 효과의 전수 검증은 미확인입니다.

# 업무일지 타임라인 개발

## 주간보고와 업무 흐름

금주·차주 업무계획을 시간순으로 연결해 **어느 시기에 어떤 업무가 이어졌고 원문에는 무엇이 적혀 있었는지** 탐색하는 프로젝트입니다. 오래된 업무를 찾을 때 보고서를 하나씩 열어야 했기 때문에 연도·국·업무에서 시작하는 화면을 구성했습니다.

위 갤러리는 「업무일지 TIMELINE 보고.html」의 가상 시연과 실제 자료 화면입니다. 각 화면을 따라가며 탐색 기준과 표시 방식이 구체화된 흐름을 살펴볼 수 있습니다.

## 원문에 따른 탐색 기준

| 출발점 | 실제 자료의 특징 | 적용 기준 |
|---|---|---|
| 부서·담당자 중심 | HML의 국·업무 구조 | 연도 → 국 → 업무 탐색, 기록된 담당자 표시 |
| 업무별 MD 파일 | 장기 기록과 반복 갱신 | HML 원본·JSONL 카드·JSON 색인·MD 가이드 |
| 제목 일치로 업무 연결 | 같은 업무의 제목 변화 | 제목·본문·시점과 문맥을 함께 비교 |
| 가지 복귀로 종료 표시 | 주차별 업무 언급 변화 | 다음 보고의 미언급을 복귀 기준으로 사용 |

ERP 웹 고도화·근태 시스템 고도화·DR 서버 작업은 목적이 다르므로 별도 가지로 읽습니다. 같은 단어가 포함되어 있어도 업무 내용과 이어지는 시점을 함께 비교합니다.

## 가지와 사건 표시

반복 언급된 업무는 주차별로 이어지고, **다음 조직 보고서에서 언급되지 않으면 줄기로 복귀**합니다. 따라서 가지는 보고서에 업무가 등장한 흐름을 나타냅니다. 조직 보고서가 없는 주는 공백으로 두고, 마지막 보고에 나온 업무는 해당 시점까지 연결합니다.

노란 사건 박스는 업무를 당시 상황과 함께 읽는 단서입니다. 자동 선별한 사건이 한 주에 세 건 이상이면 더보기로 펼치며, 원문 근거를 함께 살펴볼 수 있습니다.

## 화면 밀도와 가독성

자료가 많아지면 모든 가지를 한 화면에 배치하기 어렵습니다. 따라서 현재 구간에 해당하는 가지만 보여주고 세로 스크롤과 전체 기간 미니맵으로 이동하도록 구성했습니다. 가지 끝단에는 페이드를 적용해 화면 경계의 밀도를 줄입니다.

이름은 WORK ARCHIVE에서 WORK TIME LINE으로 바꿨습니다. 또한 가지형 SVG 아이콘과 S-Core Dream을 적용해 시간 흐름과 업무 연결이라는 화면의 역할을 표현했습니다.

## 데이터 구성과 갱신

보고서 기준 자료는 **HML 617개, 원문 조직 61개, 관측 카드 367,156개, 추론 업무 그룹 136,103개, 사건 109개**입니다. 수록 보고주간은 2014-12-29부터 2026-10-19까지이며 2014년 자료는 한 주입니다.

업무카드는 국·연도·월별 JSONL로 저장합니다. 카드가 늘어나도 필요한 구간만 찾아 읽을 수 있도록 JSON 색인을 함께 사용하고, 명세와 사용 안내는 MD로 관리합니다.

수집 매크로에는 날짜 파일명·다운로드 추적·페이지 전환 후 재개를 반영했습니다. 새 HML을 추가할 때는 `update.py`로 임시 결과를 만들고 검사한 뒤 변경 파일과 manifest를 반영합니다. 이 순서로 원문과 업무카드·색인의 연결을 함께 갱신합니다.

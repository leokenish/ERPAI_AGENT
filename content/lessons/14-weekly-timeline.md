# 주간업무일지 타임라인 시스템

## 보고서를 시간의 흐름으로 읽기

매주 올라오는 금주·차주 업무계획을 나란히 보는 데서 출발해, **어느 시기에 어떤 업무가 이어졌고 원문에는 무엇이 적혀 있었는지** 찾아보는 프로젝트입니다. 신규 활용 사례 14번입니다.

[처음부터 학습 대화 읽기](#/conversations/kbs-weekly-work-timeline)

## 실제 자료가 설계를 바꾼 네 순간

| 처음의 생각 | 확인한 자료·요청 | 바뀐 기준 |
|---|---|---|
| 부서·담당자 중심 타임라인 | 실제 HML의 국·업무 구조 | 자료가 가진 단위에 맞춰 조직·업무 흐름을 구성 |
| 선이 끝나면 업무 완료 | 연속 보고가 멈추는 이유는 다양함 | ‘보고의 끝’과 ‘실제 업무 완료’를 분리 |
| 업무별 Markdown 파일 | 12년치 자료와 반복 갱신 요구 | HML 원본 + JSONL 카드 + JSON 색인, MD는 명세·가이드 |
| 제목이 같으면 같은 업무 | 문맥으로 연결해 달라는 사용자 요청 | 근거·추론·검토 이력을 남기고 의미 연결 정확도는 별도 평가 |

## 현재까지의 구현과 확인

자료의 기준은 **UI 2.3 / 데이터 구조 2.0**입니다. 사용자에게서 수백 건의 다운로드 진행과 12년 자료 수집 완료 보고가 있었으며, 첨부 MD에는 HML 617개·관측 367,156개·추정 업무 136,103개·이벤트 109개·근거 700개 처리 결과가 기록되어 있습니다. 이 수치는 문서의 처리 보고이며, 모든 연결이 정확하다는 사용자 검수 결과는 아닙니다.

5주 표본에서 맥락을 검토한 범위와 전체 자료의 규칙 기반 추출을 구분합니다. 최신 UI 2.3의 최종 시각 수용, 전 기간의 의미 연결 정확도와 접근 권한 운영은 아직 확인되지 않았습니다.

## 예시 화면을 읽는 순서

학습 대화의 **관련 자료**에서 실제 요청 화면, 5주 표본 HTML 프리뷰와 UI 업데이트 ZIP을 확인할 수 있습니다. 5주 표본은 이후 전체 기간 자료·최신 UI와 구분합니다. 국·업무 목록, 기간 확대, 가지의 합류, 선택한 기록의 원문 근거를 차례로 읽습니다. 화면이 보기 좋다는 판단과 실제 기록이 정확하게 연결됐다는 판단은 따로 남깁니다.

## 따라 하기

1. 두 주에 걸친 같은 업무 후보를 골라 원문 문장을 나란히 기록합니다.
2. 명시된 사실과 AI가 추론한 연결을 분리합니다.
3. 보고가 끝났다는 사실만으로 완료를 표시하지 않습니다.
4. 잘못 연결된 사례와 끊어진 사례를 함께 검토합니다.
5. 수정한 기준이 다른 기간·국의 자료에서도 유지되는지 확인합니다.

# Obsidian으로 업무 관계 연결하기

## 폴더를 유지하고 연결을 추가하기

이미 만든 knowledge, 스킬, 하네스, 추출 코드가 출발점입니다. 파일을 다시 옮기기보다 한 업무를 진입점으로 삼아 **기준 → 협의 근거 → 구현 위치 → 검증 사례**를 연결합니다.

사람은 Obsidian의 노트와 그래프를 보고, AI는 같은 MD와 링크를 읽습니다. 그래프의 선만으로 실제 함수 호출이나 업무 의존성이 검증된 것은 아닙니다. 관계의 뜻은 문서 본문에 적습니다.

## 실제 업무지도 사례

사용자가 현재 적용 중인 Obsidian 화면 두 장을 제공했습니다. **첫 화면은 업무와 근거를 따라 읽는 지도**, 두 번째 화면은 **전체 연결 규모를 보는 그래프**로 살펴보세요. 아래 설명은 화면에서 읽을 수 있는 노드와 연결을 기준으로 합니다.

### 업무를 중심으로 읽는 지도

![사례 1 · 실제 Obsidian 업무지도. INDEX 주변에 settlement, selective, working-time, SRC 문서와 소스 유형별 색인이 연결되어 있습니다. 클릭하면 확대할 수 있습니다.](assets/images/obsidian-business-map.png)

| 화면에서 찾을 곳 | 업무 탐색에 활용하는 방법 |
|---|---|
| `INDEX`와 `INDEX-DB테이블`, `INDEX-함수` 등 | 업무 문서에서 구현 근거를 찾을 진입점을 고릅니다. |
| `settlement`, `selective`, `working-time` | 정산·선택근무·근로시간의 관련 문서를 탐색합니다. |
| `SRC-10-early-SRC-11` 등 SRC 노드 | 정리 문장의 근거가 된 협의 이력으로 돌아갑니다. |
| `OPEN_QUESTIONS`, `open-questions` | 미확인 사항이 확정된 지식과 섞이지 않도록 확인합니다. |

예를 들어 정산 질문을 받았다면 `settlement`를 출발점으로 삼아 연결된 문서와 원문을 확인합니다. 화면의 선은 탐색할 관계를 보여 줍니다. **실제 적용 조건과 구현 내용은 연결 문서를 열어 확인해야 합니다.** 색상별 공식 분류 규칙은 이번 캡처만으로 확정하지 않습니다.

### 전체 규모를 살펴보는 그래프

![사례 2 · 실제 Obsidian 전체 연결망. 촘촘한 노드와 군집을 통해 연결 규모와 중심부·주변부를 살펴보는 화면입니다.](assets/images/obsidian-full-graph.png)

전체 그래프에서는 연결이 집중되는 곳과 떨어져 있는 문서의 후보를 찾습니다. 개별 질문을 해결할 때는 관심 업무의 지도나 연결 문서로 범위를 좁혀 읽습니다. 화면 두 장은 **적용 화면이 확보되었다는 근거**이며, 모든 링크의 유효성이나 답변 속도 개선을 검증한 결과는 아닙니다.

> **직접 찾아보기** · 첫 지도에서 `settlement` → 관련 업무 노드 → SRC 문서로 이어지는 후보를 찾아보세요. 실제 Vault에서는 링크를 열고 문서의 관계 설명과 출처 날짜를 확인합니다. 이 포털에는 캡처를 제공하며 사용자의 Vault에 접속하지 않습니다.

## 연결 문서에 담을 정보

| 관계 | 확인할 근거 |
|---|---|
| 업무 기준의 출처 | 문서명·절·효력일·대상 |
| 협의가 바꾼 내용 | 대화 시각·요청·합의·결과 |
| 구현 위치 | 실제 파일 경로·객체명·기준 커밋 |
| 검증 방법 | 사례·기대 결과·실행 여부 |
| 다른 업무 접점 | 호출 함수·전달 필드·처리 시점·실패 처리 |

## 따라 하기: 한 업무지도 만들기

1. 기존 INDEX와 파일 경로를 조사합니다.
2. 업무 한 가지를 고르고 관련 문서·소스·검증 자료를 찾습니다.
3. 확인된 관계와 추정 관계를 구분해 `maps/` 등에 연결 MD를 작성합니다.
4. INDEX에서 지도, 지도에서 원문으로 이동하는지 확인합니다.
5. 필요한 자료를 포함하는 프로젝트 루트를 Obsidian Vault로 엽니다.
6. 다음 질문에서 AI가 지도를 읽고 실제 원문까지 확인하는지 봅니다.

```text
기존 폴더와 원본 파일을 유지하면서 업무 하나의 연결 문서를 만들어줘.
현재 지침과 INDEX를 먼저 확인하고, 기준·협의·구현·검증 자료를 찾아줘.
모든 관계에 실제 경로와 근거를 적고 추정 관계는 구분해줘.
기존 소스나 스킬을 이동하지 말고, 작성 후 링크와 변경 범위를 확인해줘.
```

## 범위를 작게 시작하는 이유

다른 담당 패키지를 로컬에 클론하지 않는 협업 설계에서는 모든 ERP를 하나의 Vault로 열 필요가 없습니다. 공통 접점 문서는 공유할 수 있지만 링크가 원격 통신이나 권한을 만들어 주지는 않습니다.

Obsidian 설치 자체로 모델 추론이 빨라지지는 않습니다. 필요한 자료를 찾는 경로가 짧아졌는지, 답변 근거가 좋아졌는지를 같은 질문으로 비교합니다. 개선 수치는 측정 후 기록합니다.

## 실습 결과 확인

- 기존 원본과 경로가 유지됩니다.
- 연결 대상이 실제로 존재합니다.
- “관련 있음”을 넘어 관계의 뜻이 적혀 있습니다.
- 지도와 다른 최신 근거가 나오면 원문 기준으로 갱신합니다.

[업무 연결 문서 양식](downloads/relationship-map.md)을 사용해 시작할 수 있습니다. 이번 양식은 교육용이며 사용자 맥에 이미 설치된 지도는 아닙니다.

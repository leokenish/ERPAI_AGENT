# ERP AI 에이전트 전체 그림

## 1. 왜 만드는가

“이 직원의 근로시간이 왜 이렇게 계산됐나요?”라는 문의는 화면에 나온 숫자만으로 설명하기 어렵습니다. 규정의 적용 조건, 담당자끼리 협의한 내용, 프로그램의 계산 방식을 함께 알아야 하기 때문입니다.

그런데 이 자료는 ERP 서버와 문서 폴더, 메신저 대화에 흩어져 있습니다. 따라서 담당자가 바뀌거나 시간이 지나면 **무엇을 바꿨는지뿐 아니라, 왜 그렇게 바꿨는지 찾아가는 과정**이 필요합니다.

AI에게 질문할 때도 같은 문제가 생깁니다. 회사의 규정과 실제 프로그램을 연결해 주지 않으면, 질문할 때마다 같은 자료와 배경을 다시 설명하게 됩니다.

이 프로젝트는 이런 반복을 줄이기 위해 시작했습니다. 목표는 **내 업무의 코드·규정·협의 이력을 함께 읽고, 답의 근거와 수정안, 확인 방법까지 준비하는 업무 도우미**입니다. 여기서 ‘에이전트’는 정해 둔 자료와 도구를 이용해 여러 단계의 일을 수행하는 AI를 뜻합니다.

## 2. 무엇을 만드는가

처음에는 근로시간이나 구매계약처럼 담당 업무 하나를 정합니다. 그리고 그 업무를 설명하는 파일과 작업 방법을 한 폴더에 모읍니다. Codex에서 이 폴더를 열면 자료 찾기부터 문서 작성, 변경 파일 검토까지 같은 맥락으로 이어갈 수 있습니다.

이렇게 구성하는 이유는 다음 질문과 다음 담당자도 같은 근거를 활용하기 위해서입니다. 따라서 결과물은 **업무의 자료와 판단 과정을 계속 쌓아 가는 작업 공간**이 됩니다.

| 업무에서 필요한 도움 | 에이전트가 준비할 결과 | 담당자의 검토 항목 |
|---|---|---|
| “왜 이 값이 나오나요?” | 규정·협의·코드의 근거를 나눈 설명 | 질문 대상과 적용 시점 |
| “이 조건을 바꾸면 어디가 영향을 받나요?” | 관련 화면·함수·테이블과 시험할 사례 목록 | 영향받는 업무와 관련 담당자 |
| “화면을 이렇게 바꿔 주세요.” | 로컬 수정 파일, 변경 이유, 검사 결과 | 기존 기능과 실제 ERP 동작 |
| “지난번과 같은 오류를 줄여 주세요.” | 고친 지식 문서, 작업 절차, 다시 물어볼 질문 | 정정의 근거와 재발 여부 |

근로시간 업무 지식, ERP WEBGUI 개편, ESS 근태시스템 개편 사례에서는 이런 질문을 바탕으로 자료와 작업 과정을 쌓았습니다. 각 사례를 읽으면 자신의 업무에서 어떤 질문부터 시작할지 구체화할 수 있습니다.

## 3. 어떤 방향을 택했는가

최초 목표는 SAP 개발 패키지를 PC로 꺼내 AI와 함께 분석·수정하는 것이었습니다. 패키지는 관련 개발물을 묶는 SAP의 관리 단위이므로, 담당 업무에 맞춰 시작 범위를 정하기 좋았습니다.

작업을 진행하면서 필요한 요소도 분명해졌습니다.

- 코드만으로는 업무의 이유를 설명하기 어려웠습니다. 따라서 규정과 담당자의 협의 대화를 함께 연결했습니다.
- SAP와 GitHub의 직접 연결에서는 TLS 통신 오류가 발생했습니다. 그래서 PC로 자료를 내려받아 GitHub에 공유하는 방식을 선택했습니다.
- 로컬에서 수정하는 동안 서버의 코드도 바뀔 수 있었습니다. 따라서 반영 전에 원본·작업본·현재 서버를 비교하는 절차를 마련했습니다.

이 경험을 바탕으로 **자료 확보 → 근거 연결 → AI 작업 → 결과 검토 → 지식 갱신**의 흐름을 만들었습니다. 이 순서에 각 도구를 연결하면 어떤 도구를 왜 사용하는지도 이해하기 쉽습니다.

## 4. 어떻게 구성하는가

### 자료 추출과 변경 이력 관리

02과정에서는 Export 프로그램으로 SAP 코드와 관련 정의를 파일로 꺼냅니다. 이어서 03과정에서는 Git으로 변경 이력을 기록하고 GitHub로 공유합니다. 이렇게 하면 팀원이 같은 자료를 받아 작업하고, 변경 이유도 다시 살펴볼 수 있습니다.

### 업무 근거와 작업 절차 구성

04과정에서는 Codex가 작업할 로컬 폴더를 엽니다. 다음으로 05과정에서는 규정과 협의 대화를 업무 문서로 정리하고, 06과정에서는 질문과 관련 문서·코드를 연결합니다.

자료를 연결한 뒤에는 07과정에서 반복 작업의 순서를 스킬로 작성합니다. 또한 정정한 답변을 다시 점검할 질문으로 남깁니다. 이런 내용을 저장하는 읽기 쉬운 텍스트 문서 형식이 MD입니다.

### 변경 비교와 선택 적용

08과정에서는 DIAG를 이용해 로컬 변경과 서버 변경을 비교합니다. 지원 대상의 검사 결과를 살펴보고, 기존 웹자산은 필요한 항목을 선택해 저장·활성화합니다. 이후 업무 담당자는 변경한 화면과 업무 규칙을 함께 검토합니다.

| 구성 | 하는일 | 연결되는자료 |
|---|---|---|
| Export · CHECK | SAP 자료를 파일로 꺼내고 추출 묶음 점검 | 소스·객체 정의·파일 목록·추출 원본·로그 |
| Git · GitHub | 변경 이력과 팀 공유 기준 관리 | 저장소·커밋·검토 기록 |
| Codex | 폴더의 자료를 읽고 설명·문서·수정안 작성 | 담당 업무 소스·AGENTS.md·업무 문서 |
| 업무 지식 · 스킬 · 검증 질문 | 답변 근거·작업 순서·점검 기준 제공 | 규정·협의·SKILL.md·피드백·회귀 사례 |
| 업무지도 · Obsidian | 질문에서 관련 근거로 가는 경로 연결 | INDEX·maps의 MD·실제 문서 링크 |
| DIAG | 원본·작업본·현재 SAP 비교와 지원 대상 검사·선택 반영 | 비교표·줄 차이·검사 결과·반영 로그 |
| 담당자 자문 MCP · 09 | 다른 업무 담당 에이전트에 질문을 전달하는 연결 구조 | 질문·작업 상태·근거를 포함한 답변 |
| ERP 조회 MCP · 10 | ERP 조회 기능을 AI 도구로 연결하는 구조 | 기존 REST/RFC 요청·조회 결과 |

MCP는 AI가 외부 도구를 일정한 방식으로 요청하도록 연결하는 규약입니다. 09과정은 **다른 담당자의 지식에 묻는 일**, 10과정은 **ERP의 현재 데이터를 조회하는 일**을 다룹니다. 먼저 01–08과정으로 내 업무의 자료와 검토 흐름을 구성한 뒤, 필요한 연결 구조를 살펴봅니다.

## 5. 실제 사례로 보면 무엇이 달라지는가

### 시간외 입력 기본값과 개인 설정

실제 대화에는 근무표가 00:00–09:00인데 입력 화면의 기본값은 18:00–24:00으로 나온다는 문의가 있습니다. 담당자는 개인 IAM 설정이 먼저 반영되는 구조를 설명하고, 해당 설정을 지우도록 안내하기로 했습니다.

이 사례에서 중요한 것은 화면에 나타난 값과 그 값이 선택된 이유를 함께 남기는 일입니다. 따라서 업무 문서에는 **관찰한 현상, 담당자의 설명, 합의한 조치**를 연결합니다. 그러면 비슷한 문의가 들어왔을 때 개인 설정과 관련 코드를 같은 순서로 살펴볼 수 있습니다. 05과정에서는 이 정리 방법을 자세히 다룹니다.

### 로컬 수정과 서버 변경 비교

로컬에서 화면을 수정하는 동안 다른 개발자가 SAP의 같은 프로그램을 고칠 수 있습니다. 이때 PC와 서버의 파일 두 개만 비교하면 누가 어느 부분을 바꿨는지 판단하기 어렵습니다.

따라서 추출 당시의 원본도 함께 보존합니다. 그러면 원본을 기준으로 내 변경과 서버 변경을 각각 찾을 수 있습니다. 02과정에서 이 기준을 준비하고, 08과정에서 실제 비교 화면을 읽습니다.

이런 흐름으로 줄이려는 것은 **자료를 다시 찾는 시간, 배경을 반복 설명하는 수고, 잘못된 전제로 수정하는 일**입니다. 자신의 업무에서도 같은 질문에 대한 답변을 구성 전후로 비교하면 어떤 부분이 달라졌는지 살펴볼 수 있습니다.

## 6. 무엇부터 시작하는가

첫 업무는 범위를 작게 정할수록 준비할 자료와 결과가 분명해집니다. 다음 순서로 시작합니다.

1. 최근 반복해서 받은 질문 하나를 고릅니다. “근로시간 전체”보다 “시간외 입력 기본값은 무엇을 따르는가”처럼 구체적으로 적습니다.
2. 관련 프로그램·규정·협의 기록을 모읍니다. 질문에서 각 자료로 찾아갈 경로도 함께 연결합니다.
3. 원하는 결과를 정합니다. 첫 목표는 적용 조건과 근거가 있는 설명입니다.
4. 근거 파일을 직접 읽고 답변을 검토합니다. 정정한 내용은 업무 문서와 검증 질문에 반영합니다.

이 과정에서 업무 담당자는 규정의 대상과 적용 시점을 검토하고, SAP 담당자는 개발계의 실행 결과를 확인합니다. 역할을 나누면 답변의 근거와 시스템 적용 결과를 각각 판단하기 쉽습니다.

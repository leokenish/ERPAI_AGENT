# 로컬 에이전트 구성

## 같은 폴더에서 에이전트 작업 시작하기

Codex 데스크톱에서 담당 패키지의 소스·업무 지식·지침을 읽고 설명과 수정안을 만듭니다. [GITHUB 연동](#/learn/workspace)에서 Clone을 마친 뒤 **설치 → 로그인 → 폴더 지정 → 분석 → 변경 검토 → 검증 → 공유** 순서로 진행합니다.

이 페이지는 요청하신 CODEX 명칭을 사용합니다. 2026-10-24 확인한 공식 Codex 앱 안내 주소는 ChatGPT 데스크톱 앱 문서로 연결됩니다. 설치 화면의 제품 이름과 메뉴는 현재 공식 안내를 따르고, 앱에서 Codex 작업을 선택합니다. [공식 앱 안내](https://learn.chatgpt.com/docs/app)

## 1. 설치와 로그인

1. [공식 앱 안내](https://learn.chatgpt.com/docs/app)의 Download에서 사용하는 OS에 맞는 설치 파일을 받습니다. 해당 화면의 OS·장비 조건을 확인합니다.
2. macOS는 받은 파일을 열어 안내에 따라 Applications에 앱을 설치합니다. Windows는 제공되는 설치 프로그램의 안내에 따라 설치합니다.
3. 앱을 실행하고 업무용 ChatGPT 계정으로 로그인합니다. 개인·업무 계정을 함께 쓰면 선택된 계정과 워크스페이스를 확인합니다.
4. Codex를 선택하고 New chat으로 작업을 시작합니다. 설치 버전에 따라 처음 표시되는 프로젝트·폴더 선택 순서는 다를 수 있습니다.
5. 작업 위치를 로컬 저장소로 지정합니다. GitHub 로그인만으로 원하는 폴더가 자동 선택되었다고 판단하지 않습니다.

설치·로그인·작업 위치 선택은 공식 앱 안내를 기준으로 합니다. 아래의 폴더 구성과 보고 방식은 이 프로젝트에 적용할 작업 절차입니다.

## 2. 프로젝트 폴더 지정

앱의 프로젝트 추가 또는 폴더 열기 기능에서 **Clone한 저장소의 루트**를 선택합니다. 예: Windows `C:\work\ERPAI_AGENT`, macOS `~/work/ERPAI_AGENT`. 실제 Clone 위치를 사용합니다.

| 선택 대상 | 확인할 내용 |
|---|---|
| 저장소 루트 | README·AGENTS.md와 소스·문서 폴더가 보이는 위치 |
| 담당 패키지 저장소 | 패키지명과 업무 범위가 README·manifest와 일치 |
| 기존 작업 폴더 | 작업 전 Git 차이를 확인하고 사용자 변경 보존 |

`dist/`만 열면 생성 결과만 보게 됩니다. ZIP 사본에는 Git 이력이 없을 수 있습니다. VS Code와 Codex에서 같은 경로를 열었는지 첫 요청으로 확인합니다.

```text
현재 작업 폴더의 절대 경로와 Git 저장소 루트를 확인해 주세요.
README.md, 적용되는 AGENTS.md, git status와 현재 브랜치를 읽어 주세요.
소스·업무 지식·스킬·검증 자료의 실제 위치를 정리해 주세요.
사용자 변경과 읽지 못한 자료를 구분하고, 아직 파일은 수정하지 마세요.
```

경로·브랜치가 예상과 다르면 먼저 작업 폴더를 바꿉니다. 앱에 별도 작업 사본이나 Worktree 선택이 보이는 경우에도 현재 경로를 확인합니다. 별도 작업 사본의 수정이 원래 폴더에 자동 반영된 것으로 생각하지 않습니다.

## 3. 지침·지식·스킬 배치

| 자료 | 역할 | 관리 기준 |
|---|---|---|
| AGENTS.md | 작업 원칙·읽기 순서·수정 범위 | 기존 파일과 하위 지침을 읽고 적용 |
| knowledge/INDEX.md | 업무 자료 탐색의 입구 | 질문별 실제 문서 경로 연결 |
| knowledge/ | 규정·협의·업무 설명 | 출처·효력일·예외·확인 수준 기록 |
| SKILL.md | 반복 작업을 처리하는 절차 | 사용 조건·탐색·판단·검증 순서 |
| 기존 추출 소스 폴더 | ABAP·웹 자산·객체 정의 | 원천·baseline 보존, 실제 위치 인용 |
| tests/ 또는 harness/ | 평가 질문·검증 기록 | 기대 행동과 실제 결과 구분 |
| maps/ | 업무·코드·검증 관계 | 기존 경로를 유지하고 문서로 연결 |

Codex는 AGENTS.md를 작업 지침으로 읽으며 상위·하위 지침이 함께 적용될 수 있습니다. 기존 내용을 새 지침으로 통째로 덮어쓰지 않습니다. [공식 AGENTS.md 안내](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

폴더명은 예시이며 실제 저장소의 구조를 우선합니다. [업무 맥락 만들기](#/learn/knowledge), [업무 스킬 및 회귀](#/learn/feedback)에서 자료 정리·반복 작업의 기준을 이어갑니다.

## 4. 첫 분석 요청

업무 하나의 대상·기준 시점·근거 범위·원하는 결과를 적습니다. 소스와 업무 문서의 관계를 먼저 확인해 수정 범위를 정합니다.

```text
이 저장소의 근로시간 누적 표시 업무를 분석해 주세요.
업무 INDEX, 관련 규정과 후속 정정을 읽고 실제 추출 소스와 연결해 주세요.
규정 설명, 사용자 요청, 코드 구현, 실행 확인을 구분해 주세요.
근거 파일과 관련 구간을 적고, 없는 자료나 동적 호출 때문에
확정할 수 없는 부분은 확인할 질문으로 남겨 주세요.
이번에는 영향 분석만 작성하고 코드는 수정하지 마세요.
```

업무명은 실제 담당 업무로 바꿉니다. 파일 이름만 나열한 답변인지, 본문·조건·후속 정정을 읽고 판단했는지 검토합니다. 소스를 읽은 것과 SAP에서 실행한 것은 각각 기록합니다.

## 5. 수정 요청과 차이 검토

분석 후 변경할 동작·유지할 기능·검증 방법을 정합니다. 앱이 파일 수정이나 명령 실행 권한을 요청하면 대상 경로와 작업 범위를 확인합니다.

```text
앞서 확인한 파일에 요청한 표시 문구를 수정해 주세요.
사용자 변경, AGENTS.md, .git, .github, 로컬 설정을 보존해 주세요.
원천과 baseline의 바이트·줄바꿈을 유지해 주세요.
변경 전후와 이유를 기록하고 관련 검사를 실행해 주세요.
미실행 검사와 실제 SAP 검증이 필요한 항목을 구분해 주세요.
변경 비교 보고서와 변경 파일 ZIP을 제공해 주세요.
커밋·push·운영 배포는 제가 하겠습니다.
```

작업이 끝나면 앱의 변경 보기 또는 VS Code Source Control에서 파일별 차이를 읽습니다. 요청 밖 변경·원천 수정·줄바꿈 전체 변경을 확인합니다.

| 검토 항목 | 확인할 결과 |
|---|---|
| 실제 변경 | 파일 경로, 이유, 요청한 동작과 유지 조건 |
| 검사 | 실행 명령·결과, 화면 확인 범위, 미실행 항목 |
| 후속 작업 | 필요한 원문, SAP 시험, 사용자 승인·운영 반영 |

## 6. 포털 검증과 공유

이 포털은 Node.js 24 이상을 사용합니다. 루트 package.json과 지침을 확인하고 다음 명령을 실행합니다. 다른 ABAP 저장소는 그 프로젝트의 검사 절차를 따릅니다.

```bash
npm run build
npm test
npm run preview:file
```

변경한 화면과 다운로드를 확인한 뒤 [GITHUB 연동](#/learn/workspace)의 Commit·Push 절차로 공유합니다. 포털 검사 통과와 실제 SAP 호환성·운영 검증을 구분합니다.

## 7. 다음 작업에 넘길 MD

다음 대화에서 상태를 다시 추정하지 않도록 목적·결정·진행·근거를 남깁니다. 프로젝트 문서 4종은 다음 질문으로 읽습니다.

| 문서 | 읽을 질문 |
|---|---|
| intent.md | 왜 이 일을 하며 어떤 방향·경계를 유지하는가? |
| spec.md | 어떤 동작·결과물·수용 기준이 합의되었는가? |
| plan.md | 무엇을 구현·검증했고 다음에 무엇이 남았는가? |
| insight.md | 프로젝트의 이유가 누구에게 왜 설득력 있고, 사람들은 어떤 이해와 관점을 얻는가? |

동명 파일도 프로젝트별로 구분합니다. [소스 추출·진단의 자료확인](#/library/export-diag)에서 해당 문서를 받습니다. 문서 안의 초안·미확인 표기는 작성 당시의 상태로 읽습니다.

## 막힐 때 확인하기

- 파일이 안 보이면 앱의 작업 경로와 실제 Clone 위치를 비교합니다.
- 지침을 따르지 않으면 적용되는 AGENTS.md와 하위 지침을 확인합니다.
- GitHub에 결과가 없으면 Commit·Push 여부와 브랜치를 확인합니다.
- 예전 판단을 반복하면 새 자료의 시점·변경 이유를 제시하고 관련 MD 갱신을 요청합니다.

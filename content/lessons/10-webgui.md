# ERP WEBGUI 개편

## 기능과 디자인 개편

업무 화면의 작은 글자·좁은 입력칸·이미지 조각 버튼을 정리하는 데서 시작했습니다. 목표는 **기존 업무의 의미와 조작을 유지하면서 읽기·입력·처리가 편한 화면**입니다. 위 화면 비교는 「WEBGUI 개선 보고.html」의 자산으로 로컬에서 재현한 결과입니다.

중립적인 배경에 청색 포인트와 일관된 간격을 적용하고, 일반 UI에는 S-Core Dream을 사용했습니다. 다만 공백으로 열을 정렬한 목록은 글꼴 폭이 바뀌면 배치도 달라집니다. 따라서 이 영역은 고정폭 표현을 유지합니다.

## 아이콘의 형태와 의미

V423까지 일부 74개 아이콘을 선형 도형으로 통합했지만, 서로 다른 기능이 비슷한 그림으로 보였습니다. 따라서 V424에서는 원래 윤곽과 색을 살리는 SVG 방식으로 바꿨습니다. 위 비교에서 폴더·조회·저장의 구별 방식을 살펴볼 수 있습니다.

원형 SVG 카탈로그는 **1,247종**이며, 상단 매핑에는 이미지 32개·문구 6개의 규칙을 사용합니다. 전체 분위기를 통일하면서도 사용자가 기능을 구별할 모양과 색을 남기는 구성입니다.

## 결재 본문 수집과 표시

새 결재 화면은 설정에 등록된 거래를 대상으로 구성합니다. 먼저 스크롤로 나뉜 원문을 수집하고 겹치는 구간을 대조한 뒤 HTML 문서로 표시합니다. 잘린 경계선은 수집한 내용에 맞춰 복원하며, 본문이나 금액이 다르면 처리를 중단합니다.

| 단계 | 대조 기준 |
|---|---|
| 대상 판별 | 설정 응답과 현재 거래의 일치 |
| 본문 수집 | 비가시 구간과 마지막 행 포함 |
| 원문 대조 | 겹친 본문·금액·결재란의 일치 |
| 신규 표시 | 준비 안내와 구 화면의 순간 노출 제어 |
| 업무 연결 | 승인·반려·결재현황의 기존 명령 유지 |

위 예제는 **합성 구매 검수조서**를 사용해 수집한 문서를 표시하는 과정을 보여줍니다.

## 다운로드와 공통 UI 개선

Java Applet에 의존하던 파일 전달을 브라우저 다운로드로 연결하면서, 업무 ABAP의 FILE_SAVE_DIALOG·GUI_DOWNLOAD 경로는 유지했습니다. 문자열 `false`의 조건 처리처럼 작은 차이도 다운로드 흐름에 영향을 주었기 때문에 화면 수정과 파일 전달의 원인을 나누어 조사했습니다.

공통 UI에서는 메뉴 잘림·한글 IME Enter·달력과 팝업 크기·중복 스크롤 요청을 보완했습니다. 또한 반복 초기화로 아이콘이 작아지는 문제는 재현 조건을 기록해 수정했습니다.

## 버전별 변경 범위

| 흐름 | 주요 변경 | 적용 단위 |
|---|---|---|
| Chrome v3 | ITS 동작·스크롤·제출 값 검토 | Chrome 대응 계열 |
| Modern V2 | CSS·JS·HTMLBusiness·아이콘 개선 | 공통 웹자산 |
| V424 | 아이콘의 원형과 의미 유지 | 아이콘 매핑 |
| V426.2 | 다운로드 Bridge 1.0.2 | 누적 다운로드 자산 |
| V429 | UI 4.2.6·결재 1.4.5 | V428 기준 GUI.JS·GUI_BUTTON.CSS 증분 두 파일 |

파일을 반영할 때는 기준 버전과 변경 대상을 함께 맞춥니다. 특히 증분 묶음은 이전 버전의 파일을 바탕으로 적용하므로 변경 파일과 되돌릴 묶음을 함께 관리합니다.

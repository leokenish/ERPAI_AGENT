# ERP WEBGUI 개편

## 기능과 디자인을 함께 바꾼 과정

업무 화면의 작은 글자와 좁은 입력칸, 이미지 조각으로 표현된 버튼을 정리하는 데서 시작했습니다. **기존 업무의 의미와 조작을 지키면서 읽고 입력하고 처리하기 쉬운 화면**을 만드는 것이 기준입니다. 위 화면 비교는 첨부한 「WEBGUI 개선 보고.html」의 자산 기반 로컬 재현입니다.

중립적인 배경, 청색 포인트와 일관된 간격을 적용하고 일반 UI에는 S-Core Dream을 사용했습니다. 공백으로 정렬한 고정폭 목록은 기존 표현을 유지합니다. 글꼴 하나를 일괄 교체하는 것만으로 모든 화면을 개선할 수 없기 때문입니다.

## 아이콘: 익숙한 의미를 남기기

V423까지 일부 74개 아이콘을 선형 도형으로 통합했지만 서로 다른 기능이 같은 그림으로 보이는 문제가 있었습니다. V424에서는 원래 윤곽과 색을 유지하는 SVG로 돌아갔습니다. 위 대표 비교에서 폴더·조회·저장의 차이를 확인할 수 있습니다.

보고서의 **1,247종**은 원형 SVG 카탈로그 규모이며, 새 SAP 파일을 그만큼 반영했다는 뜻이 아닙니다. 상단 매핑은 38개 규칙(이미지 32·문구 6)입니다. 디자인의 통일성과 기능을 구별하는 단서는 함께 지켜야 합니다.

## 결재 본문: 보이지 않는 부분까지 확인하기

등록된 거래만 새 결재 화면의 대상으로 판별합니다. 스크롤로 나누어진 원문을 수집하고 겹치는 구간을 대조한 뒤 HTML 문서로 표시합니다. 잘린 경계선은 근거를 확인해 복원하지만 본문·금액이 다르면 중단합니다.

| 단계 | 확인할 기준 |
|---|---|
| 대상 판별 | 설정 응답과 현재 거래가 일치하는가 |
| 본문 수집 | 비가시 구간과 마지막 행까지 확보했는가 |
| 원문 대조 | 겹친 본문·금액·결재란이 같은가 |
| 신규 표시 | 준비 안내와 구 화면의 순간 노출을 제어하는가 |
| 업무 연결 | 승인·반려·결재현황의 기존 명령을 유지하는가 |

위 결재 화면은 **합성 구매 검수조서**입니다. 특정 결재 본문 표시 성공은 있었지만 모든 구매 양식과 창 크기 변경의 수용이 확인된 것은 아닙니다.

## 다운로드와 공통 UI의 회귀

Java Applet에 의존하던 파일 전달을 브라우저로 연결하면서 업무 ABAP의 FILE_SAVE_DIALOG·GUI_DOWNLOAD 경로를 유지했습니다. 문자열 `false`의 조건 처리처럼 작은 차이도 실제 흐름을 바꿀 수 있어, 화면 수정과 파일 전달의 원인을 나누어 확인했습니다.

다운로드는 사용자가 한 메뉴의 성공을 보고했습니다. 전체 메뉴·형식·파일 내용의 전수 확인으로 확대하지 않습니다. 메뉴 잘림, 한글 IME Enter, 달력과 팝업 크기, 중복 스크롤 요청, 반복 초기화에 따른 아이콘 축소도 각각 재현 조건을 기록해 보완했습니다.

## 버전과 반영 범위 읽기

| 흐름 | 변화 | 해석할 때 주의할 점 |
|---|---|---|
| Chrome v3 | ITS 동작·스크롤·제출 값 검토 | Modern V2와 별도 계열 |
| Modern V2 | CSS·JS·HTMLBusiness·아이콘 개선 | 로컬 재현과 SAP 실행을 구분 |
| V424 | 아이콘의 원형과 의미 유지 | 전체 카탈로그와 반영 객체 수를 구분 |
| V426.2 | 다운로드 Bridge 1.0.2 | 별도 누적 자산 |
| V429 | UI 4.2.6·결재 1.4.5, GUI.JS·GUI_BUTTON.CSS 증분 | V428 기준 두 파일, 전체 설치본 아님 |

초기 **ITS 쓰기 도구는 검토 단계**였고 이후 선택 반영·실행 보고로 이어졌습니다. 최신 V429 파일 확보와 실제 SAP 반영·현장 해결은 별개입니다. 변경 파일·기준 버전·원복 묶음을 대조한 뒤 실제 응답 버전과 업무 동작을 확인하는 순서가 필요합니다.

자료: 사용자 첨부 「WEBGUI 개선 보고.html」, 기존 공유 대화와 프로젝트 MD 4종. 보고서에 기록된 시험은 당시 기록이며 이번 포털 검증을 SAP 검증으로 대신하지 않습니다.

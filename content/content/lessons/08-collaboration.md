# 담당 에이전트에게 원격 자문하기

## 사람의 업무 분장을 따라가는 구성

HR 담당 맥에는 HR 자료, FI 담당 맥에는 FI 자료가 있습니다. 상대 패키지를 클론하지 않고도 HR 에이전트가 FI에 질문하고 근거 답변을 받으려는 설계입니다.

각 담당자의 Desktop 작업과 외부 질문을 처리하는 자문 워커는 별도 실행입니다. 중앙 MCP에 등록한다고 기존 Desktop 대화창이 수신 서버가 되거나 전체 대화 이력이 공유되지는 않습니다.

## 실제 예제가 제공하는 범위

확보 버전은 `erp-team-mcp-example 0.1.0`입니다. 중앙 Node.js 서버, SQLite 작업 저장, MCP 도구, 모의 FI 워커가 있습니다. 실제 Codex 자문 실행은 아직 연결되지 않았습니다.

| 구성 | 역할 | 상태 |
|---|---|---|
| ask_expert | 질문을 등록하고 job_id 반환 | 예제 구현 |
| get_answer | 본인 작업의 상태·답변 조회 | 예제 구현 |
| list_experts | 허용 담당과 최근 통신 확인 | 예제 구현 |
| 워커 claim·complete | 작업 배정과 결과 제출 | 모의 시험 기록 |
| FI 자문 AI | FI 소스·지식을 읽어 답변 | 미구현 |

후속 질문은 별도 follow_up 도구 대신 ask_expert의 parent_id를 사용합니다.

## 한 질문이 처리되는 순서

1. HR 에이전트가 FI 담당과 질문·맥락을 지정합니다.
2. 중앙 서버가 인증과 허용 담당을 확인하고 queued 작업을 만듭니다.
3. FI 워커가 작업을 가져가면 running 상태와 lease가 생깁니다.
4. 현재 모의 워커는 실제 분석 없이 `[MOCK]` 응답을 만듭니다.
5. 유효한 lease로 결과를 제출하고 HR이 get_answer로 조회합니다.

서버가 done을 반환했다는 것은 작업 결과가 등록됐다는 뜻입니다. 실제 업무 분석의 정확성까지 통과했다는 뜻은 아닙니다.

## 따라 하기: 모의 통신 검증

[중앙 MCP 예제 ZIP](downloads/ERP_MCP_NodeJS_Example.zip)을 별도 폴더에 풀고 그 안의 README부터 읽습니다. 예제는 Node.js 24 이상과 패키지 설치가 필요합니다. 교육 포털 서버와 다른 프로젝트입니다.

```bash
cd <예제를_푼_폴더>
npm ci
npm test
```

원천 기록에는 요청 생성·담당별 배정·답변 반환·타 사용자 차단·후속 이력·lease 거절에 대한 테스트 1개 통과가 있습니다. 새 맥의 설치, 실제 AI, 사내망, 장기 운영까지 검증한 기록은 아닙니다.

## 실제 운영으로 넘어갈 때

- 읽기 전용 자문 작업 사본과 실행 권한을 정합니다.
- 실제 AI 실행, heartbeat, 취소와 시간 제한을 구현합니다.
- 중복 요청과 실패 후 재시도 정책을 정합니다.
- 상대 답변에 근거 파일·커밋·미확인 사항을 포함합니다.
- 기본 루프백 HTTP를 사내 운영용 주소·인증 방식으로 구성합니다.

중앙 자문 예제는 SQLite를 사용하지만 **정적 교육 포털에는 DB가 필요 없습니다**. ERP 데이터를 조회하는 MCP와 이 자문 중계 MCP의 언어·배치는 별도로 결정합니다.

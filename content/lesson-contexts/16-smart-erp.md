## 1. 이유: 원래 하던 업무를 유지하면서 매일 보는 첫 화면을 정돈하기

스마트 ERP 메인화면은 메뉴와 결재·공지·서식으로 들어가는 출발점입니다. 사용자는 이곳의 많은 버튼·아이콘·배경을 현대적으로 정돈하고 싶어 했습니다. 새 업무 기능을 추가하기보다, 이미 사용하던 기능을 그대로 이용하면서 화면의 배치와 표현을 개선하는 것이 출발 요구였습니다.

따라서 목표는 **익숙한 업무 경로를 잃지 않고 원하는 화면을 실제 ERP 구조에 맞게 구현하는 것**입니다. AI로 시안을 만드는 단계와 기존 프로그램에 반영하는 단계가 이어지는 사례이며, 이 개편으로 전체 직원의 생산성이나 만족도가 높아졌다는 효과까지 측정된 것은 아닙니다.

## 2. 실제 근거·시행착오: 선명한 이미지 한 장으로 화면 전체가 완성되지는 않았습니다

초기 인물 중심 시안은 사용자가 원하는 분위기와 달랐고, 새 참고 화면을 바탕으로 반투명 패널과 서버 인프라 배경으로 방향을 바꿨습니다. 배경을 4K로 준비해도 프리뷰가 고정 크기이면 큰 창에 회색 여백이 남았습니다. 이 문제를 고친 뒤 당시 프리뷰의 창 대응에 대한 사용자 확인이 있었습니다.

이미지에서도 케이블 접합이나 서버 간격을 고치다가 이미 받아들인 다른 부분이 달라지는 문제가 있었습니다. 사용자는 기준 이미지를 다시 지정하고 해당 부위만 수정하도록 범위를 좁혔습니다. **시안의 분위기, 창 크기에 맞는 배치, 이미지의 국소 보정은 서로 다른 문제**였고 각각 확인이 필요했습니다.

## 3. 방향 설정: 확정한 기능과 시안을 기준으로 수정 범위를 좁힙니다

기능 보존을 우선하고, 선택한 시안의 재현·가독성·창 대응을 확인하는 순서로 방향을 정했습니다. 시안을 정한 뒤에는 매번 새로운 디자인을 제안하기보다 그 기준을 코드로 옮깁니다. 중앙 패널 제거와 결재 링크 이동처럼 나중에 명시된 요구는 이전 그림보다 우선합니다.

메뉴 계층·권한·주소·버튼 동작을 유지하면서 글꼴·행 높이·선택 표시를 개선하고, 배경 그림과 클릭 가능한 HTML 영역을 분리합니다. 화면 전체를 한 장의 그림으로 만들지 않아야 실제 메뉴·텍스트·게시판을 계속 사용할 수 있습니다. 프리뷰에 쓰인 모의 수치와 장식도 실제 업무 지표로 읽지 않도록 구분합니다.

## 4. 기술적 구현: 메인페이지와 안쪽 업무 화면의 연결을 함께 확인합니다

메인 화면에는 여러 페이지가 연결되어 있어 대표 화면 하나의 CSS만 바꾸는 것으로 끝나지 않았습니다. BSP는 SAP의 웹페이지 구성 방식이고, iframe은 한 화면 안에 별도의 페이지를 담는 영역입니다. 다음과 같이 실제 참조를 따라 수정 범위를 정했습니다.

1. **연결된 앱을 확인합니다.** `ZWEB_COMMON`, `ZWEB_MENU`, `ZWEB_WF`, `ZBULLETIN_BOARD`에서 메뉴·결재·게시판이 어느 페이지를 부르는지 확인합니다.
2. **표현을 나누어 적용합니다.** 배경은 이미지로 두고 실제 메뉴·결재·게시판은 HTML로 유지하며, 기존 호출 주소와 전달값을 보존합니다.
3. **창과 글꼴을 맞춥니다.** 페이지·패널의 크기 대응을 조정하고, 확보된 v9 자료에서는 관련 화면과 iframe에 S-Core Dream을 적용한 기록을 확인합니다.
4. **프리뷰와 실제 업무를 나누어 검토합니다.** 로컬의 모의 응답으로 배치를 확인한 다음 실제 SAP의 로그인·권한·결재·공지 연결을 확인해야 합니다.

아래 기존 화면과 전달물 점검은 이 흐름의 구체적인 결과입니다. 보관된 전체 v9 ZIP의 불완전성과 실제 SAP 검증 대기 상태를 유지하며, 프리뷰 확인을 운영 반영 완료로 설명하지 않습니다.

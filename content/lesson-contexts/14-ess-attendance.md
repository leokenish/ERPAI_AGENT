## 1. 이유

여러 날의 휴가 중 하루만 바꾸거나 취소하려는데 전체 기간을 다시 처리해야 한다면 신청자와 담당자 모두에게 부담이 됩니다. 따라서 날짜·반차·기간을 필요한 단위로 선택하고 변경할 수 있도록 근태 신청 화면을 개선했습니다. ESS는 직원이 직접 신청하고 결과를 확인하는 업무 화면입니다.

목표는 **직원이 입력한 날짜와 반차 구분이 저장·결재·실제 근태 기록까지 일관되게 이어지는 것**입니다. 이를 위해 좁은 신청 이력창, 첨부 방식과 날짜 선택을 개선하면서 휴가 사용량과 잔여 일수의 처리도 함께 살폈습니다.

## 2. 실제 근거·시행착오

신청자 이력에는 상신 상태가 보이지만 결재자의 목록에는 나타나지 않는 문제가 있었습니다. 화면에서 날짜가 바뀌거나 저장 메시지가 나오는 단계와, 결재자가 신청을 받아 처리하는 단계가 서로 다른 경로였기 때문입니다.

따라서 **선택한 값 → 저장된 상태 → 결재 전달 → 승인 후 실제 기록**을 나누어 대조했습니다. 또한 기존 화면과 R1 화면이 호출하는 페이지·함수·클래스를 비교해 어느 경로의 처리를 바꿨는지 추적했습니다.

## 3. 방향 설정

기존 화면을 남겨 두면 변경 전후의 동작을 같은 기준으로 비교할 수 있습니다. 따라서 `guntae_input.kbs`를 보존하고 새 `guntae_input_r1.kbs`에 개선 기능을 모았습니다. R1 페이지와 연결된 클래스·달력·관리자 화면도 함께 정리했습니다.

이미 승인된 휴가를 바꿀 때는 원래 승인 데이터와 새 변경 신청을 나누어 관리합니다. 그래야 승인 전의 기록을 보존하면서 최종 결재 결과에 따라 날짜·사용량·잔여 일수를 반영할 수 있습니다. 주말 처리 역시 근무형태와 휴가 종류의 조건에 맞춰 적용합니다.

## 4. 기술적 구현

BSP는 SAP에서 웹페이지를 구성하는 방식입니다. 화면이 보낸 요청을 ABAP 함수·클래스가 처리하고, 결재 작업과 근태 데이터로 이어집니다. 따라서 다음 구간을 연결해 살펴봅니다.

1. **신청 화면:** 날짜·반차·기간 분할·첨부·이력에서 선택한 값을 확인합니다.
2. **저장 처리:** R1 경로가 호출하는 함수·클래스와 임시 저장·상신 상태를 대조합니다.
3. **결재 연결:** 신청 번호·결재 번호·결재자의 작업 항목을 연결하고 실제 결재자 목록과 비교합니다.
4. **승인 결과:** 원래 휴가와 변경 신청을 기준으로 반영 날짜·사용량·잔여 일수를 대조합니다.

아래 사례에서는 화면 분리, 날짜 선택, 결재 전달, 기승인 휴가 변경과 첫 상신의 처리 경로를 순서대로 살펴봅니다.

## 1. 이유: 여러 업무 화면에서 반복되는 불편을 공통 부분부터 줄이기

ERP 기능은 그대로 필요한데, 오래된 화면의 작은 글자·좁은 입력칸·이미지 버튼 때문에 읽고 조작하는 일이 불편했습니다. 처음에는 기존 HTML·JavaScript와 배치를 지키며 가독성을 높이려 했고, 이후 추출한 WEBGUI·SYSTEM 자산을 바탕으로 화면과 조작을 함께 개선하는 방향으로 넓어졌습니다.

특히 결재 화면은 많은 ABAP 프로그램이 글자·공백·선으로 문서를 그리는 방식이었습니다. 화면 하나마다 업무 프로그램을 모두 고치기에는 대상이 많았습니다. 그래서 **여러 업무가 함께 사용하는 웹 표시 부분을 고쳐 기존 업무를 계속 쓰면서 불편을 줄일 수 있는가**를 탐색했습니다. 이 사례의 AI 활용은 예쁜 시안을 만드는 일에서 실제 코드·사용자 오류·반영 결과를 반복 대조하는 일로 이어집니다.

## 2. 실제 근거·시행착오: 모양을 통일해도 기능이 더 잘 보이는 것은 아니었습니다

스크롤을 조사하면서 WEBGUI 파일 외에 SYSTEM 쪽 자산도 함께 불린다는 것을 확인했습니다. 휠은 되는데 화살표 클릭에서는 문제가 생기는 피드백도 있어, 한 동작의 성공만으로 공통 처리가 끝났다고 볼 수 없었습니다. 화면에 보이는 증상과 실제로 호출되는 파일을 함께 추적해야 했습니다.

아이콘을 단순한 선형 도형으로 통일하자 서로 다른 기능이 비슷한 그림으로 보였습니다. 사용자는 익숙한 원래 모양을 유지해 달라고 요청했고, 이후 윤곽과 색을 보존하는 SVG 방식으로 바뀌었습니다. 파일 다운로드에서도 처음 의심한 화면 이탈 경고와 실제 Java Applet 의존을 나누어 조사했습니다. **보기 좋은 수정, 조작 오류, 파일 전달 오류는 각각 원인을 확인해야 하는 문제**였습니다.

## 3. 방향 설정: 익숙한 업무의 의미와 명령은 유지합니다

우선순위를 업무 정확성과 호환성에 두고, 그 안에서 조작·배치와 디자인을 개선했습니다. 화면에 입력한 값과 승인·반려 같은 기존 명령을 보존하고, 글자·간격·아이콘·팝업처럼 불편을 만드는 표현을 고칩니다. 공백으로 열을 맞춘 목록에는 다른 글꼴을 일괄 적용하지 않는 것처럼 화면의 생성 방식도 고려합니다.

새 결재 렌더러는 모든 목록을 결재 문서로 추측하지 않습니다. 설정 테이블 `ZWGUI_APPR_CFG`에 등록한 대상만 바꿉니다. 보이지 않는 본문까지 모아 겹친 내용이 같은지 확인한 다음 표시하고, 본문이나 금액이 다르면 중단합니다. 다운로드도 메뉴별 업무 ABAP을 일괄 수정하기보다 공통 웹 처리에서 기존 저장 요청을 이어받는 방향을 택했습니다.

## 4. 기술적 구현: 표시·조작·문서 수집·반영을 나누어 연결합니다

화면 모양을 정하는 CSS, 조작을 처리하는 JavaScript, 서버 화면을 만드는 템플릿과 아이콘을 함께 검토했습니다. 각 역할이 이어지는 흐름은 다음과 같습니다.

1. **공통 화면을 조정합니다.** 글자와 행 간격, 입력칸·달력·보조창을 개선하되 기존 입력값·명령·세션을 유지합니다.
2. **결재 원문을 확보합니다.** 등록 대상을 조회하고 준비 안내를 보여 준 뒤, 스크롤로 나뉜 구간을 수집·대조해 새 HTML 문서로 표시합니다. 기존 승인·반려·결재현황 명령을 연결합니다.
3. **파일을 브라우저로 전달합니다.** 기존 파일 저장 요청을 공통 처리에서 받아 Applet 대신 브라우저 다운로드로 이어 줍니다.
4. **바뀐 파일만 확인해 반영합니다.** 파일 경로와 SAP 객체를 맞추고 변경·저장·활성화 결과를 확인합니다. 기준 버전과 되돌릴 파일도 함께 관리합니다.

아래의 화면 전환·아이콘 비교·결재 절차·버전 표는 이 선택이 구체화된 자료입니다. 특정 결재 표시와 한 메뉴 다운로드의 성공 보고를 전체 화면이나 최신 버전의 SAP 검증 완료로 넓히지는 않습니다.

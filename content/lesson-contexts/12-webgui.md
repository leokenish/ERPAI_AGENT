## 1. 이유

ERP의 업무 기능은 계속 사용하고 있었지만, 작은 글자·좁은 입력칸·이미지 버튼 때문에 화면을 읽고 조작하기가 불편했습니다. 따라서 기존 HTML·JavaScript와 업무 동작을 살리면서 가독성과 조작 방식을 개선하는 방향으로 시작했습니다.

특히 결재 화면은 많은 ABAP 프로그램이 글자·공백·선으로 문서를 그리는 방식이었습니다. 모든 업무 프로그램을 하나씩 바꾸기에는 대상이 많았습니다. 그래서 **여러 업무가 함께 사용하는 웹 표시 부분을 개선해 반복되는 불편을 줄이는 방법**을 선택했습니다.

## 2. 실제 근거·시행착오

스크롤 문제를 조사하자 WEBGUI 파일과 SYSTEM 자산이 함께 호출되고 있었습니다. 또한 마우스 휠과 화살표 버튼의 처리도 달랐습니다. 따라서 화면의 증상만 보는 데서 나아가 실제 호출 파일과 동작별 처리 경로를 함께 추적했습니다.

아이콘을 단순한 선형 도형으로 통일했을 때는 서로 다른 기능이 비슷한 그림으로 보였습니다. 이 때문에 사용자가 익숙하게 구별하던 윤곽과 색을 보존하는 SVG 방식으로 바꿨습니다.

파일 다운로드에서는 화면 이탈 경고와 Java Applet 의존 문제가 함께 나타났습니다. 따라서 **화면 표시, 조작 오류, 파일 전달을 나누어 원인을 조사하고 수정 결과를 대조했습니다.**

## 3. 방향 설정

익숙한 업무 기능을 유지하려면 화면을 바꾸더라도 입력값과 승인·반려 같은 기존 명령이 이어져야 합니다. 따라서 업무 정확성과 호환성을 우선하고, 그 안에서 글자·간격·아이콘·팝업을 개선했습니다.

공백으로 열을 맞춘 목록은 고정폭 글꼴을 유지합니다. 글꼴 폭이 달라지면 열 정렬까지 바뀌기 때문입니다.

결재 렌더러는 설정 테이블 `ZWGUI_APPR_CFG`에 등록한 대상에 적용합니다. 또한 보이지 않는 본문까지 수집해 겹치는 내용과 금액을 대조한 뒤 새 화면으로 표시합니다. 다운로드는 공통 웹 처리에서 기존 저장 요청을 이어받도록 구성했습니다.

## 4. 기술적 구현

화면 모양을 정하는 CSS, 조작을 처리하는 JavaScript, 서버 화면을 만드는 템플릿과 아이콘을 함께 검토했습니다. 각 역할은 다음 순서로 연결합니다.

1. **공통 화면 조정:** 글자·행 간격·입력칸·달력·보조창을 개선하고 기존 입력값·명령·세션을 유지합니다.
2. **결재 본문 수집:** 등록 대상을 조회하고 준비 안내를 표시합니다. 이어서 스크롤로 나뉜 구간을 수집·대조해 HTML 문서로 구성하고 승인·반려·결재현황 명령을 연결합니다.
3. **브라우저 다운로드:** 공통 처리에서 기존 파일 저장 요청을 받아 브라우저의 다운로드로 이어 줍니다.
4. **변경 파일 반영:** 대상 파일의 경로와 SAP 객체를 맞추고 저장·활성화 결과를 대조합니다. 기준 버전과 되돌릴 파일도 함께 관리합니다.

아래 화면 비교·아이콘 비교·결재 절차·버전 표에서 각 선택의 적용 내용을 살펴볼 수 있습니다.

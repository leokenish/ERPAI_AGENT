## 1. 이유

몇 년 전의 업무가 언제 시작해 어떻게 이어졌는지 찾으려면 여러 주간보고서를 다시 열어야 합니다. 금주 실적과 차주 계획이 매주 별도 문서로 취합되기 때문입니다.

따라서 이 프로젝트는 **여러 해의 주간업무를 국·업무·시간의 흐름으로 연결하고, 궁금한 지점에서 원문으로 돌아가는 화면**을 목표로 삼았습니다. 연도와 국을 선택한 뒤 가로 시간축의 업무 가지를 읽으면, 구성원도 자신의 경험과 이전 업무를 다시 찾아볼 수 있습니다.

## 2. 실제 근거·시행착오

처음에는 부서·담당자·기간이 명확한 데이터를 바탕으로 업무별 MD 파일을 만들려고 했습니다. 하지만 실제 한글 문서의 XML 형식인 HML에서는 취합 단위가 국이었고, 담당자·날짜는 문장 안에 섞여 있었습니다. 같은 업무의 제목도 주차마다 조금씩 달랐습니다.

따라서 제목만 일치시키는 방식으로는 업무의 흐름을 연결하기 어려웠습니다. ‘ERP DR서버 구성작업 추진’의 반복 기록은 연결 후보로 살피되, ERP 웹 고도화와 근태 시스템 고도화는 업무 목적을 비교해 별도 가지로 다뤘습니다.

자료를 모을 때는 종료일 입력 제약, 첫 주 다운로드 뒤 멈추는 매크로와 반복 저장창 문제가 있었습니다. 이에 수집 절차를 보완해 수백 HML을 다운로드했습니다. 화면에서도 실제 자료 규모에 맞춰 연도 선택·가지 간격·잘림·미니맵을 조정했습니다.

## 3. 방향 설정

탐색 기준은 연도 → 국 → 업무로 정하고, 담당자는 기록에 있을 때 표시합니다. 날짜가 모호한 경우에는 시간축에 배치한 기준과 원문 표현을 함께 남깁니다. 그래야 독자가 화면의 위치를 보고 원래 기록까지 되짚을 수 있습니다.

장기간의 업무를 카드마다 MD로 관리하면 반복 갱신과 검색이 복잡해집니다. 따라서 **HML은 원본, JSON 계열은 업무카드와 색인, MD는 명세와 사용 안내**로 역할을 나눴습니다. 조직 폴더에는 담당자가 알아보기 쉬운 원래 국 이름을 사용합니다.

## 4. 기술적 구현

JSONL은 한 줄에 업무카드 한 건을 저장하는 텍스트 형식입니다. 색인은 원하는 자료의 위치를 찾기 위한 목록입니다. 원문부터 시간축 화면까지 다음 순서로 연결합니다.

1. **원문 보관:** HML의 표·문단을 읽고 원본 파일과 위치를 남깁니다.
2. **업무카드 생성:** 국별 업무 내용과 기록된 담당자·기간을 추출해 원문 위치와 연결합니다.
3. **업무 연결:** 제목·어휘·시점 규칙과 표본 맥락 검토로 연결 후보를 구성하고 판단 근거를 남깁니다.
4. **화면 탐색:** 색인에서 해당 기간의 기록을 찾아 가지·사건·미니맵으로 표시하고 원문 근거로 이동합니다.
5. **새 자료 반영:** 새 HML을 반영한 임시 결과를 만들고 검사한 뒤, 변경 파일과 최종 목록을 교체합니다.

아래 갤러리는 가상 시연에서 실제 자료 화면으로 구체화된 과정을 보여줍니다.

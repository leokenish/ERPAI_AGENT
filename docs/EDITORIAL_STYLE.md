# 포털 설명문 문체 기준

2026-10-27 사용자 승인 기준. 기존 내용과 구성을 보존하는 문체 편집에 적용한다.

## 설명의 길이와 말투

짧은 평서문을 기본으로 하되 배경과 이유까지 읽을 수 있는 분량을 유지한다. 문장을 명사형 항목으로 지나치게 줄이거나 핵심어만 나열하지 않는다. `~습니다`를 `~다`로 바꾸는 데서 끝내지 않고, 긴 문장 안의 상황·판단·결과를 나눠 연결한다.

예: “AI는 계산 코드의 조건을 보고 반차 예외가 빠진 결함이라고 판단했다. 하지만 담당자의 설명은 달랐다. 이 사례에서는 실제 출근 시각이 아닌, 원래 근무 시작 시각부터 전체 구간을 입력해야 했다.”

## 이번 편집에서 지킨 범위

- 과정 번호와 공식 제목, 절의 단계와 순서, 기존 문단 블록을 유지한다.
- 목록·표·코드·이미지·링크의 개수와 연결을 보존한다. 설명형 소제목은 뜻을 유지하며 어미를 다듬을 수 있다.
- 사례·조건·예외·한계·향후 방향을 생략하지 않는다. 원인이나 성과를 새로 추정해 덧붙이지 않는다.
- 숫자·날짜·버전·식별자와 당시의 시제를 유지한다. 보고·확인·미확인을 다른 상태로 바꾸지 않는다.
- 대화기록은 실제 사용자와 AI의 말투를 유지한다. 원문 인용, 코드, 복사용 요청문, 내려받는 프로젝트 원본은 설명문 교정과 구분한다.
- 버튼·검색·오류 안내는 사용자가 할 행동을 쉽게 이해할 수 있는 표현을 쓴다. 안내 문장을 모두 평서문으로 강제하지 않는다.

## 검토 순서

1. 원문 문단에서 사실·조건·이유·한계가 무엇인지 확인한다.
2. 같은 정보를 자연스러운 문장으로 고친다. 한 문장에 여러 판단이 있으면 나눈다.
3. 문단별로 전후 내용을 대조하고 정보가 빠지거나 추가되지 않았는지 읽는다.
4. 제목 단계·목록·표·코드·링크·수치·원문 바이트를 비교한다.
5. 빌드·기존 테스트와 실제 화면에서 목차, 줄바꿈, 검색, 자료 접근을 확인한다.

문체 편집 중 사실 오류로 보이는 부분을 발견해도 조용히 고쳐 쓰지 않는다. 기존 근거와 시점을 별도로 대조할 후속 검토 항목으로 남긴다.

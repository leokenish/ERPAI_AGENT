## 설명 문체

설명은 합니다·입니다체로 작성합니다. 요청문은 “확인해 주세요”처럼 정중하고 구체적으로 표현합니다. 문장을 과도하게 줄이지 않고 처음 읽는 사람이 이유와 처리 순서를 이해할 정도의 맥락을 제공합니다.

먼저 독자가 겪는 문제를 말하고, 그 원인을 설명한 뒤 선택한 방법과 결과를 연결합니다. 실제 인과관계가 있을 때 따라서·때문에·이를 바탕으로 등을 사용합니다. 관련 없는 사항은 별도 문단이나 목록으로 나누며 접속어로 억지 연결하지 않습니다.

예: “결과 ZIP과 공유 링크만 받은 동료는 무엇부터 읽어야 할지 판단하기 어렵습니다. 자료마다 역할과 작성 배경이 다르기 때문입니다. 따라서 프로젝트의 목적과 선택한 방법을 먼저 설명하고, 관련 대화와 파일을 연결합니다.”

편집 실수의 해명, 확보하지 못한 첨부 안내, 미구현·미검증 상태의 반복 고지는 학습 설명에서 제거합니다. 실제 시행착오의 원인·수정 기준과 기술적 제약은 이해에 필요한 범위에서 남깁니다. 설계는 설계로, 모의 예제는 모의 예제로 설명하며 실행·운영 완료를 새로 만들어 적지 않습니다.

## 대화 선별과 원본 보존

반복 재촉·감사·짧은 확인만 있는 대화와 자료 이관·다운로드 재시도 같은 관리 대화를 표시에서 제외합니다. 짧은 문장이라도 오류 원인·핵심 요구·판단·실제 결과를 담으면 유지합니다. 사용자 요청은 문맥을 읽고 주체·대상·조건이 드러나도록 정돈합니다.

원본 발화·코드·첨부파일을 수정하지 않습니다. 선별·표시용 편집과 원문을 분리하며, 원문 해시가 달라지면 빌드를 중단하고 다시 검토합니다. 빈 에피소드는 숨기고 이전 주소는 같은 프로젝트의 유효한 학습 흐름으로 연결합니다. 실제 첨부는 관련자료의 프로젝트 목록에서 계속 접근할 수 있습니다.

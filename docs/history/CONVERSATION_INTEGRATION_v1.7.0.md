# 교육 대화 통합 기록

2026-10-12 · 포털 v1.7.0 · 기존 포털 v1.5.5 기반

## 화면에서 읽는 방법

1. 전체 구성도의 요소를 선택한다. 역할 설명 옆의 ‘실제 대화로 배우기’로 아래 학습 영역에 이동한다.
2. 해당 요소와 관련된 프로젝트를 선택한다. 왼쪽 목록에는 관련 에피소드만 표시된다.
3. ‘대화 기록’에서 실제 요청과 응답을 순서대로 읽는다. 긴 메시지는 전문을 펼치고, 다음 항목 또는 전체 항목을 표시할 수 있다.
4. ‘해설·시행착오’에서 요청의 의도·오해·수정 이유·결과를 확인한다.
5. ‘따라 하기’의 재작성 실습 지시를 복사해 자기 업무 자료에 적용한다.
6. ‘프로젝트 맥락’에서 시작 목적·환경·방향 변경·현재 확인 범위와 추출본의 맥락 전문을 읽는다.
7. ‘관련 자료’에서 당시 화면·확보 파일·미확보 자료를 구분한다.

왼쪽 ‘프로젝트 대화’에서는 구성도 필터 없이 6개 프로젝트의 전체 흐름을 읽는다. 기존 교육 과정에도 관련 대화 진입 링크를 추가했다. 전체 검색은 교육 본문과 에피소드·화면에 표시하는 대화를 함께 검색한다. 이 화면은 보존된 기록을 읽는 학습 화면이며 외부 AI와 실시간 통신하지 않는다.

모든 추출본의 coverage는 partial이다. 원문 전사는 추출본이 확보한 화면 본문 수준이며 플랫폼 전체 내보내기나 전체 프로젝트 대화 확보를 의미하지 않는다. 모든 대화 항목은 적어도 하나의 에피소드에서 접근 가능하다. 여러 요소에 연결된 에피소드를 중복 집계하지 않았다.

Export·DIAG는 사용자 92개와 AI 9개로 구성된다. 이번에 추가한 AI 3개는 교육자료 추출 과정의 진행·최종 답변이다. 초기 AI 답변 대부분이 없어 사용자 요청·오류 보고와 후속 코드·문서를 연결한 해설을 제공한다. AI 답변을 새로 만들어 말풍선에 넣지 않았다. MCP·Telegram의 요약 13개는 ‘답변 요약’으로 구분한다. 자체 ID·확인된 시각·미확인 시각·마스킹 여부·출처 위치를 그대로 유지한다.

## 기존 포털 자료와의 관계

- Obsidian 추출본은 해당 대화방에서 실제 화면을 확보하지 못했다고 명시한다. 포털에 별도로 제공된 업무지도·전체 그래프 2장은 과정 05의 후속 자료로 연결한다. 당시 첨부로 소급하거나 링크·속도 검증 성공으로 확대하지 않는다.
- 카카오톡 추출본에서 말한 원래 TXT·이미지는 미확보다. 포털의 SRC-11 TXT 사례는 별도 제공 자료이며 동일 원본이라고 단정하지 않는다.
- 기존 DIAG 캡처와 이번 대화·소스의 시점 및 버전을 구분한다. 최신 0.4.5 SAP 성공을 새로 확인한 것은 아니다.
- 중앙 Node 예제의 모의 워커 검증과 실제 AI 연결·ERP 조회·Telegram 왕복을 구분한다.
- 과거 Import·공유 폴더·VPN·장비·SDK 관련 제안을 현재 결정으로 자동 승격하지 않는다. 방향 변경의 이유와 결과는 각 에피소드의 해설에서 읽는다.

## 파일 구조와 갱신

- sources/conversations/20261012/{project_id}: 업로드 ZIP 내부 174개 파일을 상대경로와 바이트 그대로 보존했다. 기존 sources와 해시는 변경하지 않았다.
- content/conversations/catalog.json: 포털용 시작 목적·환경·현재 상태·별도 자료와의 관계, 기본 에피소드 선택을 관리한다.
- scripts/build-conversations.mjs: schema_version 1.0·ID·발화 순서·참조·포함 파일·노드 연결을 확인하고 표시용 HTML을 빌드한다.
- site/conversations.js, site/conversations.css: 대화 뷰와 반응형 스타일. site/app.js가 구성도·메뉴·검색·이동·복사와 연결한다.
- dist/assets/conversations: 파일 확보 상태가 included인 실제 이미지 23개만 복사한다. 이미지 색·본문·크기를 재생성하지 않는다.
- dist/downloads/conversations: 프로젝트별 README·맥락 MD·전체 학습 가이드 MD·추출 JSON을 제공한다. 각 파일의 상대경로 원본 자료는 전체 프로젝트 ZIP 안에 있다.

기타 원천 ABAP·실행기·과거 ZIP·자료는 전체 프로젝트 ZIP에 보존하며 웹에 자동 배포하지 않는다. 중앙 MCP 예제는 기존 허용 다운로드를 재사용한다. 미확보 자료는 클릭 가능한 가짜 다운로드를 만들지 않는다. 역사적 sandbox 링크와 미확보 상대 링크는 표시용 텍스트로 처리하고, 원문 JSON에는 원래 문자열을 유지한다. 사용자 문장 복사는 교육용 편집본을 사용한다.

새 대화 묶음을 추가할 때는 출처 폴더·메타데이터·source-files 해시를 추가하고 필요한 노드·관련 과정을 지정한다. 과거 원문을 최신 판단으로 덮어쓰지 않는다. 빌드·검증 후 단독 preview.html도 갱신한다.

## 확인 범위

v1.7.0 빌드와 자동 검증 31개를 통과했다. 입력 원문 보존·54개 에피소드의 5개 내용 화면·이미지 및 파일 링크·구성도 요소별 선택·프로젝트 전환·직접 주소 복원·대화 순차 표시를 확인했다. UI 제어 시험은 DOM 대역을 사용하는 로직 검증이며 실제 브라우저 렌더링 검증은 아니다. 이 환경에는 지원되는 브라우저 확인 도구가 없어 실제 화면의 줄바꿈·스크롤·모바일·Safari는 별도 확인이 필요하다.


## 교육용 문체 · v1.6.1

사용자 요청에 따라 텍스트가 있는 사용자 발화 143개를 정중한 경어체로 편집했다. 인사·군더더기는 줄이고 요구 범위, 의문, 가설, 당시 판단과 후속 변경 순서를 유지했다. 과거의 오해를 확정 사실로 바꾸지 않았다. 텍스트가 비어 있는 3개 항목에는 편집 발화를 만들지 않고 첨부 전용 안내를 표시한다. AI 발화 94개는 편집하지 않았다.

- `content/conversations/editorial-prompts.json`: 프로젝트 ID → 발화 ID별 교육용 `content_markdown`과 원문 `source_sha256`.
- 원천 JSON의 본문·역할·시각·유형·출처는 기존 그대로 보존한다. `editorial_markdown`, `editorialHtml`은 표시 데이터의 별도 필드다.
- 기본 말풍선은 “교육용 문장”으로 표시한다. v1.6.2 요청에 따라 “원문 확인”과 “원문 복사”는 제거했으며, “교육용 문장 복사”를 유지한다. 원천 JSON은 보존한다.
- 긴 요청은 편집본 기준으로 접어 표시한다. 검색에는 사용자 교육용 문장과 AI 답변을 포함한다.
- 원문이 변경되면 SHA-256 불일치로 빌드를 중단한다. 편집본을 다시 검토한 후 연결해야 한다. 새 사용자 발화에도 교육용 문장을 추가한다.

### AI 답변 미확보의 근거

추출본 자체가 전체 플랫폼 내보내기가 아닌 접근 가능한 일부 기록이다. Export·DIAG의 `coverage`에는 사용자 92개와 AI 6개만 보존했으며 U002–U090에 대응하는 과거 AI 답변 대부분을 확보하지 못했다고 명시되어 있다. MCP·Telegram은 초기 AI 답변 전문 대신 요약 13개와 발췌 1개를 확보했다. WebGUI에도 일부 과거 응답 전문이 빠져 있다고 기록되어 있다. 포털이 확보한 AI 메시지를 누락한 것은 아니며, 현재 249개 항목 모두 연결되어 있다. 해당 전문이 추출 시점에 접근되지 않은 세부 원인은 자료만으로 확정할 수 없다.

추가 원문을 제공받으면 질문·응답의 순서와 기존 발화 ID를 대조한 후 새 출처로 보존하고 연결한다. 미확보 답변을 추정 생성하여 원문으로 표시하지 않는다.


AI 답변 전문 보완을 각 프로젝트에 요청할 때는 `docs/AI_Response_Full_Export_Prompt.txt`를 사용한다. 두 프로젝트의 보완본을 수령하여 아래와 같이 반영했다.


## 답변 전문 보완 · v1.7.0

- 새 원천 124개 파일은 `sources/conversations/20261012-supplement/{project_id}`에 보존했다. 기존 추출본 폴더와 해시는 그대로 유지한다. 빌드의 프로젝트별 `sourcePath`로 현재 보완본을 선택한다.
- Export·DIAG의 기존 98개 필드 값은 동일하고 응답 확보 상태 등 메타데이터가 추가됐다. A007–A009를 E18의 자료 추출 과정에 연결하여 101개가 됐다. U002–U090에 대응하는 과거 기술 답변은 여전히 미확보다.
- WebGUI의 기존 41개 발화는 동일하다. wg-m051 사용자 상태 문의와 wg-m052–056 AI 진행·최종 응답을 wg-ep08에 연결하여 47개가 됐다. SYSTEMGUI·오류 추적·v3·구조 제안의 4개 구간/5개 요청에 대한 과거 기술 답변은 여전히 미확보다.

## 바뀐 내용

01–10과정을 설치·기능 설명 중심에서 **이유 → 실제 근거와 시행착오 → 방향 설정 → 기술적 구현 → 사례 → 한계와 다음 방향**으로 다시 구성했습니다. 먼저 업무의 문제와 선택 이유를 이해하고, 실제 파일·도구·절차로 이어지도록 작성했습니다. 전문 용어는 등장하는 맥락에서 풀어 설명하고 직접 해볼 수 있는 작은 과제를 넣었습니다.

- **01 전체 그림:** 반복 문의·흩어진 근거·인수인계의 어려움에서 출발해 무엇을 만들고 어떤 문제를 줄이는지 설명합니다. 기존 구성 표를 자료 확보·AI 작업·검토의 흐름에 통합했습니다. 이해하기 어렵다고 지적한 두 절은 제거하고 구체적인 질문·확인 행동으로 바꿨습니다.
- **02 소스 추출:** 패키지를 출발점으로 삼은 이유, 함수·DDIC·화면·BSP·MIME 관계, 누락과 XML 처리 시행착오, 원본·작업본·서버 비교, BSP 한 앱 모드가 추가된 이유를 설명합니다. 확보된 Export·CHECK·DIAG와 각각의 한계를 나눴습니다.
- **03 GITHUB:** SAP에서 GitHub로 직접 통신하려던 시도, 확인된 TLS 오류와 보류 결정, PC를 거쳐 공유하게 된 경위를 먼저 설명합니다. 뒤에 VS Code·Git 설치, ABAP 확장, Clone·원격 지정·Stage·Commit·Fetch·Pull·Push 절차를 배치했습니다.
- **04 로컬 에이전트:** 파일을 매번 다시 전달하던 한계와 로컬 폴더·Codex를 택한 이유를 설명한 뒤 설치·프로젝트 폴더·지침·첫 요청·변경 검토로 이어집니다. 로컬 파일 작업과 오프라인 AI를 혼동하지 않도록 정리했습니다.
- **05–08 업무 적용:** 실제 문의에서 맥락을 추출하고, 문서 사이에 길을 만들고, 잘못된 판단을 피드백·스킬·재검증 질문으로 남기고, 변경을 검증하는 흐름으로 연결했습니다. IAM 기본값, 반차 0원, 누적표시 롤백, BSP 페이지 확인 등의 실제 사례를 근거 범위 안에서 설명했습니다.
- **09–10 확장:** 담당자에게 업무 지식을 묻는 연결과 ERP의 현재 데이터를 조회하는 연결이 필요한 이유를 나눴습니다. 모의 통신 예제·가상 계약·아직 구현 또는 실행 확인이 필요한 부분을 구체적으로 구분했습니다.

각 과정은 여섯 개 본문 단위와 근거 링크로 구성됩니다. 소개 문구와 학습 목표도 함께 수정했습니다. 기존 상세 Git 안내, 실제 화면·자료 링크, 과정 하단의 실제 대화 연결은 유지합니다.

## 사실 확인과 보존

최초 대화부터 후속 진행 대화, 실제 ABAP·업무 문서·피드백·화면 자료를 대조했습니다. 설치·제품 안내는 2026-10-26 확인한 공식 문서와 대조했습니다. 과정별 근거와 확인 범위는 `docs/CURRICULUM_REVIEW_v1.16.0.md`에 있습니다.

패키지 추출을 폐기한 것으로 쓰지 않았고, BSP 한 앱 모드는 추가 선택지로 설명했습니다. TLS 제약은 당시 시스템의 확인 결과입니다. 과거 BSP 성공 사례를 최신 DIAG 전체 검증으로, 41개 기대 답변 초안을 41건 시험 통과로, 모의 워커를 실제 AI 업무 분석으로 표시하지 않았습니다.

기준 ZIP과 바이트 비교 결과 원천 1,576개, 대화·문체 편집 68개, 11–16과정 6개, assets 36개, site 14개, scripts 15개, tests 15개 및 AGENTS.md가 동일합니다. 과정 번호·이름·주소·분류, 자료실 소스·다운로드 목록도 그대로입니다. ‘이 과정 자료’와 발표 기능을 재도입하지 않았습니다. 실행 코드와 테스트는 변경하지 않았습니다.

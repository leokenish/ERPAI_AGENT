## 반영 내용

### 05 · 업무 맥락 만들기

“어떤 문제를 겪었는가”에 **초기 업무 정의에서 코딩·IT·ERP 기술 용어를 적지 않는 원칙**을 추가했습니다. 기술 용어가 먼저 나오면 담당자가 업무를 설명하기 전에 시스템 구조부터 알아야 한다고 느끼고, 현재 코드 동작을 업무 정책으로 오해할 수 있다는 이유를 설명합니다.

대상·상황·기준·예외·처리 이유·근거를 업무 언어로 작성하도록 표와 예시를 넣었습니다. 업무·정책 질문 → 담당자의 답변 검토·정정 → 업무 기준 정리 → 필요한 코드 연결의 순서를 안내합니다. “어떻게 만드는가”에는 **0단계 · 업무 질문과 기준 정의**와 복사 가능한 요청문을 추가했습니다. 기존 ZHR5 분석 이력·실제 문답·자료 링크는 유지합니다.

### 본문 강조 색상

기존 강조 스타일을 사용하는 설명문의 굵은 텍스트는 라이트 `#a52b3c`, 다크 `#ffabb5`로 변경했습니다. 제목·버튼·문서 다운로드 링크는 기존 역할별 색상을 유지합니다. 특히 MD 파일명은 파란색이며 밑줄과 외부 이동 화살표 없이 바로 다운로드합니다.

각 사각형은 실제 MD 한 개입니다. 위쪽 역할 버튼을 누르면 해당 문서와 관련된 연결선이 강조되고, 아래에는 문서의 역할·전체 경로·연결 이유가 표시됩니다. 파란 파일명은 원래 MD를 직접 다운로드합니다. “전체 연결”·빈 배경·Esc로 전체 관계로 돌아가며, 역할 버튼의 방향키·Home·End 탐색을 지원합니다.

기존 문서 25개와 역할 설명을 유지합니다. 선은 이 과정에서 함께 읽는 문서 관계이며, 서버 실행 순서를 새로 주장하지 않습니다. 11 과정의 전체 지식 지도는 변경하지 않았습니다. 별도 외부 라이브러리는 추가하지 않았습니다.

## 로컬 반영

1. 로컬이 v1.18.0이면 Changes ZIP을 사용합니다. 이전 버전이거나 전체 파일이 필요하면 Full ZIP을 함께 사용합니다.
2. ZIP은 기존 저장소 밖에서 풀고, 안의 `project/` 내용을 기존 저장소 루트에 비교·병합합니다. 기존 프로젝트 안에 `project/project` 폴더를 만들지 않습니다.
3. `CHANGE_MANIFEST.json`의 변경 전 해시와 로컬 파일이 다르면 덮어쓰지 말고 `REVIEW.patch`와 실제 변경을 비교해 병합합니다. 이미 변경 후 해시와 같으면 건너뜁니다.
4. `.git`·원격·브랜치·로컬 설정·별도 수정은 보존합니다. 삭제 파일은 없습니다.
5. Node.js 24 이상에서 아래 명령을 실행합니다.

```bash
npm run build
npm run preview:file
npm test
```

6. 05의 기술 용어 배제 원칙·0단계 요청문과 05–07의 관계도·다운로드·테마를 확인합니다.
7. 의도한 소스 변경만 커밋하고 현재 저장소의 실제 원격·브랜치로 push합니다. `dist/`, `preview.html`, `preview-data/`는 재생성 결과물이며 새로 Git에 추가하지 않습니다.

ZIP의 `APPLY.md`에는 Codex Desktop에 붙여 넣을 적용·검증·push 프롬프트가 있습니다.

이번 작업은 로컬 반영용 패키지 제작까지입니다. GitHub commit·push·운영 배포는 수행하지 않았습니다.

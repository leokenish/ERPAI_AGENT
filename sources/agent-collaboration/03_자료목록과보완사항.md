## C. 새로 제작할 설명용 시각자료

다음은 제작 제안이며 실제 화면이 아니다. 현재는 MD의 Mermaid 구성도와 표만 제공한다.

| 자료 | 전달 목적 | 필수 요소·연결 관계 | 표현 방식 | 문서 근거 |
|---|---|---|---|---|
| 담당 맥·중앙 구성도 | 데이터 위치와 실행 위치 구분 | HR Codex→중앙, FI 워커→중앙, FI AI→로컬 ZFI; 미구현 점선 | Mermaid/SVG | 01 §4 |
| 두 통신 통로 비교 | MCP 등록만으로 워커 수신이 되지 않음 | /mcp 대 /worker, 호출 주체·응답 | HTML 표 | 01 §5, 02 §5.2 |
| 자문 상태도 | queued/running/종료/실패 구분 | claim, complete, heartbeat/임대 만료, 요청 만료 | Mermaid | 01 §5.1 |
| 원안→교정안 비교 | 요구를 잘못 읽었을 때의 설계 변화 | ERP 루트, 수동 요청, 로컬 자문, 원격 중계와 제외 이유 | HTML 비교표 | 01 §8~10 |
| 지식·통신·권한 3층 | MD/MCP/접근 제한을 혼동하지 않기 | 접점 MD, 메시지 전달, 파일 쓰기 제한의 독립성 | SVG 또는 HTML 카드 | 01 §4.3·6 |
| 구현 상태 지도 | 모의 통신을 완성된 AI 서비스로 오해하지 않기 | 구현 서버·모의 워커, 미구현 AI·운영 | HTML 상태 표 | 01 §12~13 |
| 후속 질문 문맥 | Desktop 전체 대화가 아님 | parent_id, 선행 최대 3개 Q/A, 새 job | Mermaid | 02 §5.5 |

그래프 링크는 문서 연결이며 실제 SAP 호출 관계가 확인되었다는 뜻이 아니라는 범례가 필요하다. 색깔만으로 상태를 구분하지 말고 텍스트 라벨을 함께 표시한다.

## D. 포털 상호작용 아이디어

| 기능 | 학습에 도움이 되는 이유 | 보여줄 내용·동작 | 범위 제한 |
|---|---|---|---|
| 구성 요소 클릭 | 중앙 AI/담당 AI 혼동 해소 | 역할, 입력·출력, 구현 상태, 근거 파일 | 문서 설명만, 실제 서버 호출 아님 |
| 자문 단계 넘기기 | 누가 먼저 접속하는지 이해 | 요청 생성→FI claim→MOCK 완료→HR 조회 | 가상 시뮬레이션으로 표기 |
| 업무 탭 HR/FI/중앙 | 같은 사건을 역할별로 확인 | 보유 소스·허용 행동·사용 API | 실제 담당자 개인정보 제외 |
| 초기안/최종안 비교 토글 | 설계 변경 이유 보존 | 사용자 조건과 맞지 않았던 이유 | 초기안을 권장안으로 노출하지 않기 |
| 구현/미구현 배지와 펼침 | 증거와 목표를 분리 | 코드·시험·미검증 목록 | pass를 운영 배지로 바꾸지 않기 |
| 코드 근거 열기 | 일반론보다 실물 학습 | registerTool, owner 조건, MOCK 반환 위치 | 전체 코드 본문 중복 최소화 |
| 명령·설정 복사 버튼 | 오타 감소 | npm ci/test/start, MCP TOML, 실습 질문 | 대체값 표시와 토큰 주의문 포함 |
| 문제 해결 펼침 | 401/409/queued 상황 대응 | 원인·확인 방법·추가 검증 필요 | 인증 우회 방법 제시 금지 |

정적 포털에서 중앙 MCP를 직접 호출하는 기능은 별도 요구·인증·Origin 정책 검토가 필요하다. 현재 예제의 브라우저 Origin 차단을 문서만 바꾸어 해제하지 않는다.

## F. 통합 담당자에게 전달할 기준

1. 이 묶음은 ‘분산 담당 에이전트의 통신’ 단원에 배치한다.
2. 기초 Git/Codex 사용 다음, 실제 AI 워커/운영 배포 전에 모의 통신 실습을 배치한다.

## B. 실제 화면 캡처 요청 목록

아래 화면은 **향후 실제 환경에서 촬영할 목록**이다. 현재 확보된 기존 이미지는 없다. 실제 제품 화면을 생성형 이미지로 대체하지 않는다. ‘현재 설정’과 ‘실습용 설정’을 캡션으로 구별하고, 토큰·사번·내부 URL·조직명 등 공개 범위 밖의 값은 가린다. 토큰을 만들거나 다시 표시하는 장면은 교육 캡처에 필요하지 않다.

| 프로그램과 구체적 화면 | 반드시 보여야 할 요소 | 설명할 교육 내용 | 기존 이미지 활용 가능 여부 | 사용자 추가 캡처 |
|---|---|---|---|---|
| 선정 장비의 OS 정보·터미널 | OS·CPU 아키텍처·메모리, Python 또는 Node 버전. 장비 식별값은 가림 | ‘한 서버’의 실제 환경, 재현 가능한 버전 [01 §3·§11] | 확인된 이미지 없음 | 예. 장비 선정 후 |
| 프로젝트 폴더·터미널 | 실제 파일명, 가상환경 또는 패키지 잠금파일, 작업 경로 | SDK 설치와 완성 ERP MCP 제품 설치의 차이 [02 §8.1~§8.2] | 없음 | 예. 실습 파일 생성 후 |
| MCP 서버·클라이언트 실행 | 서버의 수신 주소, 도구명·입력·반환값, 실제 버전 | AI 없이도 가능한 MCP 호출 확인 [02 §8.2] | 없음 | 예. 첫 성공 시 |
| 개발계 API 테스트 화면 | 마스킹된 URL, JSON 필드, 응답 업무 상태, 요청 시각 | REST 계약과 MCP 도구 계약의 매핑 [02 §8.3~§8.4] | 없음 | 예. API 사용 승인 후 |

API 테스트나 로그가 성공한 화면 하나만으로 전체 연동 성공을 증명하지 않는다. MCP·ERP·AI·Telegram의 단계별 증거와 동일 테스트 건 식별자를 함께 기록한다. 이 증거 연결은 교육 보완 제안이며 기존 프로젝트에서 구현된 로깅 체계가 아니다.

## C. 새로 제작할 설명용 시각자료

현재 MD에 포함된 Mermaid는 문서용 설명이다. 렌더링한 이미지 파일이나 실제 시스템 화면은 생성하지 않았다. 아래 나머지 그림은 통합 포털 단계의 제작 후보다.

|---|---|---|---|---|
| 사내·외 경계가 있는 역할 구성도 | 단일 서버여도 봇·에이전트·MCP 역할은 다름 | 외부 모바일·Telegram, 사내 호스트, 에이전트의 소스 지식 참조, MCP→REST→ECC, 선택한 외부 모델. 요청·응답과 망 경계 표시 | Mermaid. 01의 도식을 포털에서 재사용 | 01 §4~§6 |

실제 API 명세가 없으므로 그림에 임의 RFC 함수명을 운영 함수처럼 넣지 않는다. 가상 구매오더 예시에는 ‘가상’ 표시를 유지하고, 실제 근태 데이터 사례로 오인될 직원명·사번은 사용하지 않는다.

### E.2 통합자가 유지해야 할 경계

1. 현재까지 확인한 결과는 설계 논의와 예시 제시다. 기존 코드의 설치·실행·검증·운영 완료 상태로 올려 적지 않는다.
2. 대화에서 제안한 Python 구성을 후속 Node.js 파일명만으로 폐기하거나, 반대로 Node.js 파일을 확인 없이 무시하고 최종 언어를 확정하지 않는다.
3. Telegram long polling은 사내에서 허용된 외부 HTTPS 연결을 이용하는 방식이다. 사내 통제 우회 수단으로 설명하지 않는다.
4. 사용자가 설명한 개인정보 전제는 보존하되, 실제 ERP 데이터가 Telegram·모델 제공자에게 전달되는 경로와 최소 정보 원칙도 표시한다. 이번 추출에는 실제 데이터·인증정보를 넣지 않았다.
5. 다른 프로젝트의 실제 오류·테이블·스킬·에이전트 구성은 그 프로젝트 원본을 확보한 후 별도 출처로 연결한다. 현재 자료의 가상 근태 예시를 실제 KBS 업무 검증 사례로 전환하지 않는다.
6. 이 문서의 추가 검증·운영 체크리스트는 **교육 보완**이다. 과거 대화에서 확정하거나 구현한 기능으로 거슬러 서술하지 않는다.

## F. 패키지 확인 범위

이번 패키지의 확인 대상은 필수 MD 4개 존재, 참고·예시 5개 존재, 상대경로 링크, JSON 구문, 문서 상태 용어, ZIP 최상위 경로와 파일 일치다. 이 확인은 실습 명령 실행, MCP 호환성 시험, ERP 데이터 조회, Telegram 송수신 또는 서비스 운영 검증을 포함하지 않는다.

상세한 프로젝트 상태는 [01 §12~§14](01_프로젝트_맥락과설계.md), 실습별 예상 결과와 확인 방식은 [02 §8~§9](02_교육과실습.md)에 있다.

# 선택근무 기간 중 단가 변경 계산 검토

## 요청과 결론

SRC-23(2026-10-29) 사용자 설명: 2026-09-01 단가 인상 때 기존 시스템은 선택기간 시작일 단가로 4주를 계산했다. 인사부담당자가 8월 8,400원·9월 9,240원을 일자별로 나누어 수기 계산했고, 그 결과를 ZTHREDITCOST에 등록했다. 이번 요청은 ZRPTH411_COMPARE의 날짜별 단가 계산 가능성과 대휴 단가 처리에 관한 검토다. 구현·SAP 반영 요청으로 확대하지 않는다.

개선은 가능하다. **소정시간·휴일 충당·대휴 발생 판정은 4주 전체 기준을 유지하고, 확정된 지급 대상 시간을 원천 입력·항목별로 연결하여 입력 시작일의 유효 단가를 적용한다.** 9월 1일을 기준으로 선택기간을 두 개로 만들어 각각 독립 정산하거나 금액을 달력 일수로 안분하지 않는다.

**SRC-23 같은 날 후속 정정:** 하나의 입력이 8월 31일 밤부터 9월 1일 새벽까지 이어져도 단가는 입력 시작일인 8월 31일 기준이다. 여기서 입력 시작일은 실적의 근무 시작일이며 시스템에 등록한 날짜가 아니다. 앞선 AI의 자정 전후 단가 분리 제안은 철회한다. 기존 내부 시간/휴게·휴일 분류 처리는 유지하며 단가 변경을 위해 입력을 새로 분할하지 않는다. 대휴는 BS01에 들어갈 때 일자를 확인해 확보한 단가를 사용하는 기존 경로를 유지한다는 사용자 설명을 적용한다. 시차실비와 재량·간주근무 단가는 이번 인상 대상이 아니다.

사용자 설명은 수기보정의 업무 목적을 확인한 근거다. 개별 수기 산식·승인·입력값·지급 정확성까지 검증한 것은 아니다. 기존 비교 차이를 곧바로 과다 지급·환수액 또는 실적 변경액으로 해석하면 안 된다. 원정산에는 수기 금액이 반영되고 재계산에는 그 보정이 반영되지 않는 차이가 포함돼 있다.

대상은 단가 변경을 포함하는 선택근무 기간이다. 8,400→9,240원 인상 대상과 방송지원직 D등급 5,400원 유지 등 직군별 조건은 [현행 단가 설명](../policies/overtime-rate-20260901.md)을 따른다. 모든 사람에게 9,240원을 강제하거나 과거 등급을 현재 등급으로 덮어쓰지 않는다.

## 권장 계산 흐름

1. 현재 비교 기능의 계산용 실적·근태·달력을 사용하여 4주 전체의 소정·실근로·휴일 충당·대휴를 산정한다. 기존 208시간·간주·가산·특별연장·승인상태 등 산입 조건을 보존한다.
2. 금액 계산 직전까지 원천 입력별 지급 대상 분을 유지한다. 연장·야간·휴일 150%/50%·대휴 50%를 분리하고 원천 실적과 연결한다. 야간 가산처럼 같은 근무시간에 별도로 발생하는 항목을 오류로 중복 제거하지 않는다.
3. 연장·야간·휴일에는 원천 입력 시작일의 직원 등급과 유효 단가를 조회한다. 9월 1일이나 특정 금액을 하드코딩하지 않는다. 내부 시간 계산에서 익일 자료가 생기더라도 원천 입력 시작일과 연결하여 단가 기준을 보존한다. 대휴는 생성 시 확보된 단가를 사용한다. 캐시로 중복 조회를 줄이며 단가 누락·중복 유효행은 명시적인 미계산/확인 대상으로 남긴다.
4. 입력·항목별 지급 대상 분 ÷ 60 × 해당 단가 × 해당 지급률을 합산한다. 익일 입력 전체에 시작일 단가를 적용하고 기존 휴게·야간/휴일 판정은 유지한다. 단가 인상을 이유로 입력 분할이나 휴게 재배분을 추가하지 않는다.
5. 날짜별 시간 합계가 기존 4주 항목별 시간과 일치하는지 대조한다. 단가가 일정한 기간에는 기존 금액과도 같아야 한다. 금액만 바꾸면서 소정시간·대휴 개수가 바뀌는 구현은 재검토한다.

|---|---|

설명용 예: 지급 대상 연장시간이 이미 8월 31일 1시간, 9월 1일 9시간으로 확정되었다면 1×8,400 + 9×9,240 = **91,560원**이다. 기존 시작일 단가 방식의 84,000원보다 7,560원 증가한다. 지급 대상 시간의 정확성을 새로 입증한 SAP 사례는 아니다.

## 대휴 단가에 대한 검토 의견

**기간 정산의 대휴실비와 ZTHRBS01의 대휴 보유금액은 구분하되, 사용자 설명상 이미 날짜를 확인하여 확보하는 대휴 단가 경로를 이번에 다시 설계하지 않는다.** SRC-23 후속 설명은 BS01 입력 단계에서 해당 일자의 단가를 확보하고 대휴 생성 시 그 단가를 사용한다는 운영 확인이다.

앞선 AI가 마지막 금액 산식에 재조회가 없다는 이유로 대휴 단가 경로까지 미흡할 수 있다고 강조한 부분을 정정한다. 원천 단가를 상속하는 코드 사실은 앞 단계에서 날짜별 단가가 확보된다는 설명과 양립한다. 이 설명을 신규 SAP 실행 검증이나 모든 운영행 대사 완료로 확대하지 않는다. BS01에 별도 단가 컬럼이 있다고 추정하지 않고 생성자료의 단가와 저장금액을 구분한다.

기간 정산은 여전히 선택기간 시작일 단가로 대휴실비를 계산하므로, 재계산한 대휴 명세의 단가·시간·금액을 연결하는 개선이 필요하다. 비교 프로그램은 실적 변경에 따른 가상 재생성을 수행하므로 과거 BS01 총액을 무조건 고정 복사하지 않는다. 기존 금액은 비교 대상으로 보존하고, 새 명세는 기존 대휴 단가 기준을 따라 계산한다. 이 합산 연결은 구현 검증 대상이다.

## 비교 결과와 영향 범위

권장 출력은 원정산 금액(수기보정 반영 가능), 기존 선택기간 시작일 단가 재계산, 원천 입력 시작일별 단가 재계산의 세 금액이다. 상세에는 입력 시작일·대휴 발생일·항목·지급분·등급·단가·지급률·금액·원천 실적과 인상 전후 소계를 표시한다. 실제 수기 테이블 금액은 참고 열로 분리한다. 월·사번 보정금액을 근거 없이 여러 선택기간에 배분하지 않는다.

같은 실적·지급시간·단가·원 단위 처리로 HR 수기 산식과 일치한다면 단가 경계 때문에 발생한 차이는 해소될 것으로 예상한다. 첨부 결과만으로 전원의 차이가 0이 된다고 보장할 수 없다. 등급 변경, 제외 실적 상태, 시간 귀속, 휴게, 반올림/절사, 시차실비와 수기 오류 가능성은 항목별 잔여 차이로 검토한다. 수기 총액에 맞추려고 계산 결과를 덮어쓰지 않는다.

## 남은 확인과 전달 자료

구현 전에 추가로 대조할 핵심은 두 가지다. 첫째, 기존 B 분기는 4주 초과시간에서 대휴시간을 합계로 차감하므로 입력 시작일별 단가를 적용하려면 그 차감시간을 원천 실적에 연결해야 한다. 대휴로 전환된 원천 시간을 해당 입력에서 제외하는 방식을 후보로 삼되, 기존 누적·휴일 충당 계산 및 HR 수기 내역과 일치하는지 검증한다. 이미 합의된 연장 발생일 기준을 다시 미정 정책으로 취급하지 않는다. 둘째, HR 수기 내역도 익일 한 입력에 시작일 단가를 적용했는지 확인해야 한다. 다르게 계산했다면 잔여 차이를 새 프로그램 오류로 단정하지 않는다.

원 단위 처리·휴게·소정·대휴 자격·시차실비 금액은 기존 기준 유지가 기본안이다. 산식 대사에서 차이가 확인될 때만 추가 결정을 요청한다. 수기 원장과 동일 시점 실적/근태·단가 및 원천 연결은 검증 자료이며 지금 이미 확정된 업무 기준을 다시 질문할 이유는 아니다. 별도 메시지 발송은 하지 않았다.

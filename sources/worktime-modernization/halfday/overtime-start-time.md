# 통상·시차 시간외 입력의 시작시각

## 적용 기준


통상·시차근무의 시간외 입력은 초과근무 구간만 입력하는 방식이 아니다. 원래 출근시각(자율출근에 따른 기준 출근시각 포함)부터 종료시각까지 전체 구간을 입력하고, 반차·지참·조퇴 등은 별도 근태와 연계하여 전체 시간에서 감하는 처리 방식이다. 오전반차 후 실제 업무를 시작한 시각으로 입력 시작시각을 늦추면 전체 구간이 누락되어 계산이 달라질 수 있다. [SRC-14, 2026-10-01 사용자 최종 확인]

| 조건 | 입력 예시 |
|---|---|
| 원래14:00~22:00 시차, 승인된 오전반차, 실제18:00~23:00 근무 | 시작14:00, 종료23:00. 반차는 별도 승인 근태로 반영 |
| 원래09:00 출근 통상근무, 저녁18:00~19:00 시간외 | 09:00~19:00 입력. 18:00~19:00만 입력하지 않음 |
| 자율출근 | 개인의 해당일 기준 출근시각을 확인. 모두09:00으로 고정하지 않음 |
| 선택근무 | 위 통상·시차 입력 규칙을 적용하지 않음. 실제 근무시각 입력 안내와 구분 |

입력 시작시각은 이번 처리 방식의 기준이며 반차 중 실제 근무했다는 뜻이 아니다. 휴게는 실제 휴게 구간을 유지하고 승인 근태로 공제할 시간을 임의로 휴게에 중복 입력하지 않는다. 오후반차·조퇴의 구체 종료시각 입력 방식은 이 사례만으로 확정하지 않는다.

기존2026-07-28 협의도 통상 오전반차 후 실제14:00~21:00 근무를 원래 자율출근시각09:00~21:00으로 입력하고, 선택근무는 실제14:00~21:00을 입력한다고 설명했다. [SRC-10 L2898–2914, 2026-07-28; 협의 정리본](../feedback/SRC-10-late.md)

## 10월2일 시차·오전반차 사례의 원인 정정

사례 조건: 2026-10-02 금요일 평일(사용자 제공), 원래14:00~22:00 시차, 오전반차 승인, 실제18:00~23:00 근무, 실제 휴게19:30~20:00. 최초 입력18:00~23:00에서는 실근로4.5시간으로 잡혀 필수시간 미달 조건에 걸리고 금액이0원으로 처리됐다는 사용자 최종 확인이다. 올바른 입력 시작은14:00이다. [SRC-14]

앞선 AI 분석은 금액0원 분기를 찾았지만, 입력 기준을 확인하기 전에 '승인 반차 예외가 빠진 고정7시간 검사'를 결함 원인과 수정 방향으로 제시했다. 이 결론은 **이번 사례에서는 철회**한다. 시작시각 입력 오류를 먼저 바로잡아 재계산해야 하며, 사례만으로7시간 조건 삭제나 반차 우회 분기를 권고하지 않는다.

확인한 추출 코드: ZHR_52TM_GET_OVERTIME_DATA 130–146행은 시차B·평일·퇴출아님 조건에서7시간/휴게1시간 검사를 하고 총액 및 표시용금액을0으로 설정한다. 이는0원으로 보인 경로의 근거이며 정책 오류 자체의 증거는 아니다. 내부 항목금액과 표시용금액도 구분한다.

확인 상태: 사용자가 입력 기준과 원인을 최종 확인했다. 공식 정책 시행일은 미제공이며 기록일2026-10-01과 사례일2026-10-02를 정책 시행일로 사용하지 않는다. 수정 입력 후 최종 지급액·실행 로그는 제공되지 않았으므로 검증 완료로 쓰지 않는다. 화면 필수시간4.5의 정확한 산출 분기는 별도 미확인이나 이번 입력 안내를 보류할 이유는 아니다.

## 후속 문의 확인 순서

근무유형 → 원래/자율출근 기준시각 → 실제 입력 시작·종료 → 승인 근태 → 실제 휴게 → 계산 결과 순으로 확인한다. 입력 기준이 맞는지 확인한 다음 코드 결함 여부를 판단한다. [피드백 기록](../../harness/feedback/FB-20261001-001.md)

## 최신 코드 판본 안내 — 2026-10-22

입력 구간에 대한 SRC-14 기준은 유지한다. 근태일 차단 조건을 검토할 때는 [SRC-17 KSP 변경 분석](../code-map/export-20261022.md)과 [근태 검증 문서의 현재 로컬 반영 기준](leave-work-validation.md#현재%20로컬%20반영%20기준%20—%202026-10-22,%20SRC-18)를 먼저 본다. 2026-10-16 KSD의 대휴 34 제외·ZTHRBS08 분기를 현재 구현으로 혼용하지 않는다.


## 일반검진 오전 반일과 통상 시간외 계산 — 2026-10-29 확인

**결론: 통상근무는 일반검진 반일을 포함한 전체 구간을 본래 기준 출근시각부터 입력한다.** 실제 오후 출근시각부터 입력하면 누락된 오전 구간을 시스템이 자동으로 앞에 붙이지 않는다. 본래 출근시각은 개인의 자율출근 기준을 확인하며 모두 09:00으로 고정하지 않는다. 오전에 실제 근무했다는 의미가 아니다. 휴게는 실제 구간만 입력하고 반일 근태 4시간을 휴게에 중복 입력하지 않는다. 선택근무의 실제시각 입력에 이 기준을 적용하지 않는다. [SRC-14; SRC-24, 2026-10-29 사용자 확인]

### 적용 조건과 정상·오입력 비교

설명용 사례: 통상 평일, 본래 기준 출근 09:00, 오전 공가 일반검진 반일 근태가 계산에 반영됨, 실제 오후 근무 13:00~22:30, 실제 휴게 18:00~19:00. 일반 시간외이며 익일·익휴·퇴출·재난 및 다른 근태는 없다. 금액은 2026-09-01 이후 기준단가 9,240원 대상자 기준이다. 방송지원직 등 다른 단가·인상 전 날짜는 별도 계산한다. [SRC-12/13/24]

| 계산 항목 | 정상 입력 09:00~22:30 | 오입력 13:00~22:30 |
|---|---:|---:|
| 전체 입력 구간 | 13시간 30분 | 9시간 30분 |
| 실제 휴게 공제 | 1시간 | 1시간 |
| 입력 기반 전체시간 ZA_TIME | 12시간 30분 | 8시간 30분 |
| 통상 기준 8시간 차감 후 연장 | **4시간 30분** | **30분** |
| 연장실비(100%) | 4.5×9,240 = 41,580원 | 0.5×9,240 = 4,620원 |
| 야간시간(22:00~22:30) | 30분 | 30분 |
| 야간실비(50%) | 0.5×9,240×0.5 = 2,310원 | 2,310원 |
| 합계 | **43,890원** | **6,930원** |

오입력 시 이 사례의 연장 4시간·연장실비 36,960원이 적게 산출된다. 이는 입력 사례와 추출 소스에 따른 산술이며 실제 SAP 재현·지급 검증은 아니다.

### 실제 처리 순서와 업무 설명의 구분

1. `ZHR_52TM_GET_OVERTIME_DATA` L61–82 → `LZHR008_2F03`의 `CALC_WORK_TIME_DAILY` → `ZHR_52TM_CALC_WORK_TIME_DAYILY`로 입력 구간을 전달한다. 일별 함수 L328–362에서 입력 시작·종료와 휴게를 사용해 시간을 계산한다.
2. 일별 함수 L541–553에서 해당일의 ZTHR0101 통상 상수 `ZNORHR`를 읽고 L581–625에서 정상/초과 구간을 나눈다. 사례는 통상 기준 8시간을 전제로 한다. 이는 운영 상수 행을 직접 조회했다는 뜻이 아니다.
3. `LZHR008_2F03` L5768–5770에서 `ZHR_52TM_CALC_NORM_OT_PAY`를 호출한다. 해당 함수 L109–119에서 평일 야간·연장시간을 계산하고 L237–250에서 연장 100%, 야간 50% 금액을 산출한다.
4. `ZHR_52TM_AWART_LIST` L228–235는 GUNART=40·GUNTYPE=28/29의 일반검진 오전/오후 인정시간을 4시간으로 설정한다. `ZHR_52TM_GET_OVERTIME_DATA` L91–100에서 호출하는 `ZHR_52TM_ORDINARY_ZE_TIME2`는 근태 목록을 읽고, L225–227의 4시간 근태 분기에서 `ZE_TIME = ZA_TIME − 8시간`으로 보정한다. 이 분기는 입력 시작을 오전으로 확장하거나 연장실비 금액을 다시 계산하는 처리가 아니다.
5. `ZHR_52TM_GET_OVERTIME_DATA` L130–146의 통상 평일 조건은 전체시간 8시간 미만 또는 휴게 1시간 미만이면 표시금액을 0으로 만든다. 이번 오입력은 전체 8.5시간·휴게 1시간이므로 이 조건으로 0원이 되지는 않는다.

정상 입력의 업무상 의미를 설명할 때는 ‘입력 기반 12.5시간 중 일반검진 4시간을 제외하면 실제 근로 8.5시간이고, 오후 소정 4시간을 넘는 4.5시간이 연장’이라고 풀 수 있다. **그러나 이를 코드가 실제로 `12.5−4−4` 순서로 계산하거나, 근태가 입력 시작시각을 자동 보충한다고 설명하면 안 된다.** 위 코드 경로의 시간 분리와 후속 ZE_TIME 보정을 구별한다. [SRC-17, 2026-10-22 추출본 정적 확인]

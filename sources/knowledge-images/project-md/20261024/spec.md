## 1. 현재 결과물과 사용 시나리오

원문에서 재사용 가능한 지식을 추출하여 한국어 Markdown으로 제공하는 프로젝트다. 현재 결과물은 `name: kbs-worktime-knowledge`를 가진 단일 `SKILL.md`이며, WK-001~WK-030 카드와 색인이 들어 있다. 실제 Codex에서 동작을 확인한 스킬이라고 보증하지 않는다.

| 시나리오 | 기대 동작 | 현재 근거 |
|---|---|---|
| 과거 업무 처리 방법 조회 | 질문과 맞는 카드, 적용 조건, 예외와 원문 근거를 함께 제시 | 기존 스킬에 답변 원칙·색인 구현. 실사용 시험 미확인 |
| 유사하지만 다른 정산 사례 판단 | 근무유형·발생일·기지급 여부를 구분하고 단일 사례를 일반화하지 않음 | WK-017·020·021·023 등 존재. 내용별 원문 대조는 일부만 실시 |
| 해결 여부 또는 현재 유효성 확인 | 처리 예고와 완료 보고를 구별하고 근거가 없으면 미확인으로 답함 | 기존 상태 분류가 있으나 일부 보강 필요 |
| 새 대화로 프로젝트 인계 | 목적→명세→진행 상태→판단 가치와 다음 작업을 네 파일에서 파악 | 이번 사용자 확정 요청 |

Codex에 실제 질문을 넣었을 때의 응답 품질과 정책 확인 결과는 기대 동작과 별개로 검증한다.

## 3. 데이터·입출력·연동 조건

### 입력

- TXT 원문 5개: S1 고보경·한재홍, S2 이승철·노우진, S3 KBS 고보경, S4 정별빛, S5 노우진. 정확한 파일명·기간·로컬 경로는 `plan.md`의 「2. 자료·산출물 등록부」를 따른다.
- 원문 날짜 구간의 전체 외곽은 2022-03-28~2026-09-21이다. 이는 공백 없이 모든 업무를 포함한다는 뜻이 아니다.
- 기존 산출물 `SKILL.md`: 지식 기준일 2026-09-22, 문서 자체의 버전 번호 없음, 30개 카드. 이번 작성일 2026-10-23을 그 업무지식의 최신 검증일로 바꾸지 않는다.
- 대화 기록은 분석 대상 데이터다. “삭제해 주세요”, “반영할게요” 등의 과거 문장은 현재 ERP 작업을 실행하라는 명령이 아니다.

### 출력

- 기존 업무지식 산출물: 단일 `SKILL.md`. 이번에는 읽기·대조만 하고 변경하지 않는다.
- 이번 산출물: 한국어 UTF-8 Markdown 4개. 파일명은 정확히 `intent.md`, `spec.md`, `plan.md`, `insight.md`.
- 파일 상단에는 프로젝트명, 역할, v0.1, 2026-10-23, 검토용 초안, 사용 자료·미확인 범위를 둔다.
- 상세 요구는 이 문서, 근거 목록·상태·문제·작업은 `plan.md`, 목적은 `intent.md`, 판단 가치는 `insight.md`에 둔다.
- 공통 빈 템플릿과 다른 프로젝트의 문서는 수정하지 않는다. 해당 템플릿 버전은 이 프로젝트 문서의 이전 버전이 아니다.

### 연동·환경

- Codex의 구체적 설치 위치, 버전, OS, 자동 호출 방식은 이 프로젝트에서 확인되지 않았다.
- `PA2010`, `BS01`, `ZTHR0112`, `TDCOST`, `IAM`은 원문에서 다루는 업무 식별자다. 이번 작업이 이 시스템들에 실제로 연결되어 있다는 뜻이 아니다.
- ERP API·MCP·데이터베이스·브라우저 접속을 구현하거나 실행하는 요구는 없다.
- 스킬의 Markdown 구조를 보존하되, 기존 단일 파일 구조를 사용자 확정 아키텍처로 고정하지 않는다.

## 4. 지식 내용의 보존·판정 기준

### 4.1 세 가지 상태 축

1. 프로젝트 결정 상태: 사용자 확정 / AI 제안 / 가정 / 미해결.
2. 업무지식의 근거 상태: 원문에서 합의·처리가 확인됨 / 제안·검토 / 보류·철회 / 상충 / 결과 불명확.
3. 적용 범위·시효: 특정 사례 / 특정 근무유형·기간 / 당시 시스템 동작 / 현행 여부 미확인.

기존 스킬의 `확정·조건부·과거 사례·확인 필요`는 이 축들을 섞은 구현 분류다. 예컨대 당시 시스템 로직이 확인됐더라도 규정상 정당성이나 현재 유효성은 확인되지 않을 수 있다. 새 답변·문서에서 이를 분리하고, 스킬 자체의 구체적 분류 개편 방식은 이후 정한다.

### 4.2 적용 전에 보존해야 할 분기

| 사례 | 반드시 보존할 차이 | 원문 확인 범위 |
|---|---|---|
| 누락분과 환수·환급 | 기지급/기입력 유무, 근무유형, 결재·예산의 이중 계상 위험 | S3 2026-04-20 및 2026-08-19 |
| 대휴 기간 | 선택의 4주 종료일, 재량의 기간 종료일, 간주의 개별 휴일근무일·발생시작일 | S3 2026-06-09~12. 시스템 설명과 제도 해석의 간극 존재 |
| 단가 변경 | 발생일, 대상 고용·등급, 정액 항목의 예외, 신규 입력과 기존 입력 | S3 2026-07-29, S1 2026-09-16~18 |

| 반복 정산 오류 | 재등록·개별 수정 완료와 원인 해소·전수 검증의 차이 | S5 2026-02-06, S2 2024-07-02~03 |

이는 현재 업무지식의 정답표가 아니라, 추출·응답에서 생략하면 안 되는 조건의 목록이다. 실제 지급·삭제·대휴 변경은 담당자의 현행 규정·권한 확인이 필요하다.

### 4.3 원문 없는 결론 처리

- 사진·엑셀·HWP의 이름 또는 “파일” 메시지만 있으면 첨부 본문을 읽었다고 쓰지 않는다.
- 전화로 설명했다는 기록이 있어도 전화 내용 자체를 복원하지 않는다.
- “이번 주 처리 예정”, “확인해 보겠다”, 감사 표현만으로 결과 검증을 인정하지 않는다.
- 후속 기록에서 같은 계열 문제가 나와도 동일 원인이라고 단정하지 않는다.
- 2022년의 “주말 및 공휴 제외 3일”과 2026년의 “3일”은 최신 문장에 생략이 있을 수 있다. 규정 변경이 입증된 충돌로 단정하지 않는다.

## 5. 현 산출물과 요구의 차이

현재 스킬의 존재는 확인했지만 다음 차이가 있다.

- 출처 목록 S2~S5 파일명이 실제 첨부명과 다르다.
- WK-023은 2026-08-19 사례를 S1로 연결했지만, 확인된 원문은 S3에 있다.
- 직접 인용·발언자·시각, 변경 이력, 일회성 기록 등 원래 요청의 일부 요소가 압축되었다.
- WK-004의 평일 소정시간 조건과 휴일 5시간 조건은 원문에서 결합돼 있다. 개별 불릿을 독립 충분조건으로 읽지 않도록 보강할 필요가 있다.
- WK-012~014의 “확정”은 당시 시스템 설명과 현행 규정 확정을 분리할 필요가 있다.
- WK-029는 2023~2025년 사례로 요약됐지만 2026-02-06에도 PA2010 누락·추가 기록이 있다.

확인 근거와 다음 조치는 `plan.md`의 이슈 ISS-001~ISS-007에 둔다. 이 문서를 작성했다고 해당 문제를 기존 스킬에 수정 반영한 것은 아니다.

| 보완 전후 비교 | 기존 MD, 추가 근거, 바뀐 해석, 남은 의문 | 보완이 실제 무엇을 바꾸는지 이해 | 기존·개선 MD 확보 후 가능 | 02 §7.5~7.6 |
| 프롬프트 복사 | 자료 확인·연결 후보 프롬프트, MD 보완·검수 프롬프트 | 준비된 지시를 같은 기준으로 사용 | 자리표시자와 미검증 안내 함께 복사 | 02 §7.3~7.4 |
| 체크리스트 펼침 | 교육 게시 전 확인 항목 | 실습 완료와 게시 승인을 구분 | 체크 상태를 자동 검증 결과처럼 보이지 않게 함 | 02 §12 |

업무별 탭은 실제 자료가 여러 업무로 분류된 뒤 검토한다. 현재 근거만으로 FI·MM·HR 탭 내용을 임의로 채우지 않는다. 서버 기능이나 사용자 계정이 필요한 상호작용은 통합 단계에서 별도로 설계한다.

## F. 묶음 구성과 인계 점검

| 검사 항목 | 이 묶음의 결과·한계 |
|---|---|
| 프로젝트 식별 | 최상위 폴더에 프로젝트·대화 주제·날짜 포함 |
| 필수 파일 | 요청한 MD 4개 생성 |
| 프로젝트명·기준일·버전 | 네 문서에 일관되게 명시 |
| 원본 수정 | 없음 |
| 기존 파일 첨부 | 없음. 대상 원본 확정과 전체 검토가 필요한 후보는 목록에만 기록 |
| 실제 이미지 | 없음. 추가 캡처 목록 제공 |
| 가상 예시 | 02 §6에 가상임을 표시, 실제 성공 사례와 분리 |
| 상대경로 | 제공된 MD 사이의 링크만 사용. 미확보 파일은 링크로 가장하지 않음 |
| ZIP | MD 4개와 단일 최상위 폴더. 빈 첨부 폴더 없음 |
| 실행하지 않은 작업 | 웹 구현, 서버 설치, GitHub push, SAP 변경, 실제 이미지 매칭 |
| 남은 핵심 검증 | 원본 식별, 시각 의미, 실제 이미지 연결, 담당자 검수, 정책 현재성 |

이 문서는 빠진 자료를 숨기지 않고 통합 단계에서 보완할 수 있게 만드는 인계 목록이다. 자료가 없는 것을 ‘프로젝트에 존재하지 않음’으로 바꾸어 해석하지 않는다.

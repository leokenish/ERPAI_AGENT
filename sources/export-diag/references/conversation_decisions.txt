프로젝트: SAP 패키지 추출·읽기 전용 진단 및 업무 AI 에이전트 구축
정리 기준일: 2026-10-08
범위: 현재 제공된 대화에서 사용자 요구를 선택 발췌. 전체 대화 원문 아님.
날짜: 아래 개별 과거 메시지의 날짜는 제공되지 않아 미확인. 순서는 현재 대화에 보이는 상대 순서.

[C01] 사용자 메시지: "새로운 패키지인 구매6번 패키지를 엑스포트 돌리는데 이런 메시지가 나왔어"
증거: 보이는 오류 화면은 duplicate/case-colliding archive path, BSP pop_cont_doc_down 경로.
의미: 출력 경로 충돌이 실제 장애였음. 전체 원본 ZIP은 이번에 확보하지 못함.

[C02] "bsp 페이지는 ... Properties, Layout, Event Handelr, Page Attributes, Type Definitions 5개 탭으로 구성되어있어."
요구: 숫자·원시 XML 중심 구조를 실제 탭과 이벤트 이름으로 변경. Properties와 Page Attributes 정보를 별도 XML로 보존.
주의: 사용자 철자 Event Handelr/OnDestory와 실제 표준 표기를 구별. 현행은 Event Handler/OnDestroy.

[C03] "추가 요청사항이야. 일단 기본 한국어로 전제로 하니 모든 결과물에 KO라는 수식은 다 제외 해줘."
요구: DDIC 명칭, Structures, 함수 탭 XML, 함수 소스 경로, BSP MIMEs 등 출력 구조 재구성.
후속 정정: "각각의 function 폴더들 ... 밑으로 한단계 더 내려가서 각각 Source code 폴더들을 다 만들고"
의미: Source code는 각 함수별 하위 폴더. 모든 언어 메타데이터 삭제 요구로 확장하지 않음.

[C04] "KO로 시도해보고 안되면 부분적으로 EN으로도 진행 할수 있게 해줄수 있어?"
동반 장애: Generated XML formatting changed field values, Raw XML round-trip changed values before formatting.
의미: 언어 fallback 요구와 XML 값 보존 장애는 원인을 구분해야 함.

[C05] "Active source not readable ... 그냥 추출 로그에서 제외해줘."
후속: MIME URL resolution failed 및 DDIC serialization은 적당한 로그, 외부클래스는 미지원·로그 제외 요구.
의미: 실패가 복구되었다는 뜻이 아니라 추출 범위/생략 정책을 결정한 것.

[C06] "맥북에서 코덱스 데스크톱으로 github에서 클론해서 가져와서 ZHR5 AI 에이전트 만드는건 성공했어."
증거 수준: 사용자 성공 보고. 현재 Mac 프로젝트나 저장소를 이번에 직접 검사하지 않음.

[C07] "실제 업무맥락을 파악하려면 관련 정책이나 사용자의견 같은것들이 있어야 할거 같은데"
후속 요구: 카카오톡, 매뉴얼, 규정·지침, 회의록, 양식을 MD·스킬·가이드로 구성.
의미: 코드는 구현 사실, 문서는 정책과 이유를 제공. 모델 재학습 완료로 해석하지 않음.

[C08] "업무 관련 검증 하네스 피드백 그리고 코드관련 검증 하네스 피드백"
후속: 업무 질의의 이상한 답변에 사용자 피드백을 주고 관련 MD와 하네스 파일을 고치는 방법·지속 지침 요청.
의미: 런타임 에러 없이도 업무 오답을 회귀 사례로 정의. 코드 자동 반영과 분리.

[C09] "github 통신은 보안 프로토콜로 바로 진행은 어렵겠네. 잠깐 보류하고"
증거: 보이는 화면에 Transport failure at RECEIVE / SAP error code 407 / ICM_HTTP_SSL_ERROR.
의미: SAP 직접 GitHub 통신 중단. HTTP 407이라고 확정할 증거는 아님.

[C10] "이게 ci/cd인거야?" / "github action이 검사 및 빌드 배포 자동화를 할수 있다는거는 ai인거야?"
범위: Actions, 러너, push/자동화, 로컬 Codex 피드백 연결의 개념 논의. 실제 workflow 운영 증거 없음.

[C11] "import는 부문은 제외하고 대신 import라기보다는 diag 즉 진단으로 명칭과 방향을 변경해줘."
이유: "아직 위험부담이 크고 검증이 제대로 되지 않았어."
후속: 활성화 실행·활성화 가능성 관련 표시 제거, 읽기와 활성 버전 확인 분리, 한국어 상태 사용.
현재 결정: 비교·읽기 전용 검증. 자동 활성화/저장/CTS를 현재 기능으로 설명하지 않음.

[C12] "원본/추출본/SAP ... baseline을 참조하는 원본이 무조건 중심 기준"
후속: 세 대비 상태 신규·누락·수정·변경없음, 추출본/SAP는 SAP 대비 추출본. 누락은 삭제가 아님.
후속 UI: A/B 별도 ALV, 첫 네 열 고정, 파일명에 상위 폴더, F3 목록 복귀, 간결한 헤더.

[C13] "ABAP문법 사전검사는 무조건 디폴트로 체크하는걸로 하고 체크박스를 빼줘."
추가: "신규/누락/수정만 조회" 기본 체크.
의미: 검사 절차 사용과 모든 객체 검사 성공은 구분.

[C14] "좋아 1번 2번 3번 4번 6번 너의 제안대로 개선해줘"
앞선 질문의 주제: 함수-Include 연결, 함수 속성/공통 프로그램 속성 구분, 확인 실패, 검사 미수행, JSON 다운로드.
이어서 "9128줄에 에러가 나. 비슷한 에러가 또 있을지도 확인해줘"
확보한 원본 화면: images/diag_0_4_4_csequence_error.png
현재 0.4.5 코드에서 날짜·시각 STRING 변환 확인. SAP 재활성화 성공은 미확인.

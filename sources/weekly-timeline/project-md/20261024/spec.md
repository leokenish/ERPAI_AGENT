- 프로젝트명: KBS WORK TIME LINE
- 문서 역할: 현재 요구사항, 데이터·화면 계약, 수용 기준과 미합의 쟁점
- 버전: v0.1 — 프로젝트 전용 신규 문서. 기존 동명 `0.2-template`은 공통 빈 양식으로 보존함.
- 작성·수정일: 2026-10-23 (Asia/Seoul)
- 문서 상태: 이번에 생성한 사용자 검토용 초안. 프로젝트 출처 미반영. 확정 요구와 AI 제안은 아래에서 별도로 구분함.
- 확인한 자료: 현재 사용자 대화, 관련 대화 검색 발췌, 기존 양식과 프로젝트 통찰 예시, UI 2.3.0/스키마 2.0.0 배포물·핵심 소스·설명서·검증 기록·카드 및 이벤트 표본. 정확한 출처는 `plan.md`의 「2. 기준 자료와 근거」.

## 1. 요구사항을 읽는 법

- **확정**: 사용자가 직접 요청·선택한 방향. 구현이 없거나 검증이 부족해도 요구는 유효하다.
- **구현 선택**: 현재 코드에 존재하는 구체 방식·수치. 사용자가 그 방식까지 승인했다는 뜻은 아니다.
- **AI 제안**: 다음 검증·개선을 위한 제안. 확정 요구로 승격하지 않는다.
- **미해결**: 사용자 의도나 운영 정책을 더 확인해야 하는 사항.

요구사항 표의 수용 기준은 사용자 요청을 관찰 가능한 동작으로 정리한 것이다. 새로 제안한 시험·품질 기준은 「7. 추가 검증 기준」에 별도 표시한다. 구현·시험 상태의 원장은 `plan.md`다.

## 2. 주요 사용 시나리오

1. 사용자가 배포 ZIP 전체를 풀고 `시작하기.html` 또는 `index.html`을 연다. 현재 로컬 방식에서는 `manifest.json`이 들어 있는 자료 루트 폴더를 선택한다.
2. 연도를 선택하면 그해 보고서에 수록된 조직 목록이 나온다. 조직 선택 후에는 선택 연도에만 갇히지 않고 해당 조직의 전체 보유 기간을 가로로 탐색한다.
3. 주차 줄기의 점으로 그 주에 보고된 업무를 보고, 개별 가지로 같은 업무의 이어짐과 미언급 후 복귀를 살핀다.
4. 가지를 클릭하면 원문 카드, 실적/계획 구분, 원문 날짜·참고 해석값, 명시 담당 정보, 출처와 연결 이유를 확인한다.
5. 하단 전체 기간 미니맵으로 과거·최근 구간을 이동한다. 노란 이벤트를 누르면 선별 근거와 관련 원문으로 이동한다.
6. 운영자가 새 주간 HML을 추가하고 갱신 스크립트를 실행한 뒤 자료를 다시 연다. 과거 원문을 임의 수정하지 않는다.

## 4. 현재 데이터·파일 계약

### 4.1 환경과 입력

- 현재 배포: `ui_version=2.3.0`, `schema_version=2.0.0`, `dataset_id=kbs-weekly-archive`.
- 원천: 시작일을 포함한 `공사주간업무_YYYYMMDD.hml`. 현재 파서는 HWPML의 조직/실적/계획 표 구조를 전제로 한다. 일반 HWP 바이너리 전체 형식 지원을 주장하지 않는다.
- 보고 주차는 파일명 기준. `actual`은 금주, `plan`은 다음 주를 `target_week`로 보존한다. 표제 날짜 충돌은 진단 대상으로 남기며 원문을 고치지 않는다.
- 현재 실자료: 617개 HML, 2014-12-29–2026-10-19. 마지막 계획 대상 주는 2026-10-26. 2014년은 마지막 한 주만 포함한다.
- 61개는 원문 조직 이름의 수다. 국 외 실·부·단·총국·계열사를 포함하며 회사의 공식 현재 조직 수를 뜻하지 않는다.
- 조회는 로컬 HTML/파일 선택 또는 기존 정적 웹 서버 방식. README의 안내 브라우저는 Chrome/Edge이며 모든 브라우저·버전에서 검증한 것은 아니다.
- 갱신은 Python 3.10 이상 표준 라이브러리 스크립트. 현재 조회에는 Python, DB, 외부 API, CDN이 필요하지 않다.

### 4.2 파일 구조와 역할

아래 경로는 ZIP 내부 `KBS_업무타임라인/` 기준이며 실제 파일 예시다. 조직별 월 JSONL은 현재 구현 선택으로, 사용자에게 파일 구조를 시연한 결과물의 기준선이다.

### 4.3 업무카드의 핵심 필드

| 필드 | 유지할 의미 |
| --- | --- |
| `observation_id` | 원문 위치에 근거한 관측 카드 ID |
| `org_id`, `work_id` | 원문 조직 이름, 연결 업무 참조 |
| `report_week`, `target_week`, `section` | 보고 시점, 실적/계획 대상 시점, `actual`/`plan` |
| `title_raw`, `context_raw`, `raw_text` | 제목·분류·원문 문단 본문. 표시 제목 처리와 원문 본문을 혼동하지 않음 |
| `assignees` | 명시 필드에서 추출한 정보. 없으면 빈 배열 |
| `period.raw_mentions` | 읽어 낸 날짜 표현과 해석 근거. 원문 전체는 `raw_text`로 재확인 |
| `period.display_start`, `display_end`, `basis`, `approximate` | 표시 참고값, 실제 확정 기간이 아님 |
| `source` | 원본 파일·셀·표·행·열·문단 번호 |
| `extraction`, `link` | 추출 방법·검토 상태·연결 판단 근거 |

카드 참조의 JSONL 행 번호와 출처 문단 번호는 1부터 시작한다. 이 참조 계약과 `raw_text`의 추적 가능성을 UI 수정 때문에 바꾸지 않는다.

## 5. 현재 구현 선택과 해석 제한

### 5.1 조직·업무 연결

`navigation=['year','org_id']`, `key_order=['org_id','work_id','observation_id']`다. 최초의 연도-부서-업무-담당자 구상과 이후 국·업무 우선 결정을 탐색과 식별로 분리한 현재 구현이다.

같은 이름의 조직은 같은 키로 묶고 다른 이름의 조직 승계는 추정하지 않는다. 조직 이름만으로 동일 조직이 계속 존속했다고 확정하지 않는다. 현재 61개 이름은 그대로 폴더에 쓰며, 향후 파일시스템 금지 문자가 있으면 원래 이름과 안전한 폴더명 매핑이 필요하다.

업무 연결은 다음 규칙을 사용한다. **이는 전 자료를 언어모델이 맥락 판단한 결과가 아니다.**

| 방법 | 현재 코드 기준 |
| --- | --- |
| `new_work` | 연결 근거가 없어 새 업무 생성 |
| `normalized_title` | 같은 조직·분류, 공백·기호·`(계속)` 제거 후 일치, 마지막 관측 후 84일 이내 |
| `context_inference` | 21일 이내, 대상어 2개 이상, 제목 유사도 ≥0.82, 본문 어휘 겹침 ≥0.50, 차순위와 차 ≥0.10, 숫자·분류 충돌 없음 |
| `reviewed_context` | 2026-09-14–2026-10-12 표본에서 만든 제한된 맥락 규칙 |

이 수치는 사용자 수용 기준이 아니다. 표본 검토 표시는 사용자 승인 또는 업무 소관자 검수를 뜻하지 않는다. 불확실 후보는 별도 업무로 남긴다. 업무 요약의 최초 `link_method`만 보지 말고 개별 카드의 `link`를 함께 읽는다.

### 5.2 주차·가지·날짜

- 주차는 월요일–일요일, 표시 월은 목요일이 속한 월이다. 정확한 월 주차 계산 방식은 구현 선택으로 사용자 별도 승인 기록이 없다.
- 현재 가지는 **다음 유효한 해당 조직 보고서**에 업무가 없을 때 복귀한다. 조직 보고 자체가 빠진 주는 공백으로 둔다. 사용자의 “다음주 미언급”을 결측 보고와 구별한 방식으로, 결측 처리의 명시적 합의는 남아 있다.
- `unmentioned_in_next_available_report`는 미언급 복귀, `latest_report_boundary`와 `organization_data_boundary`는 자료 경계다. 어느 것도 실제 완료 인증이 아니다.
- 같은 업무가 재등장해도 미언급 후에는 새 `segment`가 생길 수 있다.
- 날짜의 초·중·하순·말은 참고 날짜로 배치하고, 읽지 못하면 대상 주간을 사용한다. 현재 가지의 수명은 `period`가 아니라 보고 언급으로 결정된다.
- 현재 담당 추출은 담당/담당자/PD/연출/기자 등 명시 필드 중심이다. 본문에 인명이 있어도 `assignees=[]`일 수 있다. “추출되지 않음”을 “원문에 담당자가 없음”으로 표시해서는 안 된다.

### 5.3 UI·이벤트·폰트

- 데스크톱 그래프 `clamp(620px,66vh,900px)`, 최소 620px, 모바일 600px. 현재 구간의 레인을 재사용하며 많은 업무는 세로 스크롤한다. 수치는 높이를 더 늘리라는 요청의 구현값이지 사용자 확정 픽셀값이 아니다.
- 가지 레이어의 좌우 최대 64px에 페이드 적용. 메인 줄기·주차·이벤트는 선명하게 유지. 실제 시간축 양끝의 바깥 방향 및 동작 줄이기 설정에서는 효과 생략.
- 전체 기간 미니맵, 4/8/12주 확대, 주차 목록, 업무 상세, 보고 연도 선택을 유지한다. 검색은 선택 조직의 업무명·별칭·명시 담당 정보이며 전사 본문 전문 검색이 아니다.
- 파일 보기 목록은 최대 500개, JSONL 미리보기는 첫 5개 레코드다. 다운로드는 전체 파일이다.
- 이벤트는 `card_context_rules_v1` 규칙 선별이다. 현재 109건(스포츠 20, 정책·법률 67, 국가 중대사 22). 전 사건의 의미 분석·외부 사실 확인 결과가 아니다.
- 개막·개회 표현 옆 원문 날짜를 쓰는 `source_opening_date`, 그 외 카드 대상 주차를 쓰는 `source_target_week`를 구분한다. `reported`/`planned`는 카드 분류이며 사건의 진위·완료 상태가 아니다.
- 노란 표식은 회사 공통 이벤트이며 근거 상세에서 원문 카드로 이동한다. 한 주의 다수 이벤트는 더보기로 펼친다. 근거 일부 최대 12개 표시와 전체 `evidence_count`는 다를 수 있다.
- S-Core Dream 4/5/6/7 원본 OTF를 400/500/600/700으로 사용하고 같은 바이트를 CSS에 내장한다. 폰트 출처 기록·라이선스 이미지를 `assets/fonts`에 보존한다. 실제 브라우저에서의 모든 글꼴 적용·줄바꿈 검증은 남아 있다.

### 5.4 주간 갱신

`scripts/update.py`는 기존 원본과 새 HML을 임시 폴더에서 전체 재계산·검증한 후 변경 파일만 교체하고 `manifest.json`을 마지막에 게시한다. 같은 이름·같은 내용은 중복 추가하지 않고, 같은 이름·다른 내용은 오류로 중단한다.

순수 증분 계산, 자동 예약 실행, 다중 작성자 동시 갱신, 전체 디렉터리 단위 트랜잭션·자동 롤백을 구현했다고 보지 않는다. 늦게 들어온 과거 원본이나 연결 규칙 변경은 기존 연결을 바꿀 수 있으므로 백업과 비교가 필요하다.

## 6. 포함·제외·호환 경계

현재 범위는 원문 보관부터 카드·연결·시간축·주간 갱신·ZIP 전달까지다. DB 설치, 대량 카드별 MD, 원문 오류의 임의 보정은 선택하지 않은 방향이다. AI 질의응답, 조직 승계 추론, 전사 전문 검색, 실제 완료 판정은 별도 미합의 확장이다. 권한은 미구현 요구이지 명시적 제외가 아니다.

UI만 수정할 때 HML, 원문 셀, 카드, 업무 연결, 조직 인덱스 등 기존 데이터를 보존해야 한다. UI 2.2·2.3에서는 이를 해시 비교한 기록이 있다. 작은 UI 업데이트 ZIP은 기존 617개 원본 데이터용이며 단독 실행물이 아니다. 이미 새 주간 파일을 추가한 자료에 과거 manifest를 덮어쓰면 안 된다. 전체 ZIP을 별도 폴더에 풀고 새 원본을 다시 추가하는 기존 가이드를 따른다.

## 7. 추가 검증 기준 — AI 제안

아래는 아직 사용자와 합의한 품질 수치가 아니라 다음 수용 검토를 위한 제안이다.

1. 실제 사용자 브라우저에서 밀집 주간의 상·하단 가지, 상세 열기, 연도 변경, 미니맵, 좌우 페이드, S-Core Dream 적용을 함께 확인하고 화면 조건을 기록한다.
2. 업무 연결은 표현 변경·별개 범위·상시 반복·재등장·미언급 사례를 소관자가 표본 검토한다. 허용 오연결률·표본 수는 아직 결정하지 않는다.
3. 날짜 표현·혼합 업무·담당자 추출의 오인식은 원문을 바꾸지 않고 파생값·분할 기준에서 검토한다. 이미 발견한 재현 표본은 `plan.md` 「5」에 있다.
4. 정책 이벤트에서 ‘통과 촉구/결의’와 ‘통과 사실/시행 대응’을 구분하는 표본 검토를 추가한다. 원문을 외부 사실로 보정하는 제안은 아니다.
5. 운영용 사본에 실제 새 주간 HML을 추가하기 전 별도 복사본에서 기존 원문·참조·이전 카드 유지와 새 가지 경계를 확인한다.

## 주요 변경 요약

- REQ-001–014와 수용 경계를 정리하고 실행 상태는 `plan.md`에 연결했다.

- 규칙 기반 연결·이벤트, 참고 날짜, 담당 추출 범위, 권한 미구현을 명시했다.

## 미확인 사항

실제 브라우저 수용, 맥락 연결 정확성, 카드 분할·날짜 추출 오류 범위, 결측 주차 처리의 사용자 합의, 월 주차 계산 방식, 조직 개편 대응, 접근권한 정책이 남아 있다. 새 HML의 표 구조 변경과 향후 원본 교체 정책도 미확정이다. 상세 증상·우선순위는 `plan.md` 「5–7」을 따른다.

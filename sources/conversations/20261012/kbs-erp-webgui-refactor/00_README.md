대화 추출 경계는 `wg-m050`의 첫 교육대화 추출 요청까지다. 이 추출 작업 중 반복 제출된 동일 요청, 진행 안내와 “결과물 나왔어?” 상태 문의는 **추출 작업 관리 대화**이므로 이 판의 프로젝트 학습 대화에 재귀적으로 추가하지 않았다. 이후 보완판에서는 별도 추출 이력으로 관리할 수 있다. 과거 프로젝트 발화를 용량 때문에 잘라내지는 않았다.

`wg-m010` 등의 ID는 이번에 부여한 자체 ID다. 과거 전달 메시지의 `msg_idx`를 추적하기 쉽게 사용했지만 실제 플랫폼 ID는 아니다. `sequence`는 확보한 발화 사이의 상대 순서이며, 보이지 않는 중간 발화가 없다는 뜻이 아니다.

## 3. 실제 확인한 자료와 이번에 달라진 확보 상태

이전 교육 ZIP을 다시 확보하여 26개 내부 파일을 그대로 풀었다. Chrome v3 보고서도 별도로 다시 확보해 동일성을 대조했다. 최종 로컬 점검에서 초기 WEBGUI·스크롤 패치의 8개 독립 ZIP/보고서와 SYSTEMGUI·커서 패치 ZIP 5개를 추가 확보했다. 이전 요약의 “원본 미확보”를 현재 상태로 반복하지 않는다. 기존 요약 파일은 역사적 원문으로 수정 없이 보존했다.

Network 이미지 13개를 실제로 열어 확인했다. 업무 문서 POST, HTML 응답, 캐시, Timing의 수치는 [이미지 판독 기록](assets/source_notes/image_review.md)에 적었다. Fetch/XHR 필터 화면 1개는 원본 그대로 포함했다. 나머지 이미지와 콘솔 이미지는 식별자를 노출하므로 배포에서 제외하고 안전한 문자 판독을 제공한다. 새 가짜 화면을 만들지 않았다.

100개 소스는 v3 Full·Original·Rollback 및 Evidence 안에서 확보했다. 이번에는 파일 내용·구성·해시와 기존 검증 기록을 확인한 것이며, 모든 함수를 재감사하거나 실제 ERP 회귀를 실행한 것이 아니다. Drive 목록은 **2026-10-08 조회 결과**이며 10-12에 새로 동기화한 결과가 아니다.

최종 확보 통합 기준은 **Chrome v3(보고서 2026-09-14)**다. Full은 100개 전체 파일, Apply는 직전 기준본 대비 33개, Rollback은 직전 기준본 100개, Original은 제공 원본 100개다. Rollback은 실제 운영 서버에서 받은 백업이 아니다. 현재 운영 배포 버전과 v3 적용 성공은 미확인이다.

## 6. 미확보·제외와 마스킹

- 초기 지침 전체, 전달된 `msg_idx 10` 이전 전체 원문, SYSTEMGUI 1차·커서 수정·v3 진행/최종 답변 본문은 미확보다. 보고서가 있다고 가짜 AI 발화를 만들지 않았다.
- 추가 구조 개선 요청의 실제 답변 본문은 미확보다. 이전 교육 MD의 제안 요약만 참고한다.
- 실제 오류 시점의 업무 Response HTML, `gui_ts.js` 응답 본문, 서버 생성 스크롤 콜백, `ITSSM_unload` 구현, HAR·Performance trace는 미확보다.
- 실제 Chrome/ERP의 v3 배치·IME·저장·세션·요청 수 검증과 운영 승인 기록은 없다.
- Network 이미지 12개와 콘솔 PNG는 실제 열람했지만 원본 배포 제외다. JSON의 `unavailable`은 이 두 상황을 description에서 구분한다.
- `wg-m034`의 세션 식별자 조각은 명시적으로 마스킹했고 `redacted=true`, `content_type=excerpt`로 표시했다. 검색 요약의 내부 호스트·트랜잭션도 대체 표시했다.
- 첨부의 원 플랫폼 순번을 확인할 수 없어 이미지와 발화는 내용 기반으로 연결했다. 이미지 순번을 플랫폼 메타데이터로 확정하지 않는다.

추가 검색에서 얻은 요약은 [별도 보충 근거](assets/source_notes/retrieved_context_summary.md)에 둔다. 다른 프로젝트의 GitHub·MCP·DIAG 제품·Obsidian·Telegram 구현을 이 프로젝트에서 완료했다고 기록하지 않았다. `diag` 노드 연결은 이 사례의 비교·검증 학습 의미이며 특정 DIAG 시스템 도입 증거가 아니다.

## 7. 통합과 보완 요청

포털은 말풍선에 `content_type`·시각 미확인·마스킹 표식을 표시하고, 교육 해설과 재작성 프롬프트를 별도 영역으로 보여주는 것이 좋다. 미제공 첨부에는 다운로드 버튼 대신 이유를 표시한다. 실패한 가설을 삭제하지 않고 후속 정정과 연결한다.

보완 우선순위는 ① 생략된 원문 export ② 식별자를 제거한 Network/콘솔 캡처 ③ 실제 업무 HTML·오류 JS 응답 ④ 운영 배포 버전과 테스트 결과다. 이 자료를 받기 전에도 원본 보존·증거 구분·패키지 비교 실습은 가능하다. 실제 ERP 적용·통신 변경 실습에는 승인된 테스트 환경과 데이터가 필요하다.

이번 작업은 교육 자료 추출이다. 소스 재수정, 운영 적용, 웹사이트 구현, 서버 설치, GitHub push는 수행하지 않았다.

## 1. 이번 자료의 목적

KBS 팀원이 최종 구성만 외우는 대신, 실제 사용자가 AI에게 무엇을 요청하고 잘못된 전제를 어떻게 바로잡았는지 따라가도록 만든다. 실제 발화는 conversation-data.json의 messages, 해설·현재 실습은 episodes와 02_LEARNING_GUIDE.md에 따로 둔다.

이 묶음은 교육자료 추출 결과다. 웹사이트 구현·서버 설치·GitHub push·ERP 운영 변경은 하지 않았다.

- 범위: 2026-10-03 01:18:11 KST 최초 협업 질문부터 2026-10-12 15:07:03 KST 현재 추출 요청까지.
- 원문 전사 32개, excerpt/summary 역할의 채팅 발화 0개. 교육 해설은 별도 필드다.
- 10월8일 추출 요청·진행 안내·결과와 이번 10월12일 긴 요청도 생략하지 않았다.
- assistant의 실제 발화 시각은 알 수 없어 모두 null. 사용자 시각을 복사하거나 응답 시간을 만들어 넣지 않았다.
- eac-m001 등은 자체 발화 ID이며 플랫폼 ID가 아니다.
- 현재 추출 요청 이후의 진행 안내·최종 응답은 추출 경계 밖이다. 자기 결과를 과거 대화로 추가하지 않는다.
- system/developer 지시, 환경 메타데이터, 개인 기억 요약은 교육 대화가 아니므로 messages에서 제외했다.

원문의 오타·잘못된 설명·당시 예시는 그대로 두었다. Markdown 줄바꿈과 표시 텍스트를 전사한 것이며 플랫폼 내부 원본 바이트와 동일하다는 뜻은 아니다. 긴 도구 호출 코드와 실행 응답은 사용자/assistant 말풍선으로 바꾸지 않았고, 실물 코드와 도구 증거 발췌를 assets에 연결했다.

## 4. 원본과 이전 요약의 관계

이전 10월8일 ZIP은 이번에 재확보했다. 직접 생성된 원본과 다른 프로젝트 폴더의 업로드 사본은 SHA-256이 동일했다. 사본을 새 버전으로 등록하지 않고 원본 하나만 포함한다. 이전 묶음의 내부 13개 파일은 당시 검사한 파일과 바이트 일치함을 재확인했다.

기존 요약 MD는 보조 참고자료다. 이번 messages의 근거는 현재 직접 보이는 발화이며, MD 내용을 사용자나 AI 발화처럼 복원하지 않았다. 원본 소스·이전 요약 문서는 수정하지 않았다.

## 6. 원문·해설·검증의 UI 표시 규칙

1. messages는 sequence 순으로 렌더링하고 role과 content_type을 표시한다.
2. 원문을 자동 교정하지 않는다. m003의 전체 폴더 제안, m010의 수동 요청, m012의 자료 접근 가정은 후속 정정과 함께 보여준다.
3. episodes.commentary_markdown은 ‘교육 해설’ 패널, exercise_markdown은 ‘교육용 재작성 프롬프트/실습’ 패널로 표시한다.
4. 기존 원문에 있는 sandbox 링크는 원문 그대로 보존했다. 다운로드 버튼은 asset_ids를 이용해 현재 ZIP 상대경로를 연결한다.
5. 원문에는 당시 `genui` 인용 마커가 있다. 역사적 표시를 유지했고 최신 출처로 새 검증한 것이 아니다. 공식 주소 대응은 assets/tool-evidence.md 참조.
6. 인라인 Mermaid/HTML은 당시 원문 그대로이며 제품 화면 캡처가 아니다. 포털 렌더러가 지원하지 않으면 코드 보기로 표시한다.
7. AI가 ‘가능하다/만들었다’고 말한 것과 실제 파일·테스트·사용자 운영 보고를 구분한다. 사용자 측 실행 성공 보고는 이 범위에 없다.
8. map_nodes의 lookup/erp-api/telegram/diag는 사용하지 않았다. 중앙 자문 MCP를 ERP 조회 MCP 또는 DIAG 프로그램으로 분류하지 않는다.

## 7. 마스킹과 보존 정책

확인한 발화에는 실제 인증값·비밀번호나 교육에 불필요한 개인 식별정보가 없어 redacted=false다. 개인 기억·환경 메타데이터를 채팅 본문으로 가져오지 않았다. 원본 test.mjs의 토큰 모양 문자열은 테스트용 더미이며 실제 비밀이 아니다. 신규 교육 예시는 대체값 또는 로컬 생성 방식만 사용한다. 원문 오타 교정을 마스킹으로 숨기지 않았다.

## 8. 제출 검증과 남은 확인

JSON 파싱, ID 중복, episode/message/asset 교차 참조, included 경로, unavailable의 null 경로, 발화 순서·시각, 원 ZIP/추출 파일 바이트 일치, 신규 MD 상대경로를 확인한다. 검사 결과는 ZIP 생성 직전 수행하고 별도 validation-report.json에 기록한다.

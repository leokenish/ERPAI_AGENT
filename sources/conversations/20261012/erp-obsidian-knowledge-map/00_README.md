# 00. 자료 안내와 확보 범위

프로젝트: **옵시디언을 활용한 ERP 업무 관계정립**

대화 주제: 기존 ERP 업무 지식·스킬·소스에 관계 문서를 추가하고 Obsidian으로 탐색하는 방안, 이후 교육자료 추출.

## 1. 이번 자료가 담고 있는 것

**현재 확인 가능한 대화의 일부 범위를 원문 형태로 보존한 패키지다. 프로젝트 전체 대화 내보내기가 아니다.** 이 범위 안에서는 긴 요구서와 AI 진행 안내를 포함한 자연어 발화 25개를 생략하지 않고 순서대로 수록했다. 교육 핵심은 `episodes`로 따로 묶었고 원문 순서는 유지했다.

사용자가 실제로 했던 질문은 자동 연결 가능 여부 → 기존 자산 설명 → 지도와 AI의 역할 → 효율·속도 → 도입 부담 → 적용 순서 → 교육자료 추출로 구체화됐다. Mac에서 실제 관계 문서를 생성·사용한 기록은 확보하지 못했다. 실제 결과물로 확인한 것은 이전 MD 4개와 ZIP, 그리고 이번 대화 데이터·교육 문서다.

## 2. 확보 자료와 원본의 관계

2026-10-08 제공된 `ERP_Obsidian_교육자료_20261008.zip`을 다시 확보하고 내부 MD 4개를 읽었다. 원래 파일을 수정하지 않고 바이트 그대로 복사했다. 이전 ZIP의 SHA-256은 `a4890a5afc97302131c96be64904b2102327bc2d6e1525741a7c94d7326ba762`다. 개별 파일 해시는 [현재 검증 결과](validation-report.json)에 있다.

이전 MD는 당시 요약·교육 초안이다. 그 안의 `C01` 등 인용, `P01` 검색 요약, 기술 문서 설명을 실제 발화로 복원하지 않았다. 이번 실제 대화 근거는 `obs-m001`~`obs-m025`이며 이전 자체 출처 ID와 별개다. 이전 자료의 날짜·최신 판단은 당시 기준으로 보존했다. 이번 추출에서 제품 문서나 사용자 Mac 원본의 최신성을 다시 확인했다는 뜻이 아니다.

`assets/evidence/20261008_validation_excerpt.json`은 실제 도구 결과의 **발췌**를 이번에 파일로 옮긴 것이다. 당시 첨부된 원본 파일이 아니므로 `original_filename=null`이다. 과거의 검사 결과와 이번 원본 해시 계산을 필드로 나눴다.

첨부 중 이전 ZIP과 풀어 놓은 MD 4개는 의도적으로 중복했다. ZIP은 전달 원본 보존용, MD는 교육 화면에서 바로 참조하기 위한 것이다. 용량 때문에 제외한 확보 자료는 없다. 원본을 확보하지 못한 자료만 미포함으로 표시했다.

## 4. 포털 데이터 사용 규칙

`schema_version`은 요청된 **1.0**이다. 대화 `threads`, 학습 단계 `episodes`, 자산 `assets`를 분리했다. 파일 분할은 하지 않았다.

- `sequence`는 이 대화방에서 보이는 자연어 발화 순서다. 자체 ID는 `obs-mNNN`이고 플랫폼 ID가 아니다. 시각이 `null`이어도 sequence로 순서를 유지한다.
- `content_type=verbatim`은 확인된 발화 본문을 전사했다는 뜻이다. AI가 그 안에서 설명한 사실·예시가 검증됐다는 뜻은 아니다. 실제 발화 자체가 잘못된 설명을 포함해도 원문을 고치지 않는다.
- 원문 속 설명용 표·코드·프롬프트는 당시 발화의 일부로 보존했다. 실행한 명령 로그나 실제 생성 파일로 간주하지 않는다. 큰 실행 코드·로그 첨부를 분리한 사례는 이번 범위에 없다.
- `commentary_markdown`과 학습 MD는 새 해설이며 말풍선 원문과 구분해 표시한다. `exercise_markdown`의 프롬프트는 **교육용 재작성 프롬프트**다.
- `asset_ids`는 이번 추출에서 붙인 연결이다. 모든 파일이 당시 해당 말풍선에 직접 업로드됐다는 뜻은 아니다. 특히 미확보 5종은 사용자 언급 자산이다.
- `assets[].path`는 이 ZIP의 고유 최상위 프로젝트 폴더를 기준으로 한 상대경로다. 미확보 자산은 `path=null`, `availability=unavailable`이며 클릭 가능한 다운로드를 만들지 않는다.
- 원문에 있는 옛 `sandbox:` 링크와 `genui` 인용 토큰은 수정하지 않았다. 포털에서는 해당 시점의 표시 흔적으로 취급하고, 다운로드는 현재 `asset_ids`와 `path`로 연결한다. 원문 속 링크를 새 URL로 조용히 치환하지 않는다.
- 태그는 실제 연결 범위인 `knowledge`, `codex`, `maps`, `export`, `feedback`, `portal`만 사용한다. 일반 파일 검사에 `diag` 태그를 붙이지 않았다. GitHub·MCP·Telegram·ERP API는 이 프로젝트의 실제 구현 사례가 아니다.

개인정보·인증정보: 수록한 대화와 확보 첨부에서 교육에 불필요한 개인 식별정보·인증값을 포함하지 않도록 확인했다. 확인된 발화에 추가 마스킹이 필요한 값은 없어 `redacted=false`다. 예시의 날짜·금액 대체값은 당시 원문에 있던 예시이며 이번 마스킹은 아니다. 이전 작업 공간의 산출물 경로는 출처 연결을 위해 보존했다.

## 6. 완료 상태와 사용상의 한계

이번 완료 범위는 MD·JSON·첨부 패키지 생성과 구조 검증이다. 검사 대상은 JSON 문법, ID·참조, 순서, 자산 경로, MD 상대경로, 원본 바이트, ZIP 무결성이다. 사용자 Mac 설치, 실제 업무 관계의 정확성, Obsidian 화면 동작, Codex의 실제 파일 선택, 운영 ERP·SAP 동작, 응답 성능은 검증하지 않았다.

실패·수정 과정으로 교육에 활용하기 좋은 것은 **자동 연결에 대한 기대 조정, 효율에서 실제 처리 속도로 질문 구체화, “도입 손해 없음”의 조건화, 최상위 폴더 범위 한정**이다. 실제 오류 메시지·실패한 프로그램 실행·수정 후 재시험 성공 사례는 없으므로 만들어 넣지 않았다. 이번 추출은 웹사이트 구현, 서버 설치, GitHub push를 포함하지 않는다.

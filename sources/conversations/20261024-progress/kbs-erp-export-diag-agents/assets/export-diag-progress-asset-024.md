## 1. 현재 상태를 먼저 읽기

1. 최신 확인 소스는 **Export 0.4.1 / DIAG 0.7.1**이다. 패키지 모드를 유지하면서 BSP 한 앱 추출·진단을 추가했고, BSP ZIP을 앱 폴더 하나로 바꾸는 수정까지 구현되어 있다.
2. 기존 릴리스의 로컬 검증 보고는 실행 가능한 ABAP FORM 시험 267사례, 소스 통합 조건 75개, 두 REPORT의 v700 파서 오류 0을 기록한다. 이번에는 보고서와 소스 해시를 확인했으며 시험을 다시 실행하지 않았다.
3. 사용자 확인된 BSP 반영 성공은 **DIAG 0.6.11의 기존 I 버전 재사용 후 단일 페이지 활성화**다. 성공 화면의 `ACTIVATED_VERIFIED / REUSED_VERIFIED / VERIFIED / RESUME_VERIFIED`와 사용자의 SE80 정상 반영 보고가 근거다. 새 저장 경로 전체나 0.7.1의 성공으로 확장하지 않는다.
4. 이번 자료 확인에서 **0.4.1 표기 실물 ZIP**을 추가로 확보했다. 최상위 `ZWEB_COMMON` 하나, payload 982개와 각 baseline, Layout 75개·MIME 콘텐츠 659개를 확인했다. 연관 프로젝트에 보관된 자료를 출력 형식 확인에만 사용한 것이며, 생성 과정을 직접 관찰하거나 DIAG 반영까지 확인한 것은 아니다.
5. 따라서 다음 시작점은 코드를 다시 만드는 일이 아니라 **현재 SAP에 적용된 DIAG 버전과 새 형식 ZIP의 무수정 비교 결과를 확인하는 것**이다. 그 뒤 필요한 경우 작은 웹자산 변경과 원복을 확인한다.
6. 초기 목적의 ZHR5 업무 지식·소스 연결도 유지한다. 최근 웹자산 릴리스와 별도 진행 축이며, 현행 정책·코드 연결·답변 운영 완료는 미확인이다.

현재 진행 중인 코드 수정은 없다. 이번 작업의 산출물은 실제 내용을 채운 네 Markdown 검토 초안이다. SAP·GitHub·프로젝트 설정 또는 출처 목록을 갱신한 작업이 아니다.

| SAP에서 GitHub 직접 조회 | 초기 이력 U039~U045에 RECEIVE/`ICM_HTTP_SSL_ERROR` 후 보류 기록. 현재 연결을 복원하거나 운영 중이라고 간주하지 않음 |
| 앱 전체 미활성 일괄 차단 | 사용자가 다른 페이지 작업까지 막는 점에 이의 제기. 선택 페이지·공통 정의의 실제 경고/충돌 확인으로 좁힘. 모든 경고 무시가 아님 |
| BSP 폴더가 소유 패키지별로 분리됨 | 0.4.0 ZIP의 ZBUDGET/ZHR1/ZMOBILE 폴더는 메타데이터/README. 그 소유의 MIME 5개는 앱 URL 하위. 파일 삭제 대신 단일 앱 폴더와 통합 메타데이터로 수정 |
| 새 형식 확인 상태 | 0.4.1 배포 당시 보고는 로컬 fixture까지였다. 이번 E09 실물로 새 ZIP 형식 확인 범위가 넓어짐. DIAG 실서버 성공은 여전히 별도 |

### 4.2 BSP 오류 이력 — 재발 시 필요한 만큼만

다음은 과거 증상이다. 현재 0.7.1에서 모두 재발 중이라는 뜻이 아니다. 최신 구현의 상세 이력은 E04의 관련 절과 현재 소스에서 확인한다.

| 증상·발생 조건 | 대응 방향·결과 | 재발 시 확인할 근거 |
|---|---|---|
| `SO2_VERSION is unknown` | 선택적 DDIC 별칭 대신 호환되는 로컬 타입으로 수정 | 실제 설치 소스 버전·줄 번호·시스템 타입 |
| BSP Properties 키·언어·페이지 유형 실패 | 기존 페이지의 실제 키/언어/유형과 API 계약 확인 | Properties 원본·현재 값과 페이지 키 |
| 행 길이/형 변환 손실, `__DYNAMICALLY_CREATED_TYPE__ is generic` | 실제 API 행 타입과 무손실 변환을 확인하는 방향으로 수정 | P_CONTENT 행 타입·길이와 최초 차이 |
| `P_CONTENT` 기대 258/조회 257, 첫 차이 1행 2열 `[?]`/`[%]`, 선두 XML 선언행 확인 불가 | 독립 XML 선언행 가정만으로 해결되지 않음. E04는 `ZHR5.zip`의 .htm이 SO2 XML임을 확인하고 표현 변환을 추가했다고 기록 | 업로드/원본 Layout 실제 형식, `wa_verify_detail`; 이번 문서화에서는 ZHR5.zip 재분석 안 함 |
| 저장된 I/활성 A Layout이 업로드와 다름 | API 표현·저장 후 재조회·I/A 검증을 분리 | 실패 단계, 기대/조회 첫 차이, JSON/실행 로그 |
| I 버전 조회와 WAPP 미활성 점검 불일치 | 내용 확인과 미활성 목록/프로토콜 해석을 분리 | WAPP/WAPD 원문과 대상 객체 키 |
| `CX_SY_DYN_CALL_ILLEGAL_TYPE` | 활성화 체크리스트 수신 타입·동적 API 계약/예외 처리 수정 | `ACTIVATION_EXCEPTION`, API_SIGNATURE, 실제 인터페이스 |
| WAPP/WAPD 경고 반복 후 보류 | 경고 분류와 기존 I 재개 조건을 보완. 이후 0.6.11에서 재사용 후 활성화/SE80 반영 확인 | `wa_inactive_detail`, 재개 근거와 현재 I 작성자/내용 |
| Workbench 작업 번호 요구 | 사용자가 하위 CTS 번호 입력 후 진행 | 상위 요청/하위 작업 구분, 소유자·수정 가능 상태 |

현재 실제로 남은 핵심 불확실성은 최신 DIAG 실행과 각 저장 경로의 검증 범위다. 오래된 실패 메시지만 보고 이미 성공한 부분을 처음부터 다시 구현하지 않는다.

## 6. 다음 대화에서 사용할 최소 인계

> 기준은 이 네 문서 v0.1, 소스는 Export 0.4.1 / DIAG 0.7.1이다. 개발 패키지와 BSP 한 앱을 지원하며, 새 BSP ZIP은 앱 폴더 하나다. baseline과 실제 소유권을 유지한다. 기존 MIME/BSP Layout만 반영하며 ABAP/DDIC·다른 BSP 탭은 저장하지 않는다. DIAG 0.6.11의 I 재사용 후 활성화·SE80 반영은 사용자 확인됐고, 0.4.1 표기 ZIP 실물도 확인됐다. DIAG 0.7.1의 SAP 결과는 아직 없다. 먼저 후속 실행 결과와 설치 버전을 확인하고 T-01부터 이어간다. 초기 업무 AI·지식 연결 목적은 유지하되 별도 진행 상태로 다룬다.

## 7. 이번 네 문서의 일관성 검토

- 목적: 업무 AI 근거 구축과 한정된 웹자산 반영을 함께 보존했다.
- 범위: ABAP/DDIC·다른 BSP 탭 저장 제외, 개발 패키지 유지, BSP 한 앱·단일 폴더 요구가 네 문서에서 일치한다.
- 요구/계획: `spec.md`의 REQ-001~014를 상태표와 T-01~T-06에 연결했다.
- 과거 결정: 읽기 전용 방침을 최신 웹자산 승인 범위에서 대체하고 범용 Import는 되살리지 않았다.
- 검증: 코드 존재·기존 로컬 시험 보고·이번 파일 검토·사용자 SAP 확인을 구분했다.
- 가치: `insight.md`의 판단 근거와 가치 가설을 성과 완료로 쓰지 않았다.
- 문서: 공통 템플릿은 유지했고 네 프로젝트 문서는 신규 초안이다. 프로젝트 출처 갱신을 주장하지 않는다.

해결되지 않은 쟁점은 최신 SAP 실행, WAPD 경고의 실제 의미, 업무정책/코드 연결 및 우선순위다. 과거와 현재의 전면적인 목적 충돌이 해결되지 않은 채 남아 있는 것은 아니다.

## 8. 주요 변경 요약과 미확인 사항

- 신규 v0.1: 초기 이관 자료와 최신 릴리스를 대조하고, 실제 근거별 상태와 다음 시작점을 만들었다.
- 새 근거: E09의 단일 앱 폴더 ZIP과 원본 사본을 확인했다. 기존 v1.7에서 새 형식에 대해 제시한 로컬 시험·오프라인 fixture 근거에 실제 출력 파일을 추가했다. SAP 실행 과정과 DIAG 반영 미확인은 유지한다.
- 주요 미확인: DIAG 0.7.1의 SAP 실행·저장/활성화/원복, 모든 신규 저장 분기, 현재 GitHub·Mac·정책 승인·업무 답변 운영.
- 핵심 방향을 정하기 위해 지금 반드시 답해야 할 질문은 없다. 실행 재개 시 **현재 설치 버전과 새 BSP ZIP을 DIAG에서 실행한 결과**가 우선 확인 자료다.

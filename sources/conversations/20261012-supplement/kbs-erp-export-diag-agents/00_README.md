- **project_id:** `kbs-erp-export-diag-agents`
- **보완일:** 2026-10-12
- **확보 수준:** `partial`. 전체 대화 추출 완료가 아니다.
- **조사 대상 대화방:** ERP Git 관리를 위한 추출 및 배포 1개. 다른 대화방의 요약을 섞지 않았다.
- **대화 범위:** 기존 U002–U093과 A001–A006, U093 뒤의 A007–A009까지. 정확한 최초 대화 날짜는 미확인. 이번 보완 요청 이후는 다음 추출 대상이다.

## 1. 이번에 실제로 보완한 내용

**최우선 목표였던 과거 Export·DIAG·업무 에이전트의 AI 답변 전문은 새로 확보하지 못했다.** 실제 대화 검색을 세 차례 수행했지만 반환 결과가 요약에 그쳤다. 전문 열기 주소나 원 메시지 ID도 제공되지 않았다. 없는 답변을 새로 작성하지 않았다.

이전 ZIP·JSON·README·학습 가이드와 접근 가능한 공개 대화를 대조했다. 최근 교육 자료 제작의 공개 응답 3개(A007–A009)를 추가하고, 기존 사용자 요청 92개 전부에 대해 대응 AI 답변 확보 여부를 기록했다. 질문의 오타·문체·반복을 이번에 바꾸지 않았다.

| 집계 기준 | 수 | 의미 |
|---|---:|---|
| 전체 수록 발화 | 101 | 사용자 92 + assistant 9 |
| 전문으로 수록한 AI 발화 | 9 | 기존 verbatim 6개 승계 + 최근 공개 응답 3개 추가 |
| 발췌만 수록한 AI 발화 | 0 | 동일 응답으로 확인된 excerpt 없음 |
| 요약만 수록한 AI 발화 | 0 | 검색 요약을 assistant 메시지로 변환하지 않음 |
| 과거 핵심 AI 답변 신규 전문 확보 | **0** | U002–U090 구간 |
| 진행 안내 / 최종 답변 | 7 / 2 | 짧은 진행 안내를 최종 답변으로 세지 않음 |
| 최종 답변이 연결된 사용자 요청 | 3 | U091, U092, U093. 응답 작업은 2그룹 |
| 대응 답변 미확보 사용자 요청 | **89** | U002–U090. 실제 누락 AI 메시지 수는 미확인 |
| 학습 단계 | 18 | 기존 E01–E18 유지 |
| 포함 자산 / 미포함 자산 항목 | 58 / 34 | 포함 자산에 이전 ZIP 스냅샷과 이번 감사 자료가 추가됨 |
| 실제 이미지 | 22 | 기존 캡처 그대로 |

“전문으로 수록”은 해당 확보 본문 전체를 보존했다는 뜻이다. A001–A006은 이전 JSON의 원문 수준을 승계했으며 원 플랫폼의 전체 대화를 다시 열어 검증한 것은 아니다. 사용자 요청이 89개 미확보라는 수치와 누락된 AI 발화 개수는 같은 개념이 아니다. 여러 질문에 한 번 답했을 가능성을 남긴다.

## 2. 확인 자료와 확인하지 못한 범위

- 재확보한 기준 파일: `kbs-erp-export-diag-agents_교육대화추출_20261012.zip`. 내부 98개 발화, 18개 에피소드, 87개 자산 항목과 문서를 직접 읽었다.
- 프로젝트 저장 자료의 `PROJECT_CONTEXT.md`는 기존 포함 인계서와 바이트가 같았다. 요약 문서이므로 AI 발화 대신 사용하지 않는다.
- 붙여넣은 마크다운 두 파일은 내용이 동일했다. 한 파일 전체를 포함했으나 원 대화의 답변 전문과 동일한지, 어느 질문에 답한 것인지는 미확인이다. **파일 확보 1건을 답변 복구 1건으로 세지 않는다.**
- 기존 Export 0.3.18·DIAG 0.4.5·CHECK 0.3.3, 기존 지침/스킬, 실제 캡처, 파생 ZHR5 결과 JSON, 마스킹 ICM 로그를 유지했다. 새로운 SAP 실행·코드 수정·운영 검증은 수행하지 않았다.
- 해당 실행과 대응하는 Export 전체 ZIP, DIAG 0.4.5 실전 결과, 중간 수정본 전체, 업무 원문 전체, 현재 Mac/GitHub 구성은 여전히 미확인이다.
- 초기 전체 설계 대화, 과거 assistant 진행 안내/최종 답변, 일부 첨부는 미확보다. 누락 첨부를 재생성하지 않았다.

## 4. 포털 연결 시 지켜야 할 데이터 의미

- `project_id`, 기존 발화·에피소드 ID, 필수 JSON 스키마를 유지했다. 새 발화 A007–A009를 끝에 추가했고 기존 sequence는 바꾸지 않았다.
- assistant의 `response_stage`로 진행 안내와 최종 답변을 구분한다. `reply_to_user_message_ids`로 요청을 연결하고, user의 `response_coverage.status`로 원문 미확보를 표시한다.
- `content_type`은 verbatim/excerpt/summary만 사용했다. **missing은 발화의 content_type이 아니라 응답 확보 상태**다. 없는 assistant 객체를 만들지 않았다.
- `provenance`로 기존 원문 승계/이번 공개 응답 추가를 구분한다. 실제 플랫폼 메시지 ID를 만들지 않았다. 새 timestamp는 null이다. 기존 U093의 timestamp는 승계했으며 새 근거로 보충하지 않았다.
- U092/U093 중복을 유지한다. A005/A006은 U093 전의 진행 안내이며, A007–A009는 두 요청이 공유하는 계속된 작업이다.
- 원문 안 sandbox 링크는 당시 링크라 현재 다운로드를 보장하지 않는다. 포털은 asset_ids → assets.path를 사용한다. path=null이면 다운로드 버튼을 만들지 않는다.
- `availability=unavailable`은 이 ZIP에 배포본이 없다는 뜻이다. 원본 미확보와 기존 개인정보/중복 제외 사유는 개별 원래 메타데이터를 유지했다.
- 기존 전사의 줄바꿈·바깥 여백 정리는 소급 복구하지 못한다. 이번 보완에서는 기존 본문 문자열 전체를 그대로 유지했다.
- 과거 코드·초기 Import 설계·기존 요약의 오류를 몰래 수정하지 않았다. 현재 방안과 다른 부분은 해설에만 표시한다.

## 5. 추가로 필요한 자료

가장 필요한 것은 **U002–U090 구간의 사용자와 AI가 함께 있는 원 대화 내보내기 HTML/JSON 또는 전문 복사 MD/텍스트**다. `MISSING_RESPONSES.md`에서 각 질문과 다음 질문을 경계로 찾을 수 있다. 여러 요청을 묶어 답했다면 요청 묶음과 전체 답변을 함께 제공한다.

초기 프롬프트 파일의 직전 사용자 질문·공개 답변 원문도 필요하다. 코드 ZIP을 다시 받는 것만으로 당시 설명·표·주의사항이 복구되지는 않는다. 정확한 메시지 시각은 확인되는 원 기록이 있을 때만 추가한다.

## 6. 재검증

압축을 푼 최상위 폴더에서 다음을 실행한다. SAP/GitHub에 연결하거나 코드를 변경하지 않는다.

```bash
python3 assets/tools/validate_bundle.py
python3 assets/tools/validate_response_supplement.py
```

기존 합성 비교 실습은 교육용 예제이며 SAP 실행 성공 증거가 아니다. 이번 최우선 산출물은 과거 답변을 복원한 결과가 아니라, 실제 확보 수준을 유지한 보완 데이터와 구체적인 누락 요청 목록이다.

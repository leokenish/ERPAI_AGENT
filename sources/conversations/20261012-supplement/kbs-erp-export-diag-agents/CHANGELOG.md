## 2. 교체·순서·기존 원문

- 교체한 발화: **없음**. 기존 summary/excerpt assistant 항목은 각각 0개였다.
- 기존 98개 발화의 ID, sequence, role, timestamp, content_type, content_markdown을 전부 유지했다. 문자열 동일성 검사를 수행한다.
- 기존 순서 1–98은 재부여하지 않았다. 추가 응답은 기존 마지막 U093 뒤 99–101로 이어 붙였다.
- 사용자 오타·문체를 이번 보완에서 수정하지 않았다. 이전 추출에서 이미 정리된 줄바꿈·여백을 원 플랫폼 바이트로 복원했다고 주장하지 않는다.
- U030/U031 및 U092/U093의 반복 요청을 그대로 유지한다. U013/U042/U064의 빈 텍스트도 보존한다.
- A001–A006의 verbatim 표시는 이전 파일에서 승계한 것이다. 원 플랫폼 전체 대화를 다시 읽었다는 주장으로 강화하지 않는다.
- 현재 보완 요청과 그에 대한 이번 진행 안내/최종 답변은 추출 종료점 이후이므로 포함하지 않았다.

## 3. 응답 관계와 에피소드

- A001–A004 → U091. A005/A006 → U092. A007–A009 → U092/U093.
- U092와 U093은 하나의 계속된 결과 A009에 연결한다. A005/A006은 U093보다 앞이므로 U093의 직접 응답으로 소급 연결하지 않는다.
- E01–E17 ID·message_refs는 변경하지 않았다. E18의 기존 refs 뒤 A007, A008, A009를 추가했다.
- E18 해설에 원문 재확인 한계를 추가하고 이번 조사·응답 감사·이전 ZIP 자산을 연결했다. 에피소드 ID·order·map_nodes는 유지했다.
- 모든 user에 `response_coverage`, 모든 assistant에 `response_stage`, `reply_to_user_message_ids`, `provenance`를 추가했다. 필수 스키마와 최상위 배열 구조는 유지했다.
- `coverage`는 범위 101발화, 원문 미확보 89요청, cutoff와 문자 보존 한계를 반영했다. 누락을 실제 발화 객체로 만들지 않았다.

## 4. 파일과 산출물

- 이전 포함 첨부 53개 중 읽기용 파생 전사 MD 1개만 새 101발화에 맞춰 갱신했다. 나머지 52개는 바이트 동일 사본을 유지한다. 코드·원본 캡처·기존 스킬을 수정하지 않았다.
- 이전 98발화 ZIP 원본 전체를 포함하여 이전 README·가이드·검증보고와 데이터 스냅샷을 그대로 보존했다.
- 초기 프롬프트 MD 파일 하나를 전문 보존했다. 같은 바이트의 `붙여넣은 마크다운(1)(1).md`는 별도 복사하지 않고 원래 이름을 별칭에 기록했다. 기존 요청의 실제 답변으로 연결하지 않았다.
- 요청별 응답 감사 JSON·원문 검색 감사 MD·추가 검증 스크립트를 새로 작성했다. 이들은 교육용 분석 자료이며 당시 AI 원문이 아니다.
- `AI_RESPONSES_FULL.md`, `MISSING_RESPONSES.md`를 생성하고 README·자산목록·검증보고를 현재 범위로 교체했다.
- 기존 맥락 문서는 끝에 이번 보완 설명만 추가했다. 학습 가이드 E18의 refs/확보 수준과 끝의 포털 연결 설명을 갱신했다. 이전 내용은 기준 ZIP으로 확인할 수 있다.
- 이전 마스킹/제외 결정을 유지했으며 새로 확인되지 않은 코드·이미지·AI 답변을 재생성하지 않았다.

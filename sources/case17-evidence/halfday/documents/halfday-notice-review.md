# 통상근무 반일 근태일 시간외 입력 안내 검토

## 2026-10-30 우선안 재정정 — 기존 CHECK_ABSENCE_DATA 내부 분기 재사용

사용자 지적: 기존 근태 차단 FORM에서 허용 반일/차단 근태를 분기하면 중복 조회 로직을 입력 검사 함수에 따로 넣을 필요가 없지 않은가. 판단: 타당하다. 기존 _M 내부에 별도 반일 조회를 중복 작성한 제안은 철회하고 CHECK_ABSENCE_DATA의 기존 근태 조회·변경/삭제 원건 제외·평일 판단을 활용하는 방안을 우선한다. 앞선 ‘1곳+텍스트 심볼’도 최종 확정안이 아니며 아래 이력으로 보존한다.

검토 방향: 허용 반일을 SELECT에서 미리 제외하는 현 구조를 조정해 기존 근태 목록으로 반일 안내와 기타 근태 차단을 분리한다. 반일 안내는 통상 A에 한정하고 기존 시차 B 등 차단 판정은 유지한다. 복수 근태에서 반일이 먼저 나와도 즉시 RETURN하지 않고 차단 대상이 있는지 끝까지 검사하며 E63이 안내보다 우선한다. 변경/삭제 원건 제외와 ZTHRBS08 예외 조건을 유지하고, 안내 대상과 입력 예외 조건을 혼동하지 않는다. 최종 문구는 기존 코드+텍스트 심볼 방식으로 반환한다.

단, 이 FORM은 CHECK_INPUT_DATA_M뿐 아니라 CHECK_INPUT_DATA에서도 호출하는 공통 검사다. FORM 안에서만 I를 추가하면 사용자 입력 전용이라는 범위가 자동 보장되는 것은 아니다. 또한 _M 말미 L537–541에서 앞서 보관한 lv_code가 있으면 새 안내를 덮을 수 있다. 따라서 공통 FORM 1곳만으로 충분하다고 아직 확정하지 않고, 호출 시점 구분·기존 I 우선순위에 필요한 최소 보완만 확인한다. 새 공통 계층·별도 팝업·복제 조회를 먼저 추가하지 않는다. 기존 검사 후 I로 즉시 RETURN하여 중복/익휴 등 후속 검사를 건너뛰는 수정은 금지한다.

근거: SRC-18 현재 F03 L2063–2078의 반일 제외, L2098–2109 원건 제거, L2134–2162 평일·예외·E63; SRC-17 _M L493–541, 일반 CHECK_INPUT_DATA L627 이후의 공통 호출. 이번은 소스 재확인·설계 정정이며 원본 코드·텍스트 풀 미수정, SAP 미검증. [피드백](../../harness/feedback/FB-20261030-001.md).

## 현재 우선안 — 기존 관례 유지·최소 수정, 2026-10-29 후속 정정

**앞서 제시한 4곳 수정안은 현재 우선안에서 철회한다.** 사용자는 사용자 입력 시 안내만 요청했으며 관리자 화면·별도 공통 FORM·외부 프로그램 FORM 호출·메시지 문자열 병합·날짜별 1회 제한은 요구하지 않았다. 아래 기존 조사 내용은 후보·이력으로 보존하며 필수 수정 목록으로 사용하지 않는다. [피드백](../../harness/feedback/FB-20261029-004.md).

우선 범위는 **`ZHR_52TM_CHECK_INPUT_DATA_M` 1곳과 해당 프로그램의 신규 텍스트 심볼 등록**이다. 입력 중 근태 조회를 통해 통상 평일의 유효 반일을 확인하고 기존 `E_CODE`/`E_TEXT`로 정보 코드를 반환하는 방향을 검토한다. 새 FORM 2개, MOBILE_OVERTIME_CHECK 응답 병합, 관리자 MZH4110F01 수정은 우선 범위에서 제외한다. 기존 TEXT-E63은 종전 근태 오류 문구이므로 재사용해 덮어쓰지 않는다. 신규 번호는 텍스트 풀과 호출부에서 충돌 여부를 확인한 뒤 정한다.

확인한 관례:

- LZHR008_2F03 L150–153: 기존 차단 E52 대신 I52와 TEXT-E52를 반환하는 안내 예가 존재한다.
- ZHR_52TM_CHECK_INPUT_DATA_M L59–65,L537–541: 기존 I 안내를 보관하고 후속 오류 검사 완료 후 복원한다. 이번 안내도 후속 오류를 덮지 않으며 기존 안내 우선순위에 맞춰 함수 말미에 반영할 수 있다. 실제 삽입 위치는 기존 안내와의 우선순위를 포함해 정한다.
- LZHR008_2F06 L534–550,L709–712: I를 보관하고 계산 후 복원한다. MOBILE_OVERTIME_CHECK L307–314는 I를 S+문구로 전달한다. 기존 PC/모바일 콜백이 문구를 alert한다. 기존 전달 경로 재사용을 우선한다.
- TEXT-E63은 SAPLZHR008_2 텍스트 풀에서 ID=I, KEY=E63인 프로그램 텍스트 심볼이다. 사용자 예시 txt-063을 실제 소스 표기로 오인하거나 SE91 메시지 클래스로 확정하지 않는다.

검증 필요: 신규/수정 입력의 실제 호출, 입력 중 경고 표시 후 계속 계산/입력, 기존 E 및 다른 I 우선순위, 반려·변경·취소 근태 제외, 비대상 무안내. 입력 변경마다 재검사가 일어나면 안내도 반복될 수 있으며 이번 요구에 없는 1회 억제를 임의 구현하지 않는다. 날짜 초기화 전용 경로는 _M을 거치지 않을 수 있으므로 모든 진입 시점에 표시된다고 보장하지 않는다. 별도 초기진입 안내가 요구될 때만 추가 수정 필요성을 검토한다. 기존 저장전 재검사에서도 _M을 호출할 수 있지만 그 웹 콜백은 비오류 문구를 표시하지 않아 저장전 별도 팝업으로 확대하지 않는다.

입력 조건은 기존 반일 쌍·근태 상태·변경/삭제 원건 제외를 유지한다. 대상 근태와 신청/승인 범위는 앞서 검토한 조건을 담당자 확인 후 적용한다. 실제 코드·텍스트 요소는 아직 수정하지 않았으며 SAP 미검증이다.

## 요청과 제안

2026-10-29 인사부 담당자의 추가 의견으로 사용자가 전달한 요청(SRC-24 후속): 통상근무자의 반일 근태일 시간외 입력에 시작시각 안내를 표시한다. 현재는 제안 검토이며 변경 시행일·운영 반영 승인은 미확인. 이번 작업은 위치 조사·설계 검토까지이며 ABAP·BSP·DDIC·텍스트 요소를 수정하지 않았다.

권장 문구:

> 반차·반일 근태가 있는 날에도 근무 시작시간은 해당일의 원래 출근시간(자율출근 기준 포함)으로 입력해 주세요. 실제 업무를 시작한 시각부터 입력하면 연장시간과 실비가 적게 계산될 수 있습니다.

화면 공간이 좁다면 첫 문장만 팝업에 사용하고, 다음 문장을 도움말로 둔다. 일반검진·자녀돌봄까지 포함하려면 ‘반차’만 쓰지 않고 ‘반차·반일 근태’로 표현한다. ‘실제 근무시간’은 시간량으로 읽힐 수 있어 ‘실제 업무를 시작한 시각’으로 명확히 한다. 모든 직원을 09:00으로 안내하거나 근태 4시간을 휴게에 추가하라고 안내하지 않는다.

검토 의견: 입력 누락으로 실비가 적게 산출될 수 있다는 확인 사례가 있으므로 사전 안내가 타당하다. 근태만으로 시작시간이 잘못됐다고 단정하지 말고 정상 입력에도 보여주는 정보성 안내로 구성한다. 시간·금액 계산과 입력값을 자동 변경하지 않고 사용자가 확인 후 계속 입력할 수 있게 한다.

## 권장 표시 조건·시점

- 1차 범위: 실제 신청구분 통상 A, 평일, 해당 직원·근무일에 유효한 반일 근태 존재. N1만으로 판정하면 해외출장 등과 혼동할 수 있어 ZGUBUN과 함께 확인한다. 기존 1 값의 전달 여부는 호출 경로별로 확인한다. 시차 B·교대 C·선택근무로 자동 확대하지 않는다.
- 반일 후보는 현재 입력 허용 조건과 맞춘다: 연차(10,13/15), 자녀돌봄(30,43/44), 일반검진(40,28/29). 종류와 세부유형을 쌍으로 비교한다. ‘근태 인정시간=4’만으로 모든 근태를 동일 취급하지 않는다.
- 근태 상태는 현행 검사와 정합성을 우선 검토: 날짜 중첩, STATE 0/D, ZACCEPT<>N, ZUHYUNG 공백, 승인된 변경/삭제 원건 제외. 요청/승인 중 어느 상태까지 안내할지는 구현 전에 운영 담당자와 확정한다. ZACCEPT<>N을 ‘승인 완료만’이라고 설명하지 않는다.
- 날짜·직원 선택 및 기존건 편집 진입 시 1회 안내 권장. 시작/종료/휴게 수정마다 반복 팝업을 띄우지 않는다. 날짜·직원 전환 때 안내 키를 갱신하고 근태 상태 변경 후 재조회도 고려한다.
- 저장 직전 재안내는 선택안이다. 현재 저장 전 콜백은 성공 메시지를 무시하므로 별도 연결이 필요하다. 원클릭 저장 뒤 뒤늦게 뜨는 안내만으로는 입력 실수 예방이 약하다.
- 실제 기준 출근시각과 비교해 ‘다를 때만’ 표시하는 강화안은 기준시각 원천·당일 자율출근 적용을 추가 검증해야 한다. I AM 기본값이 해당일 확정 기준시각이라는 보장은 없다. 첫 단계는 반일 존재 자체에 따른 안내가 단순하다.

- 같은 검사 함수가 시간·휴게 변경에도 호출된다. 1회 표시를 안정적으로 구현하려면 BSP의 직원+날짜+안내종류 단위 중복 억제 또는 독립 안내 플래그/응답 경로가 필요하다. 메시지 문자열 비교보다는 식별 가능한 코드/플래그를 권장하며 응답 직렬화 지원은 확인 후 정한다. I_ISFST만으로 모든 날짜 변경·편집 진입을 제어할 수 있다고 단정하지 않는다.
- 기존 I AM 안내와 다른 I 메시지를 무조건 덮어쓰지 않는다. 안내를 합치면 BAPIRETURN1 MESSAGE 등 응답 필드 길이를 확인하고, 길이 초과 시 분리 표시를 설계한다. 오류가 있으면 기존 오류를 우선 표시한다.
- 경고가 실제로 확인·계속 입력이 가능한지 PC·모바일 각각 검증한다. 관리자 SAP는 웹 alert와 별도이며 ABAP MESSAGE TYPE W만 추가하는 방식으로 대체하지 않는다.

## 영향과 남은 확인

안내만 추가하는 범위에서는 시간분리·실비·대휴·월정산·PA2010·FI/EDI 로직을 변경할 이유가 없다. 향후 구현은 SAP_BASIS 700 호환 구문과 초급자용 명확한 FORM·한글 주석으로 작성한다. 이번은 코드 작성 없이 수정 후보를 찾은 단계이므로 SAP 구문검사·실행·배포는 NOT_RUN이다.

남은 결정: 최종 문구, 포함할 반일 종류와 신청/승인 상태, 날짜 선택 1회/저장 전 추가 안내, 관리자 화면 포함 여부. 현행 안내 제안과 확정 운영 정책을 구별한다. 소스는 SRC-17 2026-10-22 추출본과 SRC-18 로컬 근태 변경을 기준으로 확인했으며 실제 SAP 활성본은 미확인이다. AI 검토서 담당자 검토 대기.

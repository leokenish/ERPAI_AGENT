# 대휴 실비 단가 배수 검사 ALV

신규 실행 프로그램 `ZHR_DAEH_RATE_CHECK`의 로컬 개발안이다. 사용자가 요청한 0.5시간 단위 배수 검사이며 인정시간을 재계산하지 않는다. SAP 설치·구문검사·실행은 미수행이다. 원본 export는 변경하지 않았다.

## 설치와 실행

1. SE38에서 실행 프로그램 `ZHR_DAEH_RATE_CHECK`를 만들고 같은 이름의 ABAP 파일을 복사한다. SAP_BASIS 700 전제로 작성했다.
2. 텍스트 심볼 T01을 `대휴 실비 단가 검사`로 등록한다. 선택 텍스트는 P_YEAR=조회연도, S_PERNR=대상 사번, S_GUBUN=통상 입력구분, P_OLD=인상 전 시간외 단가, P_NEW=인상 후 시간외 단가로 등록한다.
3. 조회 전용 트랜잭션 `ZHR_DAEH_CHK`를 이 보고서에 연결하고 인사담당자 역할에만 부여한다. 프로그램도 S_TCODE를 검사한다. 직접 SQL이 HR 구조권한을 자동 적용하지 않으므로 전체 대상 조회가 허용된 담당자용이다. 기존 프로그램·권한 역할은 자동 수정하지 않는다.
4. 기본값 2026년, 8,400원→9,240원으로 실행한다. 사번을 비우면 전체, 퇴직자만 확인하려면 담당자가 확정한 퇴직자 사번 목록을 다중선택에 넣는다. 현재 재직 마스터로 제한하지 않는다. 퇴직 여부를 자동 판정하지 않는다.
5. ALV에서 판정/기준월 일치/사번으로 필터·정렬할 수 있다. 저장·정산·지급 버튼은 없다.

## 대상과 날짜

ZTHRBS01에서 STATE=3, ZDAEH=Y, RDATE가 조회연도 8월 1일~9월 30일인 자료를 조회한다. 사용/정산 완료 여부로 제외하지 않으므로 뒤늦게 확인하는 퇴직 건도 볼 수 있다. 선택은 ZSOURFLEX=S, 통상은 ZSOURFLEX 공백이면서 ZGUBUN이 조회조건에 맞는 건이다. 통상 입력구분 기본값 1/A/B는 기존 계산의 통상·시차 분기를 참고했다. 통상 시차의 대휴를 포함하며 시차실비 자체를 검사하는 것이 아니다. 별도 생성구분이 있는 재량·간주·탄력·교대는 자동 포함하지 않는다. 대상 분류는 운영 표본과 대조해야 한다.

단가 기준은 저장된 원천 근무일 RDATE다. 선택 생성부는 원천 DATUM을 RDATE로, 대휴 일자를 ZNAL/ZDDAY로 저장한다. 8/31 시작~9/1 종료는 RDATE=8/31인 한 8월 기준으로 검사한다. ZDDAY=9/1이라는 이유로 9월 단가를 적용하지 않는다. RDATE·ZNAL·ZDDAY를 함께 표시한다. 기존 분할 저장 경로에서 RDATE 자체가 익일로 바뀐 경우 원천 시작일 복원까지 구현한 것은 아니다. 본 프로그램은 BS01에 보존된 RDATE를 사용하며 분할 원천 연결이 없는 경계 건은 별도 확인한다.

## 금액과 판정

검사 대상은 대휴 실비 금액 ZD_MONEY이고, 최종 대휴정산금액 JORGEH가 아니다. 기존 ZRPTH415와 동일하게 DB 금액을 /100하여 실제 원 금액으로 비교한다. ALV는 통화 참조를 지정하지 않고 변환된 숫자를 원 단위로 표시하여 KRW 추가 배율을 피한다. 실제 DDIC 및 표시값은 SAP 표본으로 확인해야 한다.

인상 전 검사단위 = P_OLD × 0.5 × 0.5 = 기본 2,100원.
인상 후 검사단위 = P_NEW × 0.5 × 0.5 = 기본 2,310원.

| 조건 | 표시 | 차액 |
|---|---|---|
| 기준월 단위만 일치 | 기준월 배수 일치(추정) | 산출 안 함 |
| 양쪽 단위 일치 | 판별불가 | 산출 안 함 |
| 9월 건이 구단위만 일치 | 구단가 적용 의심 | 구단위로 역산한 시간에 신단가 적용한 추정차액 |
| 8월 건이 신단위만 일치 | 8월 건 신단가 적용 의심 | 신단위로 역산한 시간에 구단가 적용한 추정차액 |
| 양쪽 불일치 | 별도 확인 | 산출 안 함 |
| 0원/음수 | 별도 확인 | 산출 안 함 |
| JORGEH 존재 | 별도확인: 정산금액 존재 | 자동 추정 제외, 배수 결과는 참고 표시 |

OLD_OK/NEW_OK는 Y/N, MONTH_OK는 Y/N이며 비대상·별도확인은 '-'다. 양쪽 일치는 기준월 배수에도 해당하므로 MONTH_OK=Y지만 RESULT는 판별불가다. 정상 지급 확정이라는 뜻이 아니다.

DIFFERENCE = ESTIMATE − AMOUNT. 예를 들어 9월 33,600원은 구단위만 맞으므로 8시간으로 역산하고 신단가 추정금액 36,960원, 추정차액 +3,360원을 표시한다. 8월 36,960원은 추정금액 33,600원, 추정차액 -3,360원이다. 인정시간을 직접 확인한 결과가 아니므로 지급·환수 확정액으로 쓰지 않는다. DIFF_OK=Y인 행만 추정차액 산출 대상이다. 나머지 행은 금액 0/공백을 '차액 없음'으로 해석하지 않는다.

휴휴 식별을 JORGEH 존재와 동일시하지 않는다. 기존 소스에는 휴휴 정산금액 사전 저장과 일반 기정산 금액이 모두 있어, JORGEH가 있는 건 전체를 별도확인으로 보수적으로 분류한다. JORGEH=0이라고 휴휴가 아니라고 보장하지 않는다. 0.5시간 이외 단위, 23,100원 등 공배수, 인상 제외 직군, 부장급 0원, 수기보정도 한계다. 대상 사번에 인상 제외자를 넣으면 구단가/신단가로 판정할 수 없으므로 담당자가 제외하거나 별도 확인한다.

## 근거와 검증

- SRC-23 후속 2026-10-30 현재 대화: 시작일 기준 8,400/9,240원, 0.5시간 배수 선별, 인정시간 재계산 제외, 신규 ALV 요청. 공식 규정 승인·SAP 실행 확인과 구분한다.
- SRC-17 2026-10-22 추출본 ZRPTH410F01 L1244–1284: 선택 원천 DATUM→RDATE, DAEH_DT→ZNAL/ZDDAY, ZD_MONEY 산식.
- SRC-17 ZRPTH415F01 L121–132, L415–426, L515–541: 승인 대휴 조회, /100 표시, JORGEH 사전 저장·정산 처리.
- SRC-17 LZHR008_2F03 L4289, L6094: 통상·시차 입력구분. L5917–5918: 대휴실비 및 휴휴 정산금액의 ×100 저장.
- SRC-17 LZHR008_2F05 L102–104: 일부 분할 저장에서 RDATE/ZNAL이 분할일이 될 수 있는 한계.
- ZTHRBS01 본체 DDIC는 추출되지 않았다. 기존 프로그램 필드 참조를 재사용했으며 SAP DDIC 타입/전체 키 검증은 별도다.

`python3 tools/check_local.py`는 선별 산술 사례와 소스의 조회 전용·날짜·금액 단위 계약을 검사한다. ABAP 실행을 대신하지 않는다. 수동 검토: SAP_BASIS 700의 고전 선언/Open SQL/FORM/REUSE_ALV 방식 사용, 초급자용 한글 주석과 역할별 FORM, 신규 보고서 1개로 분리. 실제 SAP 구문검사, 표본 금액 표시·권한·운영 데이터 검증은 NOT_RUN.

SAP 표본은 최소한 8월 정상, 9월 정상, 9월 구단가, 5.5시간, 공배수, 양쪽 불일치, 0원, JORGEH 존재, 8/31 익일, 퇴직자 및 권한 미보유를 확인한다. 이후 인사담당자 수기 퇴직 정산 명세와 의심 건을 대조한다.

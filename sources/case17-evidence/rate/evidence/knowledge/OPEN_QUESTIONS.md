## 원문 대조로 해소한 항목

**Q01 — 매뉴얼 숫자:** SRC-02 p.4 원문은 **152시간**이며 p.8 화면과 일치한다. 초안의 512시간은 정리본 오독이었다. 2026-09-22 PDF 텍스트와 페이지 이미지로 재확인하여 매뉴얼 정리본·평가 문항을 정정했다. 이 항목은 더 이상 원문 오류 후보나 실무자 확인 과제가 아니다. Q02의 최대/연장가능시간 설명 차이는 별도로 남아 있다.

독립적인 회의록 파일은 이번11개 업로드에 없다. 카톡의 회의 일정·회의했다고 하는 발언만으로 회의 결정문을 새로 만들지 않았다.
자료 날짜가 오래됐다는 이유로 버리지는 않는다. 과거 오류와 변경 이유를 설명하는 근거로 보존하고 현재 답변에 적용할지 따로 판단한다.

## 선택 누적표시와 가산시간 — 2026-10-08 확인 범위

SRC-15와 BASE_DATA L632–635로 2024-10-15 가산 제외 요청 및 10-28 소정 미충족 오해를 줄이기 위한 가산 포함 롤백 이유를 확인했다. 이 표시 취지는 [업무 설명](processes/selective-cumulative-display.md)에 반영했다. 따라서 누적표시와 실근로시간을 같은 의미로 묶거나 10-15 설명을 최종 방침으로 답하는 것은 피한다.

남은 확인은 소정 소진후/평휴/휴평 등 전체 분기, 현재 활성 화면·소스와 운영값, 일자별 리포트의 후속 변경 범위, 가산의 연장수당·208시간 검사 반영 범위다. 대휴 생성 전체 구현을 실행 검증한 것은 아니며 롤백만으로 그 기준이 바뀌었다고 보지 않는다. Q08의 한도·특별연장 관련 미확인은 유지한다.

## 선택 단가 경계 검토 — SRC-23, 2026-10-29

- Q32: 원천 입력 시작일별 연장·휴일 충당·대휴 차감시간을 기존 B 총량과 대조해야 한다. 연장 발생일 기준은 확인됐으며, 총량에서 차감하던 대휴시간을 어떤 원천 입력에서 제외할지 연결 검증이 남는다. HR 수기도 익일 한 입력 전체에 시작일 단가를 적용했는지 확인 필요. 기존 원 단위 처리 유지가 기본이며 실제 차이가 있을 때만 추가 결정한다.
- Q33: SRC-23 후속으로 BS01 입력 시 일자를 확인해 단가를 확보하고 대휴 생성 때 그 단가를 사용한다는 운영 설명 확인. 대휴 단가 경로를 이번 변경의 미정 정책으로 취급하지 않는다. 기간 대휴실비와 재생성 명세의 단가·시간 합산 대사는 남는다. 시차실비·재량/간주 금액 인상 제외 확인. 시차 12,000원은 과거 협의 기록과 사용자 잠정 기억이며 현 운영값 실측은 별도다.
- [계산 개선 검토](processes/selective-rate-boundary-review.md). 검토안 미구현, SAP 미검증, 담당자 검토 대기.

입력 기준과 오전 누락 구간 자동 보충이 없다는 설명은 사용자 확인(2026-10-29). [조건부 계산 사례](processes/overtime-start-time.md#일반검진-오전-반일과-통상-시간외-계산--2026-10-29-확인)는 정적 소스·산술 확인이며 운영 상수/근태 행 및 정상·오입력 SAP 재현은 미검증. 기록일을 정책 시행일로 사용하지 않는다.


## 통상 반일 입력 안내의 구현 전 결정 — SRC-24 후속

[안내 제안 검토서](../proposals/20261029-ordinary-halfday-notice/README.md): 연차/자녀돌봄/일반검진의 포함 범위와 신청/승인 상태, 날짜 선택 1회·저장 전 추가 안내, 관리자 SAP 포함 여부는 제안 단계. 실제 SAP 활성본·반일 근태 상태·메시지 길이/우선순위·안내 중복 억제 확인 필요. 기존 W를 정보성 안내로 간주하면 계산/저장이 막힐 수 있음.


SRC-24 후속 범위 정정: 사용자 입력 안내만이 현재 요구다. 날짜별 1회·관리자 입력·저장전 추가 안내는 필수 요구에서 제외한다. 기존 4곳 확장안은 현재 우선안이 아니며 CHECK_INPUT_DATA_M+텍스트 심볼의 최소 수정 가능성과 기존 안내 우선순위를 검증한다.


2026-10-30 SRC-24 재정정: _M 별도 조회가 아닌 CHECK_ABSENCE_DATA 기존 근태 분기 재사용 우선. 공통 호출에서 입력 안내만 반환할 구분 수단과 기존 I 우선순위, 허용 반일+종일 근태 공존 시 E63 유지가 구현 전 확인 과제다. 한 FORM만으로 충분한지는 미확정.

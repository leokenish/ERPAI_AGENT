# ZRPTH411 소급 정산 화면 개선 — 교육자료 전달 패키지

시작 파일: index.html

## 포털 구성 에이전트에게
- 대화 전문은 conversation/transcript.html, transcript.md, messages.json에서 읽는다. messages.json이 구조화 원문이다.
- 최종 교육용 코드 보고서는 reports/final-code-report.html이다. 원본 대비 추가/삭제와 양쪽 줄 번호, 생략 없는 파일별 전체 코드가 있다.
- 최신 누적 코드는 code/04-latest-proposal에 있다. 실제 서버 재추출본이 아니라 대화에서 생성된 변경안을 합성한 것이다.
- history/01은 빈 FORM을 포함한 실패 사례다. 최신 코드나 권장 구현으로 노출하지 말고 ‘미완성안 반영으로 빈 화면 발생’ 교육 사례로 구분한다.
- 이미 반영한 코드에는 전체안이 아니라 각 시점의 추가 변경 HTML을 사용했다. reports/history의 적용 기준을 함께 표시한다.
- reports/history/04는 최신 추가 패치이며 사용자 실행 확인은 아직 없다.
- 원문 대화의 당시 오답·일본어·잘못된 안내를 고치지 않았다. 아래 정정 사항과 단계 정보를 함께 노출한다.

## 교육 흐름
1. 소급시작월부터 대상월 전월까지 재계산하는 로직 확인.
2. 당월 실비와 과거 소급 합계가 한 줄에 섞이는 문제 발견.
3. 기존 확정 데이터/CONFIRM_DATA 유지, 표시용 테이블 분리 설계.
4. 미완성 MAKE_DISPLAY_DATA를 제공해 GT_DISPLAY가 비어 빈 화면 발생.
5. 전체안을 다시 제공해 이미 적용한 사용자에게 혼란 발생 → 현재 적용본 기준 추가 패치로 개선.
6. 사용자 테스트: 당월 202601, 소급시작 202508, 과거 202509/202511/202512 변경. 소급 상세 54건과 금액이 나온다고 보고.
7. 사용자 요구로 최신순 정렬, 소급반영분/최종지급액을 당월 행으로 이동.

## 최종 표시 사양
- 직원별 당월 행 먼저, 과거 대상월과 기간은 내림차순.
- 소급반영분 = 기존 계산의 실제 반영액. 당월 행에 한 번 배정된 기존 값 유지.
- 최종지급액 = 해당 당월 기간실비 + 소급반영분.
- 과거 상세 행의 두 지급 필드는 0/공란. 기간별 재계산 시간·실비·기존 확정액·차액은 표시.
- ZTHREDITCOST 적용 대상은 기존 합친 행 유지. 적용 기준은 정산대상월·사번이며 소급시작월이 아님.
- 음수 상세 표시와 실제 소급 반영액은 다름. 기존 지급 결정 로직을 변경하지 않음.

## 구별해야 하는 사실과 한계
- ‘기존 확정액’ 공란은 실제 미지급의 증거가 아니다. 확정 0원, 행 부재, 기간 키 미일치 모두 가능.
- 이미 지급된 소급액의 중복 산출 방지는 이번 개발에서 제외했다.
- DB 구조 변경은 없다. 로컬 원본은 수정하지 않았으며 code/00-original은 복사본이다.
- 신규 코드는 SAP_BASIS 700을 전제로 작성. SAP 구문 검사·활성화·운영 검증 완료를 주장하지 않는다.
- 첨부 이미지와 대화에는 실명/사번이 원문 그대로 포함되어 있다. 이번 패키지는 요청된 내부 교육 원자료 보존본이며 자동 익명화하지 않았다.
- 메시지 전문은 내보내기 시점까지의 사용자·AI 답변·진행 메시지다. 시스템/개발자 지침, 내부 추론, 도구 실행 원시 로그는 제외했다. 최종 ZIP 전달 답변은 생성 시점 이후이므로 포함되지 않는다.

## 파일 구성
- conversation/: 원문 대화 3형식
- images/: 실제 첨부 이미지 원본
- code/: 5개 단계의 ABAP 전체 코드
- reports/: 최종 전체 비교 보고서와 단계별 HTML
- reference/: 사용자 첨부 HTML 원본
- metadata/: 단계·변경정보·출처 및 SHA-256 목록

교육 포털 페이지 생성이나 외부 업로드는 수행하지 않았다.

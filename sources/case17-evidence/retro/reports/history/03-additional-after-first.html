ZRPTH411 · 첫 HTML 반영 후 추가 변경만

기준: 첫 번째 17개 구간 HTML을 모두 반영한 상태 · 추가 수정 구간만 제공

이미 적용한 첫 HTML 다음에 추가할 변경만 담았습니다.
왼쪽 = 첫 HTML 17개 구간을 반영한 예상 코드. 오른쪽 = 그 상태에서 이번에 추가로 바꿀 코드입니다. 서버 원본이 없으므로 왼쪽 줄 번호는 첫 HTML 반영본에서 재구성한 예상 줄 번호입니다. 실제 서버 줄 번호는 달라질 수 있으니 프로그램·FORM명과 왼쪽 코드를 함께 대조하세요. 첫 HTML에서 이미 추가한 내부 테이블·함수 인수·엑셀 헤더·ALV 연결을 다시 추가하지 마세요.

이번에 할 일

  1. ZRPTH411 본체 START-OF-SELECTION: 이전 실행의 신규 내부 테이블 초기화 추가.
  2. ZRPTH411F01 APPEND_INIT_FIELDCAT: 참고금액 혼합 합계 방지와 지급액 열 제목 보완.
  3. ZRPTH411F01 맨 아래: 기존의 빈 MAKE_DISPLAY_DATA 전체를 실제 구현으로 교체. 바로 뒤의 CLEAR_DISPLAY_RESULT도 함께 추가.

그대로 둘 것: TOP 정의, 함수 TABLES 매개변수·본문, 상세 수신, 보정 적용 기록, ALV의 GT_DISPLAY 연결, 확정 후 MAKE_DISPLAY_DATA 호출, 화면 호출 전 MAKE_DISPLAY_DATA 호출, F02 엑셀 변경.

DB 구조와 기존 확정·취소 처리는 변경하지 않습니다. 첫 HTML에서 함수 인터페이스를 이미 정의했다는 전제입니다.

전체 파일 복사 기능은 제외했습니다. 아래 오른쪽 추가 변경 구간만 교체하세요. SAP 구문·실행 검증은 미수행입니다.

표시·합계 규칙

  • 소급 미체크: 기존 기간별 당월 행을 그대로 표시합니다.
  • 정산대상월·사번에 ZTHREDITCOST 적용: 기존 기간별 한 행 표시를 유지합니다. 소급시작월의 행 존재 여부로 판단하지 않습니다.
  • 일반 소급: 당월 기간별 행 뒤에 모든 소급 대상기간의 재계산 행을 표시합니다. 음수·0원 차액도 표시합니다.
  • 재계산 차액은 참고값입니다. 실제 소급 반영액은 기존 계산 결과를 직원의 마지막 소급 행에 딱 한 번 표시합니다. 따라서 각 기간의 차액을 지급액으로 오해하지 않도록 ‘실제 소급 반영액’ 열을 함께 확인합니다.
  • ‘이번 지급 반영액’ 열 합계는 GT_DISP2 최종지급액 합계와 같아야 합니다. 재계산 실비 열의 혼합 합계는 소급 화면에서 끕니다.
  • 정산 확정 후에도 화면을 다시 구성합니다. 확정조회 RB1과 확정취소의 저장 데이터는 기존 흐름을 유지합니다.

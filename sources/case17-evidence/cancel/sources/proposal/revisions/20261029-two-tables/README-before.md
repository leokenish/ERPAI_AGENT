# 선택근로 대상자 삭제 프로그램

2026-10-28 사용자 확정 요구에 따라 작성한 신규 개발안. 담당자 검토 대기이며 SAP 미반영·구문/실행 미검증이다. 추출 원본은 수정하지 않았다.

## 파일과 설치

[ZHR_CW_MEMBER_DEL.abap](ZHR_CW_MEMBER_DEL.abap)을 UTF-8로 제공한다. SE38에 동명 실행 프로그램을 만들고 소스를 입력한다. 전용 트랜잭션 `ZHR_CW_DEL`을 이 프로그램에 연결하여 인사부에만 부여한다. 프로그램 내부에서도 S_TCODE를 검사하므로 전용 권한 없이 SE38로 실행해도 차단한다. 표준 P_ORGIN의 정보형 9021 쓰기 권한도 검사한다. P_ORGXX·구조권한 등 운영 권한 체계는 권한 담당자가 확인한다. 선택화면 텍스트를 p_pernr=사번, p_begda=선택근무 시작일, p_endda=선택근무 종료일로 지정한다.

## 요청과 동작

세 입력은 모두 필수이며 PA9021과 ZTHR0132의 시작일/종료일이 동일하다는 사용자 확인을 전제로 한다. 각 테이블에서 정확히 한 건을 찾고 근무주기도 일치해야 한다. 기간 조정/분할/보정 기능은 없다. 인사부 권한으로 ZTHR0112 실적을 결재 연결·상태와 무관하게 물리 삭제한다. 대휴 ZTHRBS01은 읽지도 변경하지도 않는다. 결재 테이블도 변경하지 않는다.

종료일 YYYYMM과 근로유형 0110으로 ZTHR0160 행을 찾으면 삭제를 차단한다. ZTHR0113에 해당 기간의 정산 이력이 있거나 실적 ZADMIT_DT가 남아 있어도 차단한다. ZTHR0113은 정산연월을 한 달로 제한하지 않아 소급 이력도 보호한다. 실적은 DATUM 범위 대신 선택기간 키로 읽어 익일/복수 행을 포함한다.

첫 조회 후 삭제 건수 확인창(기본 취소)을 표시한다. 확인 후 직원 및 공통 테이블 잠금, 마감/정산/권한 재검사, 전체 행 값 비교를 수행한다. 세 테이블 모두 SQL DELETE로 처리한다. PA9021은 조회해 둔 원본의 전체 기본키로 정확히 1건만 삭제한다. 중간 COMMIT이나 갱신 태스크는 없으며 건수 불일치/SQL 오류는 ROLLBACK한다. 성공 시 한 번 COMMIT WORK AND WAIT한다.

## 실제 소스 근거

SRC-17, 2026-10-22 KSP/300 추출본의 아래 구간을 직접 확인했다.

- [ZRPTH410F01](../../exports/ZHR5/packages/ZHR5/programs/PROG/ZRPTH410F01/source/ZRPTH410F01.abap): L208 PA9021 조회, L297–421 ZTHR0132 생성, L974–1005 정보형 함수 사용. 기존 코드는 정보형 등록 함수 사용이며 신규 삭제 프로그램의 직접 SQL과 구별한다.
- [CW_PROCESS_DATA](../../exports/ZHR5/packages/ZHR5/function-groups/FUGR/ZHR008_3/Function%20Module/ZHR_52TM_CW_PROCESS_DATA/Source%20code/ZHR_52TM_CW_PROCESS_DATA.abap): L22–40 종료월 기준 마감 검사. 기존 함수의 case별 예외를 재사용하지 않고 새 삭제 기능은 무조건 마감을 차단한다.
- [ZRPTH411F01](../../exports/ZHR5/packages/ZHR5/programs/PROG/ZRPTH411F01/source/ZRPTH411F01.abap): L543–587 마감 생성/취소, L737–749 확정 시 실적 정산일, L1190–1262 정산 취소 연계.
- ZTHR0132/0112/0113/0160 DDIC 키는 추출 definition.xml에서 확인했다.

## 운영 적용 전 확인할 제한

1. **동시 마감:** ENQUEUE_E_TABLE은 이 프로그램 간 협조 잠금이다. 기존 월마감/실적 쓰기 코드가 이 잠금을 자동 준수하지 않는다. 재검사만으로 검사 직후의 경쟁 상태까지 차단할 수 없다. 운영 전 기존 마감·입력·기간생성 경로와 공유하는 잠금을 연계하거나 해당 쓰기 작업과 동시 실행되지 않는 운영 통제를 확정해야 한다. 기존 소스에 잠금을 추가하는 변경은 이번 파일에 포함하지 않았다.
2. **PA9021 직접 삭제:** 기간 조정/보정 없이 세 테이블을 한 DB LUW에서 삭제하기 위해 정보형 함수 대신 전체 키 SQL DELETE를 사용했다. 표준 HR 변경문서·시간제약 검사·버퍼 무효화·사용자 출구는 자동 실행되지 않는다. 정보형 9021의 별도 저장/감사 요구와 다른 세션 버퍼 영향을 개발계에서 확인한 후 적용한다. 직접 삭제가 회사 기준에 맞지 않으면 정보형 API 기반으로 재설계해야 한다. 후속 삭제에서 오류를 강제로 발생시켜 전체 롤백을 확인한다. COMMIT 오류 이후에는 ROLLBACK만으로 복구됐다고 단정하지 않는다.
3. **결재:** 연결 유무로 삭제를 막지 않는다. 기존 결재함에서 삭제된 실적을 조회/승인할 때 오류·재생성이 없는지 확인해야 한다. 결재 이력 정리는 이번 범위 밖이다.
4. **감사/복구:** 현재 파일은 성공 건수와 처리자를 목록으로 출력하며 영구 감사원장·전체 원본 백업 테이블을 구현하지 않았다. 운영 적용 전 회사의 백업/감사로그 방식을 연결해야 한다. 화면 목록을 영구 감사로그로 보지 않는다.
5. 전용 트랜잭션과 P_ORGIN은 로컬 정적 검사로 운영 권한의 적절성을 입증하지 않는다. 비인사부 사용자 차단 시험이 필요하다.

## 검증 시나리오와 상태

로컬 정적 검사는 verification.json에 기록한다. 실제 SAP 구문 검사, 확장 구문 검사, 함수/잠금 인터페이스, 사용자 출구, 권한, 실행/DB 결과는 모두 NOT_RUN이다. SAP_BASIS 700 고전 선언/SQL/FORM과 업무 목적을 설명하는 한글 주석을 사용했다. SAP 컴파일 통과를 주장하지 않는다.

개발계에서 다음을 확인한다.

- 열린 기간·실적 0건: PA9021/0132 각 1건 삭제.
- 열린 기간·미상신/결재중/승인/삭제 상태와 결재 연결 실적: 상태에 관계없이 같은 기간의 실적 전부 삭제. 다른 기간·직원 보존.
- 월 경계: 9월 시작/10월 종료이면 10월 마감으로 검사.
- 마감 행 존재, 정산이력 존재, 정산일 잔존: 각각 세 테이블 불변.
- 날짜 불일치·중복 주기·권한 부족·확인 취소: DB 불변.
- 확인창 이후 데이터 변경 또는 마감: 중단 및 DB 불변.
- PA9021/사용자 테이블 삭제 오류: 세 테이블 모두 원복.
- 동시 마감/입력/대상기간 생성: 공유 잠금 연계 후 경쟁 시험.
- 재실행: 일치 대상 없음으로 중단.

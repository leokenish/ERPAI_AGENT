# 선택근무 정산 후 PA2010 삭제 프로그램 개발안

작성일: 2026-10-24. 사용자 요청에 따른 신규 프로그램 초안이다. SAP 등록·구문검사·실행·운영 반영은 하지 않았다. 담당자 검토 상태는 대기다.

- 프로그램: **ZRPTH411_RET_DEL**, 실행 프로그램(Type 1)
- 프로그램 제목: 선택근무 지급 항목 삭제
- 제안 트랜잭션: **ZHR5_RET_DEL**
- 소스: [ZRPTH411_RET_DEL.abap](ZRPTH411_RET_DEL.abap)
- 기준 환경: SAP_BASIS 700, SAP GUI 대화식 실행
- 기존 추출 소스 수정: 없음. `exports/` 밖에 신규 파일로 작성했다.

## 요청과 적용 범위

기존에는 인사 담당자가 시스템 담당자에게 선택근무 퇴직자의 PA2010 제외를 요청했다. 이번 요청은 인사 담당자가 별도 프로그램에서 사번 한 명과 정산연월을 입력해 직접 처리하도록 만드는 것이다. 시행일과 운영 배포는 정해지지 않았다.

요청한 흐름은 다음과 같이 구현했다.

1. 사번 한 명과 정산 대상연월을 입력한다. 범위 입력이나 여러 사번 입력은 제공하지 않는다.
2. 선택근무 마감 내역, 연결된 PA2010 지급 항목을 조회한다.
3. “사번 … / 정산연월 … / 선택근무 지급 항목 …건을 PA2010에서 삭제하시겠습니까?” 확인창을 표시한다. 기본값은 ‘아니오’다.
4. ‘예, 삭제’를 누르면 사번 잠금 후 자료를 다시 확인하고 삭제한다. 아니오·취소·창 닫기는 삭제하지 않는다.
5. 저장 후 PA2010을 다시 조회해 대상 항목이 없으면 “삭제 완료되었습니다” 팝업을 표시한다.

한 명의 해당 월 자료가 여러 정산일에 나뉘어 있으면 연결된 여러 항목을 처리한다. 삭제 함수 호출 중 한 건이라도 실패하면 `ROLLBACK WORK`하고, 모두 성공했을 때 한 번 저장한다. 이는 코드의 처리 의도이며 실제 함수·업데이트 동작은 SAP에서 시험해야 한다.

## 가장 중요한 연월 기준

입력하는 연월은 **기존 선택근무 정산 화면의 대상연월**, 즉 `ZTHR0113-ZADMIT_YM`이다. PA2010 날짜의 월이나 프로그램을 실행하는 달로 해석하지 않는다.

예를 들어 정산 대상연월이 `202609`이고 그 마감 내역의 PA 정산일(`ZADMIT_DT`)이 `20261010`이면, 입력은 `202609`이며 연결 대상은 PA2010의 `BEGDA = ENDDA = 20261010`이다. 이 날짜는 설명용 예시이고 운영 지급일을 확정한 것이 아니다.

연결 조건은 다음과 같다.

| 단계 | 사용 조건 |
|---|---|
| 월마감 확인 | `ZTHR0160-ZMONTH = 입력 연월`, `Z52WKTP = '0110'` |
| 개인 정산 확인 | `ZTHR0113-PERNR = 입력 사번`, `ZADMIT_YM = 입력 연월`, `Z52WKTP = '0110'`, 정산일 존재 |
| 지급 항목 확인 | 같은 사번, `PA2010-SUBTY = LGART = '8050'`, `BEGDA`가 위 정산일 중 하나 |
| 삭제 허용 조건 | `BEGDA = ENDDA`, `AWREF` 공란, 기존 정산 생성 방식의 기본 키(`OBJPS/SPRPS/SEQNR` 초기값), `HISTO` 초기값 |

같은 사번·정산일에 다른 정산연월이나 다른 유형의 ZTHR0113 내역도 연결되면 중단한다. PA2010 한 행에 다른 월 금액까지 합산됐을 가능성을 이 초안에서 임의로 분리하지 않는다. 비표준 키나 잠긴 항목도 개별 확인 대상으로 중단한다.

2026-10-28 사용자 전달 요청에 따라 퇴직자 제한을 제거했다. PA0000 조회와 STAT2 검사를 수행하지 않으며 재직·퇴직 상태와 관계없이 정산 자료 조건으로 대상을 확인한다.

## 코드 읽는 순서

| 구간 | 하는 일 |
|---|---|
| `PARAMETERS` / `AT SELECTION-SCREEN` | 사번·연월 입력과 연월 형식 검사 |
| `START-OF-SELECTION` | 실행권한 → 대상 조회 → 최종 확인 → 잠금 → 재조회 → 삭제 → 완료 팝업 |

## SAP에 등록해 시험하는 방법

1. 개발 시스템에서 이름 중복을 확인하고 SE38에 `ZRPTH411_RET_DEL`을 실행 프로그램으로 생성한다. 제안 이름은 현재 로컬 export에서 중복이 발견되지 않았으며 SAP 전체 이름 중복은 미확인이다.
2. ABAP 파일 전체를 붙여 넣고 SAP 구문검사를 수행한다. 논리 데이터베이스나 별도 텍스트 요소는 필요하지 않다.
3. SE93에서 `ZHR5_RET_DEL`을 해당 프로그램의 실행 트랜잭션으로 만든다. 패키지·전송요청은 사내 개발 절차에 따른다.
4. 지정 인사 담당자 역할에 해당 트랜잭션 실행권한을 부여하고 기존 HR 권한도 확인한다. 코드는 `S_TCODE`를 명시적으로 검사하므로 SE38에서 실행해도 해당 권한이 필요하다.
5. 아래 시험을 개발/검증 시스템에서 수행한다. 실제 운영 데이터 삭제와 배포는 이번 작성 작업에 포함되지 않는다.

`HR_INFOTYPE_OPERATION`과 사번 잠금 함수는 기존 패키지의 호출 형태를 참고했다. 권한 검사를 해제하는 함수는 호출하지 않는다. 다만 표준 함수 본문, 운영 HR 권한 설정, 변경문서 설정은 제공된 export 범위 밖이므로 실제 사용자 권한·삭제 이력 생성은 SAP에서 확인해야 한다. `S_TCODE` 검사는 프로그램 실행권한이며 개별 인사자료 접근권한 전체를 대신하지 않는다.

## 남은 확인 사항

- 다른 월이 같은 PA일자에 연결된 경우의 중단 기준은 유지한다. 담당자가 검토해야 한다.
- SAP 구문검사, 표준 함수의 실제 인터페이스·인포타입 커스터마이징·HR 권한·롤백·변경문서 및 업데이트 처리는 아직 검증하지 않았다.
- 사번 잠금은 같은 잠금을 지키는 프로그램 사이에서만 효과가 있다. 기존 월정산·전표 프로그램은 직접 DB 변경 구문도 포함하므로 이 프로그램과 동시 실행하지 않는 운영 순서가 필요하다. 기존 프로그램을 고치지 않은 초안이 동시 실행까지 완전히 차단한다고 보장하지 않는다.
- AWREF 공란 검사는 제공된 코드에서 확인한 전표 연결 기준이다. 다른 시스템의 최종 지급 여부 전체를 입증하는 검사는 아니다.
- 별도 영구 삭제 이력 테이블은 추가하지 않았다. 표준 변경문서가 실제로 남는지 검증하고, 부족하면 담당자·시각·삭제 전 키/금액을 보관할 이력 기능을 후속 범위로 정한다.

로컬 점검 결과는 [verification.json](verification.json)에 기록한다. ABAP 실행 시험을 대신하지 않는다.

## 2026-10-28 퇴직자 제한 해제

사용자가 전달한 인사 담당자 요청에 따라 PA0000 현재 유효 행 및 STAT2=0 검사를 제거했다. 화면 제목·사번 라벨·확인창도 대상자 기준으로 변경했다. 프로그램/트랜잭션 이름은 유지한다. 한 명씩 처리, 권한, 마감, 8050, 전표, 키, 잠금·재조회·롤백 검사는 유지했다. SAP_BASIS 700 구문 범위 내 삭제와 문구 수정이며 단순한 FORM 흐름을 유지한다. 시행일·SAP 배포·실행 검증은 미확인이다.

변경 전 소스·패치·전후 해시: [변경 보관 폴더](revisions/20261028-remove-retiree-limit/). 기존 추출 소스는 수정하지 않았다.

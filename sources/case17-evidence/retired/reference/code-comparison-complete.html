이전 미완성 HTML을 대체하는 파일입니다.
MAKE_DISPLAY_DATA와 보조 FORM까지 실제 코드를 포함했습니다. 원본은 수정하지 않았습니다. SAP_BASIS 700을 전제로 작성했으나 SAP 구문 검사·활성화·실행은 아직 수행하지 않았습니다. 서버에 이미 일부 반영했다면 새 코드를 중복 추가하지 말고 ‘변경 후 전체 코드’를 기준으로 대조하세요.

적용 순서

  1. 개발서버의 현재 프로그램·함수를 백업하고 로컬 기준본과 다른 기존 변경이 있는지 비교합니다.
  2. TOP 내부 테이블 정의와 함수 인터페이스를 먼저 맞춥니다.
  3. 함수 본문, F01, F02, 본체를 적용한 뒤 관련 객체를 함께 구문 검사합니다. 각 코드의 ‘전체’는 해당 Include/함수 한 개의 전체입니다.
  4. 함수 그룹 ZHR008_3와 프로그램 ZRPTH411의 활성화·화면 테스트를 수행합니다.

DB 구조 변경 없음. GT_DISP2와 CONFIRM_DATA/CANCLE_CONFIRM_DATA의 저장 처리는 유지합니다. 기지급 소급분 중복 차감은 추가하지 않았습니다.

함수 코드 상단의 *" 인터페이스 주석은 설명입니다. 주석 붙여넣기만으로 TABLES 정의가 생성되지 않습니다. 함수의 FUNCTION~ENDFUNCTION 전체 코드는 SE37 소스 편집 기준으로 제공합니다. 추출 XML이나 동일 함수의 중복 Include를 별도로 수정하지 않습니다.

표시·합계 규칙

  • 소급 미체크: 기존 기간별 당월 행을 그대로 표시합니다.
  • 정산대상월·사번에 ZTHREDITCOST 적용: 기존 기간별 한 행 표시를 유지합니다. 소급시작월의 행 존재 여부로 판단하지 않습니다.
  • 일반 소급: 당월 기간별 행 뒤에 모든 소급 대상기간의 재계산 행을 표시합니다. 음수·0원 차액도 표시합니다.
  • 재계산 차액은 참고값입니다. 실제 소급 반영액은 기존 계산 결과를 직원의 마지막 소급 행에 딱 한 번 표시합니다. 따라서 각 기간의 차액을 지급액으로 오해하지 않도록 ‘실제 소급 반영액’ 열을 함께 확인합니다.
  • ‘이번 지급 반영액’ 열 합계는 GT_DISP2 최종지급액 합계와 같아야 합니다. 재계산 실비 열의 혼합 합계는 소급 화면에서 끕니다.
  • 정산 확정 후에도 화면을 다시 구성합니다. 확정조회 RB1과 확정취소의 저장 데이터는 기존 흐름을 유지합니다.

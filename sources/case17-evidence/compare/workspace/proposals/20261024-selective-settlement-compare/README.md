# 선택근무 정산 전후 변경 비교

**신규 실행 프로그램 `ZRPTH411_COMPARE` — 조회 전용 개발안, SAP_BASIS 700 기준.** 기존 ABAP·추출 원본은 수정하지 않았다. 사용자가 적용 후 제공한 조회 결과를 검토하고 2026-10-26에 보조 근태 0건 처리를 수정했다. 수정본의 SAP 활성화·재계산은 미실행이며 업무 검토 상태는 `pending_business_review`다.

적용 파일은 [ZRPTH411_COMPARE.abap](ZRPTH411_COMPARE.abap) 하나다. 아래 검사 도구와 JSON은 로컬 검증 자료이며 SAP에 등록하지 않는다.

## 2026-10-26 비교 열 색상 추가

최신 전체 코드에는 근태 0건 처리 수정과 비교 열 색상 구분이 모두 포함된다. 이미 등록한 `ZRPTH411_COMPARE` 소스만 교체하고 구문 검사·활성화한다.

| 열의 의미 | 배경색 | 적용 항목 |
|---|---|---|
| 정산 당시 | 파랑 계열 | 당시 기간실비, 대휴수·시간, 항목별 정산 금액 |
| 현재 등록 | 회색 계열 | 현재 대휴수·시간·저장금액, 대휴 상세의 현재값 |
| 재계산 | 녹색 계열 | 재계산 기간실비, 대휴수·시간·저장금액, 두 상세 화면의 재계산값 |
| 차액·증감 | 노랑 계열 | 기간/항목별 차액, 대휴수·시간 증감, 추가·삭제·내용 변경 건수 |

메인 목록·금액 상세·대휴 상세에 같은 기준을 적용하고 상단에 색상 설명을 표시한다. 색상은 열의 의미를 구분하며 변경 발생이나 지급 완료를 뜻하지 않는다. `미계산` 문구와 열 제목은 유지한다. 실제 색조는 SAP GUI 테마에 따라 다르므로 개발서버에서 세 화면을 확인한다. 계산식·조회 조건·데이터는 바꾸지 않았다.

수정 전 사본, [색상 변경 패치](revisions/20261026-column-colors/column-colors.patch), [전후 해시·검증 기록](revisions/20261026-column-colors/change-record.json)을 보존했다. v700 문법·부분 타입·정적 검사 및 계산부 불변 확인은 통과했으며 SAP 화면 표시는 아직 확인하지 않았다.

## 2026-10-26 수정본 적용과 11명 재조회

이미 등록한 **이번 비교 리포트 `ZRPTH411_COMPARE`의 소스 전체를 위 파일로 교체**하고 구문 검사·활성화한다. 기존 정산 프로그램/함수는 변경하지 않는다. 신규 테이블·함수·트랜잭션 추가는 없다. 아래 최초 등록 절차를 다시 수행할 필요는 없다. 프로그램명을 바꿔 등록했다면 첫 줄 REPORT를 그 이름에 맞춘다.

수정 전에는 `ZHR_52TM_AWART_LIST`가 근태 목록 0건에 반환하는 `E / 해당 데이터가 없습니다.`까지 계산 오류로 처리했다. 이 목록은 기간실적 자체가 아니므로 0건이어도 기간실적을 사용한 대휴·금액 계산을 계속해야 한다. 수정본은 **반환 행이 0건이고, TYPE/MESSAGE가 기존 함수의 0건 응답과 일치하며, 다른 반환 필드는 모두 초기값인 경우만** 통과시킨다. 메시지는 `SAPLZHR008_2`의 현재 로그인 언어 텍스트 `I/M01`에서 읽고, 조회할 수 없을 때 확인된 한국어 문구를 사용한다. 다른 E/A 응답과 추가 오류정보가 있는 응답은 계속 중단한다.

| 재검증 항목 | 개발서버에서 확인할 내용 |
|---|---|
| 동일 조회 | 시작일 **2026.06.08**, 종료일 **2026.07.05**, 사번 공란. 기존 대상/권한이 같다면 71명이다. |

선택적으로 [ZRPTH411_COMPARE_TEST.abap](tests/ZRPTH411_COMPARE_TEST.abap)을 별도 실행 프로그램으로 등록하면 실제 비교 리포트의 반환 판정 FORM에 11개 경계 사례를 전달할 수 있다. `P_REPORT`는 등록한 비교 리포트명이며 기대 출력은 `Tests: 11 / Failures: 0`이다. 이 보조 프로그램은 업무 데이터를 읽거나 저장하지 않는다. **11개 테스트 사례와 미계산 직원 11명은 별개**이며 보조 테스트의 SAP 실행 상태도 `NOT_RUN`이다.

수정 전 소스·검사 결과, [변경 패치](revisions/20261026-awart-empty/awart-empty.patch), [전후 해시·검증 기록](revisions/20261026-awart-empty/change-record.json)을 보존했다. 대휴·금액 계산 산식 생성 영역은 변경하지 않았다.

## 개발서버 적용

1. SE38/SE80에서 **새 프로그램 `ZRPTH411_COMPARE`**, 유형 **실행 프로그램**을 만든다. 제목은 **선택근무 정산 전후 변경 비교**로 지정한다. 같은 이름의 객체가 이미 있으면 덮어쓰지 말고 새 이름을 정한 뒤 첫 줄 REPORT도 맞춘다.
2. 원본 파일 전체를 UTF-8로 업로드하거나 붙여넣는다. 별도 INCLUDE, 화면, GUI STATUS, 메시지 클래스, 함수 모듈, 신규 테이블은 만들 필요가 없다. 선택화면 라벨과 ALV 제목은 코드에서 설정한다.
3. 아래 기존 DDIC/함수 의존성이 개발서버에 있는지 확인하고 **구문 검사 → 활성화**한다. 패키지·전송요청은 개발서버 기준으로 지정한다. 금액의 소수점 계산이 원본과 같도록 프로그램 속성 **고정 소수점 산술(Fixed point arithmetic)**을 반드시 활성화한다.
4. SE93에서 새 보고서 트랜잭션 **`ZHR5_CW_CMP`**를 만들고 이 프로그램의 선택화면 1000에 연결한다. 코드가 이 이름의 `S_TCODE` 권한을 명시적으로 검사하므로 SE38에서 실행해도 해당 권한이 필요하다. 기존 동일 이름이 있으면 새 코드와 트랜잭션 이름을 함께 조정한다.
5. 테스트 사용자에게 실행권한과 해당 인원의 `P_ORGIN` 읽기권한을 부여한 뒤 실행한다. 현재 검사는 INFTY=2010, SUBTY=8050, AUTHC=R 및 선택기간 종료일 기준 조직정보를 사용한다. 사내 P_ORGINCON·구조적 HR 권한을 사용하는 경우 보안담당자가 기존 관리자 조회 기준과 맞춰 검토해야 한다.
6. 처음에는 완료된 선택기간 하나와 사번 하나로 아래 검증을 수행한다. 확인 후 사번을 공란으로 실행해 전체 대상자의 결과와 수행시간을 확인한다.

이 프로그램은 저장 버튼이나 대휴 재생성 실행 버튼을 제공하지 않는다. 테스트를 위해 기존 정산 프로그램의 저장 루틴을 연결할 필요가 없다.

## 입력과 조회 대상

| 입력 | 의미 |
|---|---|
| 선택근무 시작일·종료일 | 둘 다 필수. 확정자료의 BEGDA/ENDDA와 **정확히 일치**하는 선택기간이다. 월 안에 걸치는 모든 기간을 찾는 조건이 아니다. |
| 사번 | 선택 입력. 공란이면 해당 기간의 정산 완료 대상자 중 조회권한이 있는 인원 전체다. |

정산 완료 대상은 `ZTHR0113`의 `Z52WKTP='0110'`, `Z52PRSQ='04'`, `ZADMIT_DT` 존재 여부로 찾는다. 현재 재직자만으로 제한하지 않는다. 동일 사번·선택기간에 서로 다른 확정월이 여러 건이면 기준이 모호하므로 계산 불가로 표시한다. PA0001 이력이 없거나 조회권한이 없으면 상세와 금액을 표시하지 않는다.

## 화면 사용법

사번·기간별 한 행에 다음 값을 나란히 표시한다.

- 원정산월·원정산일, 계산 상태, 비교 결과.
- **정산 당시 기간실비 / 재계산 기간실비 / 기간 차액**. 금액을 클릭하면 연장·야간·휴일·대휴 발생 실비·시차실비별 비교를 연다.
- **정산 당시 대휴수·시간 / 현재 등록 대휴수·시간 / 재계산 대휴수·시간 / 현재 대비 증감**.
- 현재 대휴 저장금액과 재계산 대휴 저장금액, 발생일/원천별 추가·삭제·변경 건수.
- 사용 표시·현금정산 표시가 있는 대휴수와 확인 사항.

**대휴 일자 상세**를 클릭하면 `원천 실적일 + 대휴 발생일`별로 기존/신규 개수·시간·저장금액과 추가 예정·삭제 예정·내용 변경·동일을 표시한다. 같은 개수의 대휴가 다른 날짜로 이동하면 기존 날짜 삭제와 신규 날짜 추가로 나타난다. 두 날짜를 임의로 일대일 짝짓지 않는다. 추가/삭제 건수는 이 날짜 조합의 개수이며 대휴 총 개수 증감과 다를 수 있다.

`정산 당시` 금액·대휴 집계는 ZTHR0113에 저장된 값이다. 상세의 `현재` 일자·시간·금액은 조회 시점 ZTHRBS01이다. 정산 당시 발생일 목록의 역사적 스냅샷이 없으므로 현재 목록을 당시 원본이라고 표시하지 않는다. 양쪽 집계가 다르면 확인 사항을 표시한다.

`차이 없음`은 **계산 결과가 같다**는 뜻이다. 실제 실적 수정 이력이 없다는 뜻은 아니다. 실적 수정 사실은 과거 실적 스냅샷/변경 로그를 별도로 확보해야 증명할 수 있다. 기존 ALV 필터로 차이가 있는 행만 볼 수 있다.

오류·자료 부족 시 새 금액·개수·시간을 `미계산`으로 표시한다. 0개/0원으로 계산된 정상 결과와 구별한다. 금액은 원, 시간은 `시간:분`이다. `미계산`을 같은 열에 표시하기 위해 금액·일부 개수 열은 문자 형식이며 숫자 합계/숫자순 정렬은 제공하지 않는다.

## 계산과 DB 접근

| 단계 | 처리 |
|---|---|
| 기존 자료 읽기 | ZTHR0113 확정값, ZTHR0132 기간 기준, ZTHR0112 기간실적, 현재 선택 대휴, 근태와 단가를 읽는다. |
| 가상 초기화 | 별도 내부테이블 `LT_VIRTUAL`에서만 ZDAEH/ZDAEH_DAY/ZDAEH_TM을 초기화한다. |
| 대휴 계산 | 로컬 `RC_CALCULATE`의 C 경로에서 기존 생성표시가 없는 상태로 새 대휴와 원천별 집계를 산출한다. |
| 가상 반영 | 신규 집계를 원천 실적 전체 키로 내부테이블에 반영한다. 새 대휴가 없는 실적은 초기화된 상태를 유지한다. 개수·시간이 신규 상세 합계와 일치하는지 확인한다. |
| 금액 계산 | 같은 자료의 B 경로에서 새 대휴 시간·개수를 적용한 기간실비를 계산한다. |
| 비교 | 원정산 금액과 비교하며, 현재 대휴와 새 대휴는 날짜별 합집합으로 비교한다. |

**직접 변경되는 업무 테이블은 없다.** ZTHR0112, ZTHRBS01, ZTHR0113, PA2010, FI 및 이력 테이블에 저장하지 않는다. 내부테이블의 MODIFY/DELETE는 조회 작업공간을 정리하는 구문이다. 삭제 후 ROLLBACK하는 방식도 사용하지 않는다.

기존 `ZHR_52TM_CW_CAL_AND_DAEH`를 호출하지 않는다. 한 프로그램만 등록할 수 있게 계산부를 로컬 FORM으로 분리했다. 차후 저장 기능이나 별도 함수 모듈로 옮길 때 같은 계산 입력/결과를 재사용할 수 있다.

계산부는 실적·근태·단가를 전달받으며 실적이나 대휴 DB를 다시 조회하지 않는다. 다만 기존 일별 시간분리·달력 보조함수는 계속 사용하므로 모든 환경정보까지 인수로 받는 완전 독립 계산기는 아니다. 하위 표준/외부 함수의 전체 구현은 이번 추출 범위에 없다. 개발서버에서 조회 전후 DB 불변과 실제 호출 경로를 확인해야 한다.

ZTHR0113 기간 금액은 내부 저장값에 100을 곱해 원 단위로 표시한다. BS01 생성의 ZD_MONEY는 원본 생성식에 이미 100이 들어가므로 다시 곱하지 않는다. 신규 BS01 예상 금액은 **ZD_MONEY 필드와 같은 타입에 먼저 대입**해 저장 시 반올림 단위를 맞춘다. 대휴 생성 금액은 원천 실적의 저장 단가, 기간실비는 기간 시작일 단가를 사용한다. 두 단가가 다르면 확인 사항을 표시한다.

ZTHR0113의 ZDAEHHR는 확정 저장 시 HHHHMM, ZTHR0112-ZDAEH_TM/BS01-ZD_TIME은 HHMMSS다. 신규 집계와 시간 증감은 분 단위로 계산한다.

## 기존 의존성과 첫 버전의 제한

- DDIC: ZTHR0113/0112/0132, ZTHRBS01, ZTHRCOST, ZTHREDITCOST, PA0001 및 ZSHR0111/0115/0137/0141/0143/0145/0146, ZTSHR0115, 관련 데이터요소·표준 ALV 타입을 사용한다. 새 DDIC는 없다.
- 직접 호출: `ZHR_52TM_AWART_LIST`, `ZHR_52TM_CALC_WORK_TIME_DAYILY`, `ZHR_GET_PERSONNEL_RANK_N`, `ZHR_GET_DAY_DATA`, `ZHR_MINUS_TIME_N`, `DAY_ATTRIBUTES_GET`, `RP_CALC_DATE_IN_INTERVAL`, `REUSE_ALV_GRID_DISPLAY`, `REUSE_ALV_COMMENTARY_WRITE`. 함수 내부의 추가 의존성은 기존 개발서버 구성을 따른다.
- ZTHRBS01과 ZTHRCOST 전체 DDIC, 외부 등급/달력/시간 함수 일부는 미추출이다. 표준 및 외부 객체의 타입·인터페이스는 개발서버 구문 검사 대상이다. 객체 부재를 의미하지 않는다.
- 현재 대휴는 `PERNR + RDATE의 선택기간 포함 + ZSOURFLEX='S' + STATE='3' + ZDAEH='Y'`로 찾는다. RDATE는 원본 생성 코드의 원천 실적일, ZDDAY는 발생일이다. 전체 외래키/사용참조까지 확정한 삭제 범위가 아니다. 원천 실적일 연결이 없으면 경고하며, 선택기간이 중복되면 재계산을 중단한다.
- 기존 B/C와 맞춰 실적 상태 3/H를 산입한다. 기존 A 소급은 E도 포함하므로 **E 상태 실적이 있으면 이번 조회는 계산 보류**로 표시한다. 전체 목록에서 사라지지는 않는다. 다른 제외 상태도 확인 사항을 표시한다.
- 월별 ZTHREDITCOST가 있으면 재계산은 **수기보정 전 자동 산식**이라는 경고를 표시한다. 월별 보정액을 개별 선택기간에 임의 배분하지 않는다. 따라서 실적 변경이 없어도 수기보정·달력·단가·기간기준의 변화 때문에 결과가 다를 수 있다.
- 사용 표시(ZDCHK 또는 ZDHDATE)와 정산 표시(JORGEH_TXT)가 있는 대휴도 조회한다. 이 표시는 향후 자동 적용 제외 검토용이다. JORGEH 금액만으로 정산 완료라고 판정하지 않는다.
- 조회 시점 스냅샷을 이력 테이블에 보존하지 않으며, 조회 중 다른 사용자의 변경을 잠그지 않는다. 검증은 다른 변경이 없는 개발 자료로 수행한다. 향후 저장 시에는 입력 변경 여부 재검증과 잠금이 필요하다.
- 화면의 양수/음수는 **기간 비교 차액**이다. 이미 지급한 소급분·급여 삭감분을 차감한 잔여 지급액이 아니며, 다음 달 확정 지급액으로 바로 사용할 수 없다. 기존 양수 소급 흐름을 보류시키는 코드는 없다.
- 대휴 사용 가능 시작/종료일의 새 값은 이번 일자 상세에 포함하지 않았다. 발생일 비교가 우선이며 실제 저장 구현 때 기존 기간 종료일 기준의 사용기간 산식을 함께 적용해야 한다.

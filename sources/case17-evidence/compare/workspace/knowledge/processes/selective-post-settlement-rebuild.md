# 선택근무 정산 후 대휴 재구성 검토

2026-10-29 후속: [기간 중 단가 변경 계산 검토](selective-rate-boundary-review.md). SRC-23은 ZTHREDITCOST의 이번 보정이 인상 전후 일자별 수기 계산 등록임을 확인했다. 현재 비교 프로그램은 시작일 단가를 사용하므로 차이를 실적 변경액으로 단정하지 않는다. 4주 시간 판정을 유지하는 날짜별 금액 계산은 검토안이며 아직 구현하지 않았다.

출처: [SRC-19 사용자 운영 설명과 신규 요구](../../docs/SOURCE_REGISTER.md#선택근무%20소급%20운영%20설명과%20대휴%20재구성%20요구%20—%20SRC-19), 2026-10-24. 기존 코드 근거는 SRC-17(2026-10-22 KSP/300)이다. 사용자 설명, 정적 코드 확인, 신규 설계 요구를 구분한다. 후속 요청에 따라 [조회 전용 신규 ABAP 개발안](../../proposals/20261024-selective-settlement-compare/README.md)을 작성했으며 원본 소스는 변경하지 않았다. 저장 기능은 미구현이고 SAP 활성화·실행·급여 삭감·실제 지급을 검증하지 않았다.

## 기존 운영과 앞선 제안의 정정

- 사용자 설명상 선택근무 실적 수정에 따른 추가 지급은 다음 달 선택근무 소급정산으로 처리한다. 음수 차액은 급여에서 삭감하므로 현 선택근무 소급에 음수 지급액으로 넣지 않는다. 급여 삭감의 구체적 프로그램·테이블·연계 방식은 미확인이다.
- 따라서 앞선 AI의 “이력에만 금액을 남기려면 양수 차액도 소급 보류해야 한다”는 제안은 이 요청에 적용하지 않는다. 양수의 기존 소급 경로를 유지한다. 신규 메뉴가 별도 지급을 만들거나 양수 차액을 추가로 전송하는 요구가 아니다.
- 기존 소급 함수는 과거 ZTHR0113의 ZRLPRDAMT 합계와 현재 재계산 기간실비 합계를 비교한다. 실제 분기는 `lv_sign > 1`일 때 소급금액을 만들고 그 외는 0이다. 이 내부 비교값을 임의로 원 단위 최소 지급 정책으로 해석하지 않는다.
- 신규 기능의 차액은 특정 선택기간에 대한 검토값이다. 기존 소급의 조회기간 합산·상태·보정 조건이 있어 화면의 기간 차액과 다음 달 최종 지급액이 항상 동일하다고 단정하지 않는다. 이미 지급/삭감된 차액과 반복 수정의 중복 처리 여부는 후속 대사 항목이다.

## 보조 근태 조회 0건의 의미 — 2026-10-26

SRC-19 후속 사용자 시험 결과 `result.XLS`에서 71명 중 11명이 `해당 데이터가 없습니다.`로 미계산이었다. SRC-17의 `ZHR_52TM_AWART_LIST` L503–509는 보조 근태 목록이 비어도 E와 M01 문구를 반환한다. 기존 `ZHR_52TM_CW_CAL_AND_DAEH` L166–173, L562–569는 이 반환을 중단 조건으로 사용하지 않는다. 따라서 이 문구만으로 기간실적 부재나 대휴 생성 불가를 판정하면 안 된다.

신규 비교 리포트의 반환 처리 오류를 수정했다. 근태 목록 0건 + 해당 함수의 0건 메시지 + 다른 반환정보 없음인 경우만 빈 근태 목록으로 계산을 계속한다. 다른 오류와 필수 기간실적/기준/단가 부족은 계속 미계산이다. 원본 함수·업무 DB는 수정하지 않았다. 수정 전 60명의 계산 결과는 사용자 파일에서 확인했지만 11명의 수정 후 금액·대휴와 실제 SAP 실행은 미검증이다. [수정본과 재검증 절차](../../proposals/20261024-selective-settlement-compare/README.md), [정정 기록](../../harness/feedback/FB-20261026-001.md)을 따른다. 정상 0건과 오류 구분에 관한 회귀 사례는 Q66이며 담당자 검토 대기다.

같은 날 사용자 표시 개선 요청으로 비교 열의 정산 당시/현재 등록/재계산/차액·증감을 각각 파랑/회색/녹색/노랑 계열로 구분했다. 요약과 두 상세 화면의 필드 카탈로그만 변경하며, 색상은 지급·정산 상태나 실제 차이 발생의 판정이 아니다. 계산·DB 처리에는 변경이 없고 SAP GUI 화면 확인은 대기다.

## 신규 기능의 의미와 조회

현재의 확정 금액 비교 기능에 더해, 해당 기간의 선택 대휴가 아직 생성되지 않았다는 계산용 상태에서 대휴 목록 전체를 다시 산출하는 신규 업무다. 월정산 취소나 사용·현금정산된 대휴의 상태 해제를 뜻하지 않는다. 앞서 사용자가 선택한 자동 적용 범위는 미사용·미정산 대휴다.

1. 당시 정산값, 현재 실적, 기존 생성 대휴의 원본 집합과 원본 키를 읽어 보존한다. 기존 실적이 삭제·재입력된 경우도 추적해야 하며, 연결이 불명확한 건은 자동 삭제 대상으로 확정하지 않는다.
2. 계산용 복사본에서 대상 실적의 ZDAEH/ZDAEH_DAY/ZDAEH_TM만 초기화한다. 대상 기간의 기존 선택 대휴를 생성 여부·중복 판단에서 제외한다. 근로실적·휴게·휴가 사용 사실·근태·소정시간·달력·단가, 다른 기간/유형의 필요한 자료는 보존한다.
3. 해당 선택기간 전체를 다시 계산하여 발생일별 새 대휴 목록을 만든다. 익일 중복 검사도 같은 계산용 자료와 이번에 새로 산출한 목록을 사용한다.
4. 새 대휴 결과를 계산용 실적에 반영한 후 기간실비와 항목별 금액을 계산한다. 원정산 기간실비와 비교하고, 현재 등록 대휴와 새 대휴 목록의 차이도 표시한다.
5. 조회와 미리보기에서는 ZTHR0112/ZTHRBS01을 포함한 업무 DB를 변경하지 않는다. 임시 삭제·수정 후 ROLLBACK하는 방식도 사용하지 않는다.

실적 변경 여부와 결과 변경 여부는 별개다. 대휴 개수·시간·총액이 같아도 발생일 또는 원천 실적이 달라졌다면 재구성 차이가 있다. 기존 목록과 새 목록을 날짜별로 1:1 대응한다고 가정하지 않는다. 사용시작일·종료일도 해당 선택기간 등 실제 생성 기준으로 계산하며, 새 발생일만으로 임의 이동시키지 않는다.

## 저장은 기존 집합 삭제와 새 집합 생성

저장 대상은 해당 사번·선택기간의 생성원천이 확인된 선택 대휴 집합이다. 기존 ZTHRBS01 생성 구분은 ZSOURFLEX='S'이지만 이 값 하나만으로 삭제 범위를 정하지 않는다.

1. 적용 직전 입력자료 변경, 대휴 사용·정산 및 관련 참조를 재확인한다. 변경되었으면 다시 미리보기를 요구한다. 혼재·연결 불명확 건의 자동 적용은 제외한다.
2. 삭제 전 원본 실적·대휴 키와 전체 값, 계산 근거, 새 결과를 이력에 보관한다. 기존 실적↔삭제 대휴↔새 대휴 연결과 처리번호를 남긴다.
3. ZTHRBS01에서 **사전에 확보하고 재검증한 기존 대휴 집합**을 삭제한다. 새 발생일 목록으로 삭제하면 사라진 날짜의 옛 대휴가 남으므로 금지한다. 다른 기간·다른 근무유형의 대휴는 삭제하지 않는다.
4. 새 결과의 발생일·시간·금액·사용기간으로 ZTHRBS01을 새로 생성한다. 기존 순번을 날짜별로 무조건 재사용하지 않는다. 실제 전체 키·참조 관계는 DDIC 및 운영 자료 확인 후 결정한다.
5. ZTHR0112의 대상 실적 키 전체에 대해 ZDAEH/ZDAEH_DAY/ZDAEH_TM을 새 결과와 일치시킨다. 새 대휴가 없는 실적도 공란/0으로 반영하여 옛 값이 남지 않게 한다. 전체 결과 0개도 정상 결과이며 새 대휴 INSERT만 없는 처리다.
6. 원본 삭제, 새 대휴 삽입, 실적 갱신, 이력 저장을 하나의 트랜잭션으로 처리한다. 실패하면 모두 되돌린다. 중간 COMMIT이 있는 기존 저장 FORM을 그대로 호출하지 않는다.

ZTHR0113 원정산 금액·시간·대휴 집계, PA2010, 기지급 FI 전표는 이 메뉴에서 변경하지 않는다. 재계산 금액과 차액은 이력에 기록한다. 양수는 이후 기존 선택 소급 경로에서 새 대휴 상태를 사용해 계산하도록 하고, 음수는 인사부의 급여 삭감 검토 근거로 남긴다. 이력 저장이나 대휴 재구성 완료를 지급·삭감 완료로 표시하지 않는다. 계산 결과에 차이가 없으면 불필요한 삭제·재생성을 생략하는 설계가 가능하다.

## 남은 구현 확인과 검증 계획

- 조회 개발안은 독립 보고서 ZRPTH411_COMPARE다. [소스와 적용/검증 조건](../../proposals/20261024-selective-settlement-compare/README.md)을 함께 읽는다. 기간 확정 코호트, 복사본 초기화→대휴 재계산→복사본 반영→기간실비 계산 순서이며, E 상태·수기보정·혼재 단가·현재 원장과 확정 집계 차이는 별도로 표시한다. 새 코드 작성과 SAP 적용 완료는 다르다.
- ZTHRBS01 전체 DDIC와 원천 실적/사용신청 참조 관계는 [미추출 의존](../../maps/sources/EXT-ZTHRBS01.md)이다. 과거 삭제·재입력 건을 포함한 대상 집합의 유일 식별을 확인해야 한다.
- 미리보기와 저장이 같은 계산부·근태·단가·달력·상태 기준을 사용하도록 한다. 기존 A와 B/C의 상태 차이를 무시하고 두 함수를 연속 호출하지 않는다. 하위 함수의 DB 재조회/저장 의존성은 구현 때 계속 확인한다.
- 다음 달 소급 실행 전에 대휴 재구성을 완료하는 업무 순서, 반복 보정/기소급/급여 삭감 후의 대사, 여러 기간의 양수·음수 합산 처리는 실제 표본으로 검증한다. 기존 소급 전체를 개편하거나 양수를 보류하는 새 정책으로 확대하지 않는다.
- 개발계 검증: 조회 후 DB 불변, 같은 개수의 발생일 이동, 추가·소멸·시간 변경, 전체 0개, 삭제·재입력 실적, 익일·기간 경계, 사용·현금정산 혼재, 조회 후 동시변경, 저장 실패 전체 롤백, 같은 입력의 반복 적용, 다음 달 소급 결과.
- 문서 회귀 기준은 [Q61–Q65](../../tests/business-qa.md)에 별도 기록한다. SAP 실행 검증은 NOT_RUN이다.

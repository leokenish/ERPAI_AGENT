SRC-17의 `ZHR_52TM_AWART_LIST` L503–509는 보조 근태 목록이 비어도 E와 M01 문구를 반환한다. 기존 `ZHR_52TM_CW_CAL_AND_DAEH` L166–173, L562–569는 이 반환을 중단 조건으로 사용하지 않는다. 따라서 이 문구만으로 기간실적 부재나 대휴 생성 불가를 판정하면 안 된다. 신규 비교 리포트의 반환 처리 오류를 수정했다. 근태 목록 0건 + 해당 함수의 0건 메시지 + 다른 반환정보 없음인 경우만 빈 근태 목록으로 계산을 계속한다. 다른 오류와 필수 기간실적/기준/단가 부족은 계속 미계산이다. 원본 함수·업무 DB는 수정하지 않았다. 수정 전 60명의 계산 결과는 사용자 파일에서 확인했지만 11명의 수정 후 금액·대휴와 실제 SAP 실행은 미검증이다. [수정본과 재검증 절차](../../proposals/20261024-selective-settlement-compare/README.md), [정정 기록](../../harness/feedback/FB-20261026-001.md)을 따른다. 정상 0건과 오류 구분에 관한 회귀 사례는 Q66이며 담당자 검토 대기다. 같은 날 사용자 표시 개선 요청으로 비교 열의 정산 당시/현재 등록/재계산/차액·증감을 각각 파랑/회색/녹색/노랑 계열로 구분했다. 요약과 두 상세 화면의 필드 카탈로그만 변경하며, 색상은 지급·정산 상태나 실제 차이 발생의 판정이 아니다. 계산·DB 처리에는 변경이 없고 SAP GUI 화면 확인은 대기다. ## 신규 기능의 의미와 조회 현재의 확정 금액 비교 기능에 더해, 해당 기간의 선택 대휴가 아직 생성되지 않았다는 계산용 상태에서 대휴 목록 전체를 다시 산출하는 신규 업무다. 월정산 취소나 사용·현금정산된 대휴의 상태 해제를 뜻하지 않는다. 앞서 사용자가 선택한 자동 적용 범위는 미사용·미정산 대휴다. 1. 당시 정산값, 현재 실적, 기존 생성 대휴의 원본 집합과 원본 키를 읽어 보존한다. 기존 실적이 삭제·재입력된 경우도 추적해야 하며, 연결이 불명확한 건은 자동 삭제 대상으로 확정하지 않는다. 2. 계산용 복사본에서 대상 실적의 ZDAEH/ZDAEH_DAY/ZDAEH_TM만 초기화한다. 대상 기간의 기존 선택 대휴를 생성 여부·중복 판단에서 제외한다. 근로실적·휴게·휴가 사용 사실·근태·소정시간·달력·단가, 다른 기간/유형의 필요한 자료는 보존한다. 3. 해당 선택기간 전체를 다시 계산하여 발생일별 새 대휴 목록을 만든다. 익일 중복 검사도 같은 계산용 자료와 이번에 새로 산출한 목록을 사용한다. 4. 새 대휴 결과를 계산용 실적에 반영한 후 기간실비와 항목별 금액을 계산한다. 원정산 기간실비와 비교하고, 현재 등록 대휴와 새 대휴 목록의 차이도 표시한다. 5. 조회와 미리보기에서는 ZTHR0112/ZTHRBS01을 포함한 업무 DB를 변경하지 않는다. 임시 삭제·수정 후 ROLLBACK하는 방식도 사용하지 않는다. 실적 변경 여부와 결과 변경 여부는 별개다. 대휴 개수·시간·총액이 같아도 발생일 또는 원천 실적이 달라졌다면 재구성 차이가 있다. 기존 목록과 새 목록을 날짜별로 1:1 대응한다고 가정하지 않는다. 사용시작일·종료일도 해당 선택기간 등 실제 생성 기준으로 계산하며, 새 발생일만으로 임의 이동시키지 않는다. ## 저장은 기존 집합 삭제와 새 집합 생성 저장 대상은 해당 사번·선택기간의 생성원천이 확인된 선택 대휴 집합이다. 기존 ZTHRBS01 생성 구분은 ZSOURFLEX='S'이지만 이 값 하나만으로 삭제 범위를 정하지 않는다. 1. 적용 직전 입력자료 변경, 대휴 사용·정산 및 관련 참조를 재확인한다. 변경되었으면 다시 미리보기를 요구한다. 혼재·연결 불명확 건의 자동 적용은 제외한다. 2. 삭제 전 원본 실적·대휴 키와 전체 값, 계산 근거, 새 결과를 이력에 보관한다. 기존 실적↔삭제 대휴↔새 대휴 연결과 처리번호를 남긴다. 3. [SRC-12, 2026-09-23 사용자 설명] 현재 기준을 묻거나 시행일 이후 계산 예시를 들 때는 인상 대상임을 전제로 9,240원을 사용한다. 8,400원은 시행 전 사례 또는 인상 제외 대상임을 명시할 때만 사용한다. 과거 협의·매뉴얼의 수치를 일괄 치환하지 않는다. 확인 상태: 변경 금액과 시행일은 사용자 설명으로 확인했다. 공식 승인문서 열람, SAP 배포·실제 지급 검증을 수행했다는 뜻은 아니다. 이 정리본 전체의 담당자 검토는 대기 상태다. ## 직군별 현행 기준 — SRC-13 후속 정정 2026-09-23 사용자 정책 설명에 따라 연봉계약직·특정업무직은 2026-09-01부터 모두 시간외 A등급을 적용하고, 방송지원직은 계속 D등급을 적용한다. [SRC-11 L328–366, 2026-09-16~18; 협의 정리본](../feedback/SRC-10-early-SRC-11.md) ## 앞선 선택근무 예시의 단가 정정 조건: 인상 대상, 관련 근무일·연장 발생일 모두 2026-09-01 이후, 소정 160시간, 평일 170시간, 휴일 3일 각 8시간, 대휴 3일/24시간, 지급 대상 연장 10시간, 야간·시차 없음. 시간 산정 조건은 앞선 예시 그대로 두고 단가만 정정한다. 실제 SAP 계산 결과가 아닌 설명용 산술이다. | 항목 | 정정 계산 | 금액 | |---|---|---:| | 연장실비 | 10×9,240 | 92,400원 | | 휴일실비 | 24×9,240×0.5 | 110,880원 | | 합계 | 92,400+110,880 | **203,280원** | 별도 대휴 3일은 동일하다. 종전 예시 184,800원 대비 18,480원 증가한다. 단가 변경이 근무시간·대휴 발생조건을 변경했다는 근거는 없다. 근거: 시간 구성 [SRC-02 pp.5–6], 연장실비 검증식 [SRC-11 L139–143, 2026-08-28], 단가·시행일 [SRC-12]. 원래 답변과 수정 이력은 [FB-20260923-001](../../harness/feedback/FB-20260923-001.md)에 기록한다. ## 2026-10-29 수기 운영 확인과 계산 개선 검토 SRC-23 사용자 확인: 기존 선택 정산은 시작일 단가를 4주 전체에 적용하여 2026-09-01 인상을 일별로 나눌 수 없었다. 인사부가 8월 8,400원·9월 9,240원으로 일자별 수기 계산한 결과를 ZTHREDITCOST에 등록했다. 수기보정의 목적을 확인한 것이며 개별 계산·승인·지급 정확성 검증은 아니다. SRC-23 후속 확인에 따라 한 입력은 익일로 넘어가도 입력 시작일 단가를 적용하고 단가 때문에 자정 분할하지 않는다. 대휴는 BS01 생성 단계에서 일자로 확보한 단가를 사용하는 기존 경로를 유지한다. 기간 대휴실비는 새 대휴 명세의 단가·시간을 합산하도록 검토한다. 마지막 산식의 단가 상속을 앞 단계 날짜 조회의 부재로 오해하지 않는다. 코드 수정·SAP 실행은 미수행이다. ### 인상 제외와 익일 입력 기준 — SRC-23 후속 - 2026-09-01 단가 경계를 넘는 한 실적도 입력 시작일 단가로 계산한다. 8월 31일 시작해 9월 1일 종료하면 해당 입력 전체는 8월 31일 단가다. 자정 이후 시간을 별도 단가로 바꾸지 않는다. 기존 휴게/야간/휴일 판정은 보존한다. - 시차실비는 인상하지 않았으며 기존 계산값을 유지한다. 사용자 표현은 “현재 12000원?”으로 정확한 액수는 잠정 기억이다. 기존 협의 정리본에도 근무당 12,000원으로 기록돼 있다(SRC-10 L3061–3067, 2026-08-03). 이번에 원문 또는 운영값을 재검증한 것은 아니며 새 고정값을 하드코딩하지 않는다. - 재량근무·간주근무 단가도 이번 인상에서 제외한다.

# 강사용 진행 예시

## 1. 돈 두 칸부터 시작하기

“휴일에 일한 대가로 먼저 받는 돈”과 “대신 쉬지 못했을 때 추가 정산할 돈”을 달력 두 칸에 나누어 놓는다. 단가 10,000원, 토6/일2에서 먼저 받는 금액이 둘 다 30,000원이지만 이유는 0.5배와 1.5배로 다름을 묻는다. 합계 60,000원을 두 배 한 120,000원과 실제 대휴 추가 정산 목표 60,000원을 비교한다. 이후 토6/일6과 토3/일2로 바꾸어 ×2가 항상 틀린 것은 아니라는 반례를 보여 준다.

## 2. 세 장의 메모를 두 날짜에 꽂기

토8·일2·토2 메모를 차례로 보여 준다. 총 근무는 토10+일2, 날짜는 2개다. 날짜별 서랍에 메모를 넣으면서 기존 MODIFY가 토요일 앞 80,000원을 뒤 20,000원으로 교체하는 장면을 설명한다. 시간 분할 자체와 금액 합산을 분리한다. 이 중간 상태를 실제 최종 지급액이라고 소개하지 않는다.

토8·일6·토2로 바꾸면 토요일 금액은 같지만 일요일 대휴가 하나 더 생기는 예시가 된다. 날짜 수 2개와 실제 대휴 수 1개/2개가 별개의 질문임을 강조한다.

## 3. 사용자가 마음을 바꾸는 장면

“계산하면 기록하고, 바로 읽고 지운다고 생각했다”는 M062를 그대로 읽는다. 그 후 화면 재계산 경로의 쓰기와 저장 분기의 삭제를 나누어 보여 준다. 이전 DB 값이 다음 요청까지 남는 조건을 명시하고, 익일 해제 → 새 쓰기 건너뜀 → 과거 행 조회 → 읽은 뒤 삭제를 한 단계씩 진행한다.

질문: “저장 후 임시 테이블을 열었더니 비어 있다. 그러면 과거 값이 영향을 주지 않은 걸까?” 답은 아니다. 이미 이전 값을 JORGEH에 복사한 뒤 삭제됐을 수 있다. 단, 실제 COMMIT/ROLLBACK은 운영 검증이 필요하다는 조건을 생략하지 않는다.

## 4. AI 활용에서 배울 점

- AI가 후보를 많이 제시한 것을 정답 개수로 세지 않는다.
- 사용자의 “확정 전에 이미 틀렸다”는 시간 정보가 후보를 좁혔다.
- “그 2시간은 어디서 왔나?”라는 질문이 AI의 예시 조건을 명확히 했다.
- 선택 CW·A·D/T/B를 구분한 뒤 적용 대상을 좁혔다.
- 이미 있는 반환 구조를 활용해 새 인터페이스를 만들지 않는 제안을 구성했다.
- 원본 보존, 줄번호·패치·검증 결과로 제안을 검토 가능한 상태로 만들었다.
- 로컬 파서·모형 PASS를 SAP 운영 검증 완료로 바꾸지 않았다.

## 5. 마무리 실습

학습자에게 SAVE-03을 보여 주고 토8/일6/토2를 정렬·합산한 결과를 손으로 적게 한다. 이어 F03-03을 보여 주고 “동일 원행의 중복”과 “같은 날짜의 서로 다른 구간”을 구별하게 한다. 마지막으로 SAVE-02에서 복사 목록의 JORGEH 한 줄을 찾게 한다. ABAP 문법 암기보다 ‘무슨 값이 어디로 가야 하는가’를 설명하게 하는 것이 목적이다.

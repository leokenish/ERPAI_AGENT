먼저 알아둘 것

이 자료는 “AI가 한 번에 정답을 맞힌 이야기”가 아닙니다.

사용자의 구체적인 질문으로 AI의 예시와 적용 범위를 바로잡고, 실제 코드로 확인한 것과 아직 실행하지 않은 것을 구분한 사례입니다. 사용자의 오해만을 원인으로 돌리지 않습니다. 발견한 위험도 실제 반기 보정 건의 원인으로 확정하지 않았습니다.

왜 이 구간을 고쳤나

당시 이해 → AI 확인 → 수정 결정 → 전후 코드. 원본·제안의 줄번호를 함께 봅니다.

03 · 근거로 돌아가기

대화 전문과 원본

질문·공개 답변·진행 안내까지 그대로 보존했습니다. 후속 정정도 지우지 않습니다.

같은 용어를 쓴다고 같은 코드 경로는 아닙니다.

용어를 일상 언어로 읽기

대휴
휴일 근무에 대해 나중에 쉴 수 있도록 발생하는 휴무. 여기서는 발생한 날짜와 금액을 함께 추적합니다.
휴휴
한 번의 근무가 휴일인 첫날과 휴일인 다음 날에 걸친 경우.
휴일실비
해당 근무에 대해 먼저 계산되는 금액. 여기서 쓰는 합계는 설명용 휴일분이며 전체 시간외 총액과 구별합니다.
대휴 정산금액 · JORGEH
대휴를 사용하지 않았을 때 추가 정산에 사용할 금액. 이 사례는 그 금액이 올바르게 전달되는지 다룹니다.
계산 행
컴퓨터가 계산하기 쉽게 나눈 한 줄. 3줄이라고 3일 근무하거나 대휴가 3개라는 뜻은 아닙니다.
키
DB 행을 찾아 구분하는 주소. 기존 임시 테이블은 사번과 날짜를 사용합니다.
MODIFY / ADD
MODIFY는 같은 키의 행을 바꿀 수 있습니다. ADD는 숫자를 더합니다. 저장한다고 자동 합산되지는 않습니다.
임시 DB / 내부 테이블
임시 용도의 DB는 공유 저장소입니다. 내부 테이블은 실행 중 사용하는 작업 목록입니다. CLEAR·REFRESH로 DB 행을 지우지는 않습니다.
ZTOMO
익일 여부. 이 값만으로 두 날짜가 모두 휴일인지 알 수는 없습니다.
정적 확인 / 실행 검증
소스의 조건·구문을 읽은 것과 실제 SAP에서 입력·저장한 결과를 검증한 것은 다릅니다.

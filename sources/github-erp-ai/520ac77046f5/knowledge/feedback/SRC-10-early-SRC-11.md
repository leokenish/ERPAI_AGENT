# KBS 근로시간 업무 지식 근거 노트 — SRC-10 전반부 / SRC-11 전체

상태: 원문 검토 초안, 실무자 미확인. 이 문서는 카카오톡의 역사적 요청·협의·설명·완료보고를 분리한 근거 노트다. 현행 승인 정책, 법률 판단, 실제 소스 코드·운영 데이터의 독립 검증 결과로 사용하지 않는다. 직원은 사례 A 등으로 익명화했고 불필요한 사번·성명·가족·건강 정보는 제외했다. 기술 명칭은 원문 표기를 유지했다.

## 2. SRC-10: 요청·처리·설명 이력

### 2.1 2026년 3월: 권한, 퇴직자, 전표, 간주/재량

- **3/4, 권한 부여 보고와 화면 확인.** ERP 인사권한을 부여했다는 설명에 대해 담당자가 메뉴 노출을 확인했고, 명칭은 ‘14.근로시간관리’로 확인됐다. 시간외 담당자의 전표결재 권한도 필요해 보여 ‘00공통 - 00ERP업무담당자관리’를 안내했다. 후자는 필요성/경로 안내까지이며 사진의 구체 설정 내용은 확인 불가다. [SRC-10 L6–29, 2026-03-04]
- **3/5, 해외출장 취소 시 간주근로 해제 문의 — 미결.** 해외출장 간주근로 신청 후 출장 취소로 해당 날짜 일반 업무 입력이 막혔고, 본인이 직접 간주근로 해제 가능한지 문의했다. ‘다큐인사이트 해외출장 취소 정산 요청의 건 (2603).pdf’ 파일 참조가 있으나 본문 미확인. 이 구간에는 답변/해제 완료가 없다. [SRC-10 L30–33, 2026-03-05]
- **3/7, 퇴직자 PA2010 제외와 140,400원 판단의 정정.** 선택근로 퇴직자 2명을 pa2010에서 제외해야 전표를 생성할 수 있다는 인수인계 설명에 따른 삭제 요청이 있었다. 사례 A의 일별 실적 140,400원과 월마감 0원 차이를 처음에는 지급 누락으로 보아 통상근무 pa2010에 140,400원을 넣는 방향까지 확인했다. [SRC-10 L34–54, 2026-03-07]
- **같은 날 후속 확인에서는 초기 지급 판단이 확정되지 않았다.** 사례 A는 1/31 퇴직이었고 선택근로 대상 등록이 2/1까지 남아 2월 조회에 잡혔으며, 실제 보인 근무일은 1월이고 2월 입력 실적은 없다는 설명으로 바뀌었다. ‘1월에 0원 정산이었으니 2/1 종료인 기간을 2월 정산으로 지급해야 할 수도 있다’는 담당자 의문 후 전화로 넘어갔다. 최종 텍스트는 두 사람 pa2010 삭제 완료와 감사 응답뿐이다. 따라서 **140,400원 최종 지급 여부/귀속월 미확인**, 선택기간 삭제 완료도 미확인이다. [SRC-10 L55–107, 2026-03-07]
- **3/9~3/10, 퇴직 정산 추출 지원.** ‘테이블직접보기’에서 bs01 다운로드를 위해 66명의 사원번호를 붙여 넣었으나 전부 들어가지 않는 현상이 보고됐고 원격 확인을 약속했다. 다음 날 정산이 무사히 마무리됐다는 사용자 보고가 있다. 붙여넣기 장애의 구체 원인·해결 절차는 텍스트에 없다. [SRC-10 L110–125, 2026-03-09~10]
- **3/10, 인사정보 검색 권한 경로.** ‘20.인사관리 10.인사마스타 관리 20. 인사정보검색’ 권한 요청은 발령사항 확인 목적이며, 이후 인사운영부 IT 담당에게 요청하는 사안이라는 정정이 있었다. 권한 부여 완료는 기록되지 않았다. [SRC-10 L127–130, 2026-03-10]
- **3/16, FI전표생성 메뉴 동일성 설명.** 통상/선택/재량/간주 폴더 각각의 FI전표생성은 같은 메뉴를 폴더별로 배치한 것이고, 해당 정산 구분을 선택해 사용한다는 설명이다. 구체 프로그램명/트랜잭션 코드 검증은 없다. [SRC-10 L132–142, 2026-03-16]
- **3/17, 퇴직급여 산정을 위한 대휴 금액 문의.** 시간외 실제 지급 요청인지 퇴직급여 계산용 정산금액 확인인지 구분했고 후자라고 확인됐다. 1/17·1/18 양일 휴일에 걸친 대휴 사례에서 처음 29,700원씩 총 59,400원으로 설명했다가 하루 대휴 사용 사실을 확인해 29,700원으로 정정했다. 정산기간 밖에는 해당 메뉴에서 금액이 안 보인다는 설명도 있다. 화면과 전화 후속 설명은 없어 일반 계산식으로 확장할 수 없다. [SRC-10 L159–185, 2026-03-17]
- **3/18, 재량근무 중 해외출장 간주근로 중복 차단 — 검토 단계.** 출장시스템에 간주근무가 붙어 있어 재량근무자도 간주 신청 가능하다는 설명이다. 업무 담당자는 ‘재량근무는 수행 방법·시간배분을 재량에 맡기므로 출장에도 기존 재량 적용이 계속된다’는 답변을 현업에 했다고 보고했다. 이는 담당자 정책 해석이며 규정 원문 확인 아님. [SRC-10 L186–194, 2026-03-18]
- **양방향 차단 방안.** 재량 대상자가 간주 신청하지 못하게 하고, 이미 간주인 대상자도 재량 등록되지 않게 해야 한다는 아이디어가 제시됐다. 출장시스템이 시간외 쪽 재량명단을 참조해 차단하는 방향은 가능해 보였지만 반대 방향은 추가 검토가 필요했다. 팀 내부 논의 후 재요청하기로 했으며 구현/운영 반영 완료는 없다. [SRC-10 L195–210, 2026-03-18]
- **3/19 요청 → 3/20 양식 교체 완료보고.** ESS 통상근무 시간외 신청화면의 ‘시간외실비 입력기한 경과분에 대한 Kobis 내부결재 양식’이 구버전이라는 신고에 따라 선택근로 화면과 같은 첨부로 교체 요청했고, 다음 날 ‘파일 바꿨어요’라고 보고했다. 첨부 표기는 ‘시간외실비 입력기한 경과분 내부결재 양식.hwp’. 새 양식의 내용/승인 범위는 이 대화만으로 확인되지 않는다. [SRC-10 L212–228, 2026-03-19~20]
- **3/20, 선택 누락분 휴일 대휴 0시간 — 미결.** 휴일 5시간 이상 근무한 선택근로자의 누락분 처리에서 대휴시간이 모두 0이라 금액이 과다해 보인다는 신고와 ‘대휴 확정/생성 작업이 필요한가’라는 질문이 있었다. 직원별 ‘선택일별 입력 후.xlsx’ 2개와 사진이 언급되나 텍스트 답변/최종 조치는 없다. [SRC-10 L238–248, 2026-03-20]
- **3/20, 일회성 운영 중단 공지.** 운영서버 이슈로 16:30에 잠시 내렸다 올리고 16:40 재접속을 안내했다. 정기 정산 규칙이나 반복 작업 일정으로 해석하면 안 된다. [SRC-10 L249–257, 2026-03-20]
- **3/27, 선택근로 신청 취소 삭제 완료보고.** 3/30부터 선택 신청한 직원이 단축근무 대상이라 선택명단에서 제외해야 하는 사례에서 인사마스터 삭제만으로 전 시스템 삭제가 되는지 질문했고, 삭제명단을 두 담당자에게 메일 공유하도록 안내했다. 같은 날 삭제 완료보고가 있다. 삭제 프로그램을 나중에 만들겠다는 언급은 계획이며 해당 프로그램 완료 증거는 없다. [SRC-10 L258–267, 2026-03-27]

### 2.2 2026년 4월: 시차실비, 정산 순서, BS01 해석, 입력 예외

- **4/1, 통상 시차실비 12,000원 제외의 사유 설명.** 3/6 근무분의 기한 경과 입력에서 시차실비만 제외해 3월 정산 전에 조정하려는 요청이다. 담당자는 ‘5일이 지나면 시차실비는 임금형식이 아니어서 임금체불에 해당하지 않으므로 지급하지 않는다’는 내부 설명을 전달했다. **법률 결론이 아니라 당시 담당자의 설명**으로 보존하며, 5일의 달력일/근무일 계산 방식은 이 대화에 없다. [SRC-10 L281–315, 2026-04-01]
- **4/1 최초 수정은 저장 성공 뒤 상신 단계에서 실패.** ERP 재접속 후 입력하도록 수정 완료보고가 있었고 담당자도 정상 저장을 확인했다. 그러나 같은 날 결재 상신 후 12,000원이 다시 포함된 금액으로 바뀌었다고 보고했다. 개발 담당자는 상신까지 영향을 주는 구조라 승인 완료 후 인사부가 고치는 순서로 바꾸는 방안을 제시했다. 최초 저장 성공을 최종 정산 성공으로 기록하면 안 된다. [SRC-10 L316–323, L346–357, 2026-04-01]
- **4/2 승인 완료건 수정 방식으로 변경·사용자 확인.** 승인 완료건도 선택→변경→‘시차제외’ 체크→금액 저장이 가능하도록 조치했다는 보고가 있다. 삭제 상태였던 사례의 3/6 시차근무 51,900원 건을 승인 상태로 변경한 뒤 담당자가 수정했고, 개발 담당자가 정상이라고 답했다. 사용자는 정산에 잘 들어갔는지는 한 번 더 확인하겠다고 했다. 승인 이후 수정 방식은 당시 합의/운영 설명이며 최종 지급 검증은 별도다. [SRC-10 L359–383, 2026-04-02]
- **4/1 선택근로의 관리자 입력 경로.** 선택근로자도 통상과 동일 기준으로 입력기간을 열어주며 담당자가 대신 입력 가능하다고 설명했고 메뉴는 ‘14.60.10 관리자용앱’이다. 선택+시차의 체크박스 조정 방안은 당시 아이디어였고 실제 기한경과 지급요청 사례는 아직 없다고 정정했다. [SRC-10 L324–344, 2026-04-01]
- **4/29 선택+시차 실제 발생 — 통상 기능과 다름.** 5일 경과분에서 시차근무 기록은 남기고 시차실비 12,000원만 빼려 했으나, 당시 선택근무는 체크와 금액이 연동되어 체크 시 정산에 무조건 12,000원이 들어간다는 설명이다. 통상처럼 시차실비만 제외하는 기능은 별도 구현이 필요했다. 일단 시차 체크 없이 입력·결재·월정산하고 나중에 체크를 넣자는 임시 합의까지 있으며, 체크 복원/별도 기능 완료는 확인되지 않는다. [SRC-10 L913–939, 2026-04-29]
- **4/3, 선택근로 중도 퇴직 처리와 신청 취소의 구분.** 4주 종료 전 3/13 퇴직 사례에 대해, 재직자 정산에서 pa2010을 빼고 퇴직자 정산으로 넘기는 방법을 설명했다. 선택기간/대상자 자체를 삭제하는 것은 해당 기간 선택 신청을 취소하는 사람을 대상으로 했던 과거 운영이었다. 3월 선택 pa2010은 4월 정산 시 들어가므로 정산 완료 후 삭제 요청해야 한다는 설명이다. 날짜 ‘6~7일’은 한 메시지에서 ‘퇴직자’로 혼용되지만 전후 질문은 6~7일 재직자·8일 퇴직자 정산이다. [SRC-10 L385–401, 2026-04-03]
- **4/6, 늦은 선택 대상자 제외요청 처리.** 제외문서를 늦게 제출한 선택근로 대상자 삭제를 메일로 요청했고 같은 날 삭제 완료보고가 있다. 삭제 범위·개별 데이터 상세는 메일/사진을 보지 않아 확정할 수 없다. [SRC-10 L402–408, 2026-04-06]

- **4/22 선택 대휴가 BS01에 보이는 이유.** 과거 bs01에 실비·근로시간 0, 입력구분·업무내용 공란인데 대휴일만 부여된 행이 나타나는 것은 선택근로자의 대휴 생성 시 대휴정보가 bs01에도 저장되기 때문이라는 설명이다. ‘BS01 0원 행=오류’로 일반화하면 안 된다. [SRC-10 L647–655, 2026-04-22]

[SRC-10 L661–713, 2026-04-23]

### 2.3 2026년 5월: 미결, 휴게시간, 소급, 출제위원, 생성 후 고정 데이터

- **5/6 전월 입력/결재 마감 질문과 문자 요청.** 담당자는 ‘5일에 시스템이 자동 닫히는 것이 아니라 입력은 가능하되 6일부터 정산이라 전월 입력하면 안 되는지’ 질문했고, 연휴로 결재시일 ‘근무일 3일 후’ 전에 정산이 닥친다고 설명했다. 4월 시간외 입력분 결재를 5/6 오전까지 끝내지 않으면 미결로 4월 정산 지급 불가라는 전사 문자 초안을 제안했다. 답변은 문자시스템 건수 조정 안내였으며 **자동폐쇄 여부·마감 규칙 질문에 직접 답한 기록이나 실제 발송 완료는 없다.** [SRC-10 L940–950, 2026-05-06]

- **8/24 교대 스케줄과 IAM 기본값의 우선순위.** 실제 스케줄은8/23 00~09시 조근인데 입력 기본값18~24시가 떴고 직원이 직접 지워00~09시로 입력·결재 완료한 사례다. 개발 담당자는 시간외입력 IAM 설정이18~24시로 되어 있어 워크스케줄보다 우선한다고 설명했다. IAM은 본인 변경 가능하며 교대자는 스케줄 기본값을 쓰도록 개인 IAM을 지우라는 안내로 정리했다. 우선순위 코드 변경이나 실제 IAM 삭제 완료는 기록되지 않았다. [SRC-11 L4–35, 2026-08-24]
- **8/24 단가 인상 일정 협의와 소급 우려.** 시스템은8/26 반영→8/27 노출을 전제로 준비했고, 협의가9월 이후로 밀리면 소급 가능하냐는 질문에 담당자들은 소급 없는 전제를 유지하자는 입장을 밝혔다. 과반노조/직원의견 절차에 관한 발언은 당시 내부 논의 설명이며 법적 적정성 판단 근거로 사용할 수 없다. 공식 승인 문서/의결 사실은 이 대화에 없다. [SRC-11 L36–66, 2026-08-24]
- **8/26 인상단가 반영 예정.** ‘오늘 시스템 반영 예정, 내일부터9/1 근무일은9,240원 단가’라는 안내가 있다. 이는 시스템 반영 예정과 적용 근무일을 구분한 증거다. 8/26 실제 배포 완료·전 직원 적용 검증은 별도로 확인해야 한다. [SRC-11 L75–80, 2026-08-26]
- **선택기간 등록 취소 완료보고 두 사례.** 8/24에는8/24~9/20 4주 등록 삭제 요청→당일 삭제처리 보고,9/9에는8/17~9/13 4주 삭제 요청→당일 완료보고가 있다. 퇴직자 PA2010 제외와 달리 선택 대상기간 취소 사례다. [SRC-11 L67–74, 2026-08-24; L271–280, 2026-09-09]
- **8/27 재량 신청 누락분은 선택과 달리 자동 산입 안 됨.** 사례 L은6/30 기존 신청 종료 후7/1~8/15 재량 사후신청. 미정산8/1~8/15는 등록 후 정산하되 이미 정산 완료된7월은 누락으로 처리해야 했다. 2023-12의 선례를 참고해8월 정산 때7월 재량 대상 등록→시간외담당자가 대휴 생성→시스템 금액 확인 후 개발 담당자에게 pa2010 추가 요청이라는 개별 처리 방안을 확인했다. pa2010 추가는 금액 공유 후 언제든 가능하다는 설명이다. 선례 원데이터를 독립 확인한 것은 아니다. [SRC-11 L81–101, 2026-08-27]
- **9/2 재량 누락 합산은 대상월·확정상태·프로그램 유형 구분 필요.** 사례 L의 합계 요청은7월750,000원+8월375,000원+450,000원=1,575,000원으로 바뀌었다. 개발자의 추가 완료보고 뒤 수당관리 화면에 누락합산이 보이지 않고7월 확정처리 내역으로 잡히며 지급확정까지 된 것처럼 보인다는 연속 재문의가 나왔다. 최종 요청은8/1~8/15 ‘2TV일일’ 건에7월750,000+8월375,000=1,125,000원을 합치고8/16~8/31 ‘단막’450,000원은 따로 두는 것. **9/2 마지막 수정 요청에 대한 최종 완료/재확인 기록은 SRC-11에 없다.** [SRC-11 L146–154, L174–195, 2026-09-02]
- **8/27~8/28 당번특근과 통상 차이 및 저장 시 금액/유형 변화 — 미해결.** 같은 근무의 필수시간·실비가 달랐고 통상 익휴 체크를 해도 당번특근과 같지 않다는 신고. 샘플은15:30~익일09:00, 휴게16:00~16:30 및 익일07:30~08:30, 입력시33,600원이나 저장 후8,400원 누락/통상유형으로 표시된다는 내용이다. 7/1·7/2 테스트 삭제 이력은 삭제 완료보고가 있으나 금액 문제는 별도 분석 중이었다. [SRC-11 L102–125, 2026-08-27]
- **당번특근 설명과 잔여 쟁점.** 개발 담당자는 통상 선택 시 다음날 전부 연장, 당번특근 시 다음날8시간을 소정으로 보아 필수근로시간 설정이 다르다고 설명했다. 그러나 담당자는 당번특근에서 초과1시간이 떠서는 안 될 것 같다고 재질문했고 디버깅하겠다는 답변까지다. 이 설명을 ‘익휴 모든 경우의 확정 산식’으로 확장하면 안 된다. [SRC-11 L127–145, 2026-08-28]
- **8/28 검증용 연장실비 계산식.** 담당자가 공유한 엑셀 검증식은 ‘연장실비=(최대근로시간−대휴시간)×시간외기준단가(8,400원 OR 9,240원)’이다. 9/1 단가 변경 계산 논의에 사용한 담당자 수식이며 실제 프로그램 전 분기의 확정 산식이나 엑셀 내용 검증 결과가 아니다. [SRC-11 L139–143, 2026-08-28]
- **9/2 과거 누락분 중복 합산 신고.** 사례 M의6/24·6/25 누락212,100원을8월 정산에 주려는데 이미7월에6/12 누락8,400원을 지급한 이력이 있어,6월 누락 조회 시220,500원으로 다시 합산된다는 신고다. 같은 메시지에212,100과212,000이 혼재한다. 산술상212,100+8,400=220,500이며 **212,000 표기는 원문 오기 후보**로 보존하고 원본을 고치지 않았다. 조회 금액만으로 재지급 완료를 단정할 수 없다. 확인 약속까지 기록됐다. [SRC-11 L155–164, 2026-09-02]
- **9/7 사용자별 조회 차이와 일별 단가 오류.** 같은 누락 건이 업무 담당자 화면에는 수정212,100원, 다른 담당자 화면에는 수정 전으로 보인다고 재신고했다. 이어5명의 월마감과 일별 차이에 대해 일별 ‘단가’가9,240원으로 잘못 들어간 사례를 발견했다고 보고했다. 원인·대상근무일·캐시/권한 등의 기술 원인은 설명되지 않는다. 이후 선택 정산금액 확인을 무사히 마쳤다는 전체 보고는 있으나 각 오류별 수정 절차/검증 증거는 없다. [SRC-11 L244–253, 2026-09-07]
- **9/7 연차 반영 수정의 회귀와 롤백 완료보고.** 사례 N의8/24~8/28 휴가가 잘 보이다 사라졌고, O의8/28 및8/31~9/2도 누락됐다. 특정 직원 연차 오류 조정이 전체에 영향을 미쳤다는 담당자 진단에 따라 롤백 진행→완료보고가 나왔고 원래 대상자만 수작업하기로 했다. 그 대상자의7/29 연차가 다시 뜬다는 확인이 있다. 전 대상 전 기간 정상화 시험이나 원인 소스코드를 확인한 것은 아니다. [SRC-11 L196–215, 2026-09-07]
- **9/7 누락 테이블과 합계 프로그램 불일치 해결 확인.** 사례 P의 누락은 테이블직접보기에 있으나 ‘sumT1’을 돌리면 합산되지 않는다고 신고했다. 개발자는 해당 사번만 넣어 돌려 ‘sum1t’에 반영될 것이라 안내했고 사용자가 잘 들어갔다고 확인했다. **sumT1와 sum1t는 원문 표기가 서로 달라 실제 동일 객체인지 미검증**이다. 정확한 프로그램/테이블명을 추정해서 정규화하지 않는다. [SRC-11 L218–226, 2026-09-07]
- **9/7 정산 순서와 퇴직자 PA2010.** 선택 정산금액 확인 후 전표 생성을 위해 퇴직자3명을 pa2010에서 제외 요청했고 삭제 완료보고가 있다. 사용자는 선택 정산이 되어야 재량·간주 정산이 가능하다고 설명했다. SRC-10의 통상→선택 설명과 연결되나 전체 시스템의 불변 의존관계를 소스 검증한 것은 아니다. [SRC-11 L253–269, 2026-09-07; SRC-10 L410–421, 2026-04-06]

## 5. 정정·충돌·미확인 사항의 우선 확인 질문

1. **대휴 기한의 기준일과 승인 근거:** 선택은 기간종료일, 재량은 기간종료일, 간주는 사용시작일 기준이라는6월 설명이 각 지침의 승인·유효 범위와 맞는가? 간주의12월분 다음해12월 만료 문제를6/10 이후 변경했는지 SRC-10 후반과 대조해야 한다. 현재 규칙으로 단정하지 말고 변경 전/후를 분리해야 한다. [SRC-10 L1686–1701, 2026-06-09; L1725–1767, 2026-06-10]
2. **출제위원 미보상과 부장급 조회:** 일반직 출제위원도 미보상이라는 업무설명과 과거 정산 화면 흔적은 실제 지급금액0/사용처리일 가능성이 남는다. 사용내역을 미보상으로 배분하려는 조회 요구와 보상 지급 대상 제외를 어떻게 분리했는가? 부장급 표시 변경이 이후 완료됐는가? [SRC-10 L1337–1429, L1455–1461, 2026-05-21]
3. **기한3일/5일의 대상 차이:** 시차실비 기한5일, 정기문자 상신3일,5월 결재시일 ‘근무일3일 후’는 입력·상신·승인 중 무엇이며 달력일/근무일을 어떻게 세는가? 기간 숫자만 보고 서로 충돌한다고 단정하지 않는다. [SRC-10 L308–313, 2026-04-01; L940–946, 2026-05-06; SRC-11 L284–305, 2026-09-11]
4. **선택 시차12,000원 제외 기능:** 통상은4/2 승인완료건 변경으로 처리했으나 선택은4/29 체크/금액 연동으로 별도 구현 필요 상태였다. 정산 후 체크 복원이 과거 재정산 시12,000원 재산입을 유발하지 않는지, 후속 기능 개발 여부를 확인해야 한다. [SRC-10 L363–383, 2026-04-02; L916–938, 2026-04-29]
5. **퇴직자 지급 누락과 PA2010 삭제:** 정산 전후 재직상태 필터가 야간2,700원을 누락시킨 사례가 있으며 선택기간 대상자 삭제와 PA2010 전표 제외는 서로 다른 처리다. 개별 삭제 범위·퇴직정산 재지급/중복 방지 기준을 확인해야 한다. [SRC-10 L386–399, 2026-04-03; L968–985, L1034–1036, 2026-05-07]
6. **누락/환급과 고정 과거데이터:** 원 정산월을 최종전표 기준으로 유지하는 설명, 누락 추가 후 대휴시간 고정, 기지급 누락8,400원 재합산은 서로 다른 층위다. 현재 재계산·대휴 재생성·기지급 차감의 책임과 표시 화면을 확인해야 한다. [SRC-10 L1242–1249, 2026-05-18; L1478–1505, L1544–1553, 2026-05-26~27; SRC-11 L155–164, 2026-09-02; L244–247, 2026-09-07]
7. **재량 누락 사례의 최종 상태:**7월750,000원을8/1~15 건에 합친1,125,000원,8/16~31 별도450,000원, 총1,575,000원이 올바른 정산월/미확정 상태에 반영됐는가?9/2의 ‘추가했다’ 이후에도 잘못된 월·확정상태 지적이 있었으므로 최초 완료보고만으로 닫으면 안 된다. [SRC-11 L150–195, 2026-09-02]
8. **단가 적용일·직군·기존 입력 보정:**9/1근무일부터9,240원 반영 예정, 과거 일별에9,240원이 잘못 잡힌 사례, 신규 계약직5,400원→등급A→9,240원은 대상과 시점이 다르다.9/22 목표였던 과거분 보정 완료와 실제 근무일 기준 분기를 확인해야 한다. [SRC-11 L75–78, 2026-08-26; L250–253, 2026-09-07; L328–364, 2026-09-16~18]
9. **일시 수기보정의 표준화 여부:**재난 체크를 잠시 쓰고 삭제, 실제 시간과 다른 임시 입력, 휴일2개 입력 제한을 개별 해제한 것은 당시 예외 조정이다. 승인 문서·원실적 대조·후속 정산 검증 없이 반복 가능한 표준으로 문서화하면 의미가 바뀐다. [SRC-10 L609–645, 2026-04-20~21; L767–911, 2026-04-28; L1113–1174, 2026-05-11; L1192–1213, 2026-05-12]

# ZHR5 주요 처리 흐름 — 정적 분석 초안

각 단계는 실제 읽은 코드의 동작이다. **[확인]**은 소스상 사실이고 운영 실행 결과가 아니다. 근거 ID는 [객체 지도의 원본 경로 사전](object-map.md)에 연결된다. 함수 내부의 호출 대상 중 미추출·미검토 부분에서 설명을 멈춘다.

검토 순서: 추출 범위·객체 목록 → ZRPTH401 → ZRPTH402와 TOP/F01 → BSP 요청·연결 함수 → 함수그룹 공통 FORM → 승인·DDIC 대조 → PA2010의 FI 연결 일부. 아래는 이해하기 쉽도록 업무 순서로 정리했다.

## F01. 탄력근로 계획 조회·저장·상신·회수·삭제

**진입점:** `Z52_FLEX_TIME/FLEX_WORK_PLAN_ESTABLISH.htm`, 함수 `ZHR_52TM_PLAN_WORK_TIME`. 입력은 사번, 시작/종료일, 근로유형, 주기, 주간계획유형, 일일계획 `T_DAILY`, 기간계획 `T_TOTAL`이다. 이 페이지는 `I_Z52WKTP=0120`, `I_Z52PRSQ=02`를 전송한다. [S01](object-map.md#s01) 1630–1646, 1753–1786행

| 단계 | [확인] 코드에 있는 처리 | 근거 |
| --- | --- | --- |
| 웹 요청 | `FUNCTION_NAME=ZHR_52TM_PLAN_WORK_TIME`을 `../ZWEB_COMMON/AJAX_COMMON.HTM`으로 전송. 상신 요청 시 먼저 S로 저장하고, 성공 callback에서 반환된 계획을 사용해 A 요청을 구성 | S01 1771–1786, 1950–2082 |
| 조회 R | 사번·유형·기간 겹침·순번·동적 상태 조건으로 ZTHR0106 조회. I_ZDAILY가 있고 기간계획이 있을 때 ZTHR0107 조회 | [S02](object-map.md#s02) 68–134 |
| 저장 S | T_DAILY가 비어 있으면 오류. `get_plan_save`에서 겹치는 계획 중 STATE 0이면 순번 재사용. 없으면 STATE 5 건을 2로 바꾸는 경로를 거쳐 새 순번 결정 | S02 138–151; [S03](object-map.md#s03) 582–618 |
| 계획 계산·기록 | 주차/주간시간 계산 함수 호출, 일일 휴게시간 차감 및 가산시간 포함 집계, 기간 STATE=0. ZTHR0106과 ZTHR0107 변경이 성공하면 COMMIT, 실패 분기에서 ROLLBACK | S03 634–808 |
| 상신 A 검사 | 두 입력 테이블 중 하나라도 비어 있으면 CHECK에서 진행하지 않음. ZTHR0101의 ZLIMIT으로 `기준 시작일 - ZLIMIT`을 구해 현재일이 그보다 늦으면 오류. 주차별 필수시간과 계획시간이 같지 않으면(ABAP `<>`) 오류. 결재자 이름 공백·외부 결재자 검사 오류 시 중단 | S02 156–161; S03 884–947 |
| 상신 A 기록 | `ZWF_START_WORK_HR`에 ZWFTYPE=E와 결재자 목록 전달. 성공 시 STATE=E, ZSERIAL=반환 WF 키, 상신자·상신일을 기록하고 계획 두 테이블을 변경·커밋 | S03 951–1014 |
| 회수 B | ZWF_DELETE에 WF 키와 KEY_2=E 전달. 성공 시 계획 STATE=5로 변경·커밋 | S02 165–225 |
| 삭제 D | 해당 사번·기간에 ZTHR0110 실적이 존재하면 중단. 승인 STATE=3 계획이면 해당 기간 PA9021 레코드 삭제 경로가 있으며, 계획 STATE=2로 변경. 성공 후 승인계획 삭제 통보 FORM 호출 | S02 230–307 |
| 초기화 N | 입력 일일계획이 있으면 첫 행 순번과 기간을 기준으로 ZTHR0107을 삭제한 후 `get_plan_save` 호출 | S02 315–337 |

**[추론]** 기간 Header와 일일 Line Item을 함께 보존하고, 저장 후 상신하는 계획 업무로 해석할 수 있다. 저장 성공과 결재 승인 완료는 별도 상태다.

**[확인 필요]** AJAX dispatcher의 실제 함수 호출·권한, ZLIMIT 운영 값, 외부 결재자 선정·WF 생성 및 메일 전송은 확인하지 못했다. 시간 검사 주석은 “미달”이라고 쓰지만 실행 조건은 `<>`여서 초과도 배제할 수 있다. 이를 현재 사규라고 단정하지 않는다. 화면 주석의 회수 R과 함수 분기 B의 차이도 담당자 확인 대상이다. [Q04–Q07](open-questions.md#q04)

**[미검토]** 휴게·주간시간 계산 함수 내부, get_break_time/get_work_time 등 보조 FORM의 전체 예외 분기. 따라서 최대 근무시간·특례·휴일 처리 전체 규칙은 아직 설명할 수 없다.

## F02. 계획 승인·반려와 근무정보 반영

**진입점 후보:** `ZHR_52TM_APPROVE_OT_DATA`. 입력은 결재자 `I_PERNR`, 결재 대상 `IT_WF0015`다. 요청유형 P/R은 각각 계획/실적이며 DDIC `ZD52REQTP`와 일치한다. 실제 운영 화면 또는 WF에서 이 함수를 호출하는 경로는 미확인이다. [S05](object-map.md#s05), [S21](object-map.md#s21)

1. **[확인]** 대상별 `ZHR_52TM_VALID_DATE_CHECK`를 `I_OPT=A`로 호출한다. 반환 구조가 비어 있지 않으면 그 대상을 건너뛴다. 이 함수 내부의 날짜 정책은 미검토다. S05 125–147행
2. **[확인]** 계획 P 분기는 `ZSERIAL=KEY12`, `STATE=E`인 ZTHR0106을 읽는다. 못 찾으면 실패 건수를 늘리고 ROLLBACK 후 다음 대상으로 간다. 150–162행
3. **[확인]** `update_approve_result` 매크로는 ZORDR와 결재자 일치 여부 및 ZSTAT Y/N에 따라 승인 플래그·STATE를 변경한다. 단순 분기에서는 Y→3, N→9지만, ZORDR=02에는 결재 단계별 별도 분기가 있으므로 모든 승인 입력이 즉시 STATE=3이라고 말할 수 없다. 64–115, 167–175행
4. **[확인]** 계획 P에서 `WA-ZSTAT=Y`이면 사번·겹치는 기간·근로유형 0120~0140 조건의 PA9021을 조회한다. 기존 행이 있으면 오류 처리하고, 없으면 기간·근로유형·주기를 담아 PA9021을 MODIFY한다. 이어 ZTHR0106을 MODIFY한다. 178–210행
5. **[확인]** ZSTAT Y이면 외부 `ZWF_APPROVE_WORK`, N이면 `ZWF_REJECT_WORK` 호출. 반환이 비어 있지 않으면 ROLLBACK·실패 집계, 비어 있으면 COMMIT·성공 집계한다. 410–450행

**[추론]** 계획 승인 입력을 HR 근무정보와 결재 엔진에 연결하는 처리다. **[확인 필요]** PA9021 기록 조건은 최종 STATE가 아니라 `WA-ZSTAT=Y`에 걸려 있다. 다단계 결재에서 이 분기가 언제 호출되는지, 중간 승인과 최종 승인에서 원하는 시점에 반영되는지 확인해야 한다. PA9021 직접 DB 변경이 존재하지만 미추출 정보형 클래스 검증까지 수행한다고 설명할 수 없다.

**[미검토]** 실적 R 분기 안의 상세 시간/대휴·금액 생성, 결재 화면의 호출 체인. 따라서 전체 승인 트랜잭션의 원자성이나 모든 실적 승인의 효과를 보장하지 않는다.

## F03. 탄력근로 계획 미결처리 배치

**진입점:** `ZRPTH401`. 입력은 P_DATE(기본 현재일), P_WKTP(기본 0120), S_PERNR다. 본문은 141행 전체를 읽었다. [S06](object-map.md#s06)

1. **[확인]** P_DATE에 유효한 ZTHR0101의 `ZCONST=ZLIMIT`을 조회한다. 없으면 메시지 후 종료한다. 종료일은 `P_DATE + ZLIMIT - 1`이다. 39–54행
2. **[확인]** 사번 범위, BEGDA가 계산 구간 안에 있음, STATE가 0 또는 E인 ZTHR0106을 읽는다. **P_WKTP는 이 SELECT 조건에 사용되지 않는다.** 56–61행
3. **[확인]** 대상이 없으면 종료하고, 있으면 ZSTATE_1의 F 설명을 요청한다. 각 대상에 ZSERIAL이 있으면 `ZWF_DELETE(TABNAME=ZWF0022, KEY_2=E)` 호출로 회수를 요청한다. 68–109행
4. **[확인]** WF 회수 실패 행은 내부 테이블에서 제거하고 다음 건으로 넘어간다. 그 외 행은 STATE=F와 변경자·시각을 설정한다. 111–126행
5. **[확인]** 남은 내부 테이블을 ZTHR0106에 일괄 MODIFY하고 성공하면 COMMIT, 실패하면 ROLLBACK한다. 129–135행

**[확인 필요]** 실제 잡/변형의 사용 범위, P_WKTP 미사용 의도, ZLIMIT 값·변경 책임자. `GV_TOT`은 회수 실패 행을 제거하기 전에 계산되어 마지막 “완료 건수”를 실제 성공 건수로 해석하면 안 된다(90, 113, 132행). 배치가 현재 운영에서 매일 실행된다고는 확인하지 않았다.

## F04. 탄력근로 월 정산 계산·확정·취소

**진입점:** `ZRPTH402` → `ZRPTH402TOP`, `ZRPTH402F01`. 월 PA_YYMM, 유형 PA_ZWKTP(기본 0120), 주기 PA_ZSEQ(기본 02), 정산일 PA_ADMDT, 소급 옵션/시작월을 입력한다. RB1 조회·취소, RB2 월 정산금액, RB3 미결처리, RB4 월 합계 분기다. [S07](object-map.md#s07) 78–175행, [S08](object-map.md#s08) 127–158행

| 단계 | [확인] 코드에 있는 처리 | 근거 |
| --- | --- | --- |
| 입력 검사 | RB2에서 정산일이 없거나 소급 옵션에 소급 시작월이 없으면 메시지 후 종료 | S07 54–61 |
| 조회·분기 | 승인 계획 STATE 3, 월 확정 ZTHR0120, 관련 PA2010/8030 조회. RB2는 이미 GT_0120에 있는 사번을 REJECT하고 `set_calc_weekly_amt` 호출 | S07 81–110, 149–158 |
| 월 지급 계산 | `ZHR_52TM_MONTHLY_PAYMENT`에 사번·월·유형·주기·소급 옵션·`I_OPT=X` 전달. 반환 중 WPAYEND가 월말 이하인 건을 표시 데이터로 구성 | [S09](object-map.md#s09) 13–50 |
| 함수의 대상·주 구간 | 월과 겹치는 STATE 3 계획, 주기·유형을 조회. 계획 시작일에서 7일 간격으로 주 구간을 구성하고 계획 종료일로 제한. I_OPT=X일 때 주 계산 함수 호출 | [S10](object-map.md#s10) 98–106, 176–244 |

| 계산식 일부 | 연장/야간/휴일/대휴 계산 호출의 계수는 각각 1.0/0.5/1.5/0.5. CALC_OT_AMOUNT가 시간의 시·분을 변환해 단가×시간×계수로 계산. 이후 set_round_amt 호출 | S10 675–711; [S11](object-map.md#s11) 48–76; [S03](object-map.md#s03) 2591–2610 |
| 확정 명령 | PAI의 CONF에서 확인 팝업 응답 후 `confirm_data`. 화면 flow logic·GUI status 자체는 미추출 | S09 383–420 |
| 확정 기록 | 표시된 금액을 사번별로 COLLECT하여 PA2010에 SUBTY/LGART=8030, KRW, 시작/종료일=PA_ADMDT로 구성. 0 이하 금액 행 제외. PA2010 변경 → ZTHR0110 정산일 변경 → COMMIT → ZTHR0120 변경 순서 | S09 540–625 |
| 확정 취소 | CONFC에서 `cancle_confirm_data`. 코드상 AWREF가 있는 PA2010 건을 제외하고 삭제, 관련 실적 정산일 초기화, ZTHR0120 삭제 | S09 422–447, 814–923 |
| 실적 미결 | RB3의 표시 대상에서 선택행 DONE 처리 시 ZTHR0110 STATE=F와 처리일·처리자 변경, 성공/실패별 COMMIT/ROLLBACK | S07 117–124; S09 449–497, 1096–1123 |

**[추론]** 계획/실적을 기반으로 월별 지급 후보를 계산하고 PA2010에 정산 결과를 연결하는 단계다. PA2010에 기록하는 것만으로 급여 계산·회계 전표·실제 지급 완료를 의미하지 않는다.

**[확인 필요]** 확정 코드의 COMMIT은 ZTHR0120 변경 **앞**에 있다. 따라서 후속 실패의 ROLLBACK으로 앞선 모든 변경이 취소된다고 설명할 수 없다. 취소 FORM에도 명시적 COMMIT이 보이지 않아 전체 호출/화면 트랜잭션 경계의 추가 확인이 필요하다. 담당자가 운영 성공·실패 사례와 재처리 절차를 제공해야 한다. [Q08](open-questions.md#q08)

**[미검토]** 일별 시간 산정·휴일·대휴·소급 차액의 전체 분기, 단가/등급 산출의 전체 경로. 계수는 이 코드의 인수일 뿐 현행 지급 규칙의 완전한 설명이 아니다. 원단위라는 주석만으로 반올림 동작을 확정하지 않는다. 실제 FORM은 ROUND에 `DECIMALS=1`, `SIGN='+'`를 전달하므로 타입과 운영 예제를 함께 확인해야 한다.

## F05. 통상/교대 시간외근무 저장과 상신

**진입점:** `ORD_OT_INSERT.htm`의 요청과 `ZHR_52TM_MOBILE_OVERTIME_APPR`. 화면은 IS_ZSHR0131에 신청 내용을, I_MODE에 신규/수정 구분, I_ACTION에 작업을 담는다. 저장 결과에서 사번·근무일·순번을 돌려받는 흐름이다. [S12](object-map.md#s12), [S13](object-map.md#s13)

1. **[확인] 웹:** APPR 입력을 우선 SAVE로 바꿔 요청한다. 저장 성공 callback은 상세 조회로 진행하는 분기가 있고, 별도 변경 조회 성공 callback에서 APPR 요청을 보낸다. 모든 중간 조회 함수 본문은 아직 검토하지 않았다. S12 1864–1877, 1880–1912, 2031–2068행
2. **[확인] SAVE:** 신청 데이터 변경 FORM·초과시간 계산 FORM·외부 `ZHR_52TM_CHECK_APPROVER_N` 호출 뒤 `ZHR_52TM_GET_OVERTIME_SAVE`를 호출한다. 반환 T_DATA를 ZTHRBS01에 MODIFY하고 첫 행의 사번/RDATE/SEQNR를 반환하는 경로가 있다. S13 143–225행
3. **[확인] 가공 함수:** GET_OVERTIME_SAVE는 `ZHR_52TM_GET_OVERTIME_DATA`를 호출하여 시간·금액·대휴 정보를 받는다. 신규 건의 STATE=0/미상신을 설정한다. 회수 상태 5 건을 2로 바꾸는 경로, 2일 대휴 분할 경로, 누락 표시 시 승인 상태 3을 설정하는 특수 분기도 있다. S14 40–114, 174–277, 294–360행
4. **[확인] 저장 위치의 예외:** 일반 경로는 T_DATA를 가공해 호출자에게 돌려주지만, 대휴 2일 분할 분기에서는 함수 안에서 ZTHRBS01을 직접 MODIFY한다. 또 ZHRDAEHUAMT 금액을 읽은 후 삭제하는 코드가 있다. 항상 “가공만 하는 함수”라고 설명하면 안 된다. [S14](object-map.md#s14) 165–169, 208–212, 277, 360행
5. **[확인] APPR:** 기존 데이터를 대상으로 특정 일자 이후 재계산/저장 경로를 거친 뒤 날짜 검사 함수 호출, 오류이면 RETURN. 이후 GET_OVERTIME_REQUEST에 대상 테이블을 넘긴다. S13 276–355행
6. **[확인] 상신 함수:** GET_OVERTIME_REQUEST는 외부 안식년 관련 판정 함수 `ZHR_GET_RETIREMENTAGE`를 호출하며, E1 예외와 LV_GUBUN/LV_ANNUAL 조합에 따른 중단 분기가 있다. 상신자·1차 결재자 목록을 구성해 `ZWF_START_WORK_HR(ZWFTYPE=F)`를 호출한다. [S15](object-map.md#s15) 24–92행
7. **[확인] 상신 결과:** WF 호출 성공 및 ZTHRBS01 행 조회 성공 시 STATE_TXT를 결재중, ZSANGSIN을 Y, ZNO를 반환 WF 키로 바꾼다. MODIFY 성공 건마다 COMMIT한다. 이 코드에서 STATE 자체를 E로 할당하지는 않는다. 성공/시도 건수를 비교하여 결과 코드를 반환한다. S15 94–132행

**[추론]** 시간외 신청 데이터와 결재 요청을 연결하는 경로다. 함수명의 APPR는 이 문맥에서 **결재 상신**이므로 최종 결재 승인 처리와 혼동하지 않는다.

**[확인 필요]** 외부 dispatcher·결재자/안식년 판정·WF 본문, ZTHRBS01 DDIC 정의와 운영 데이터, 누락 표시 시 자동 승인 규칙의 허용 범위. GET_OVERTIME_REQUEST의 2차 결재자 조건은 현재 입력 LS_DATA가 아니라 LS_ZTHRBS01-ZCOSA1을 검사한다(70–78행). 의도와 실제 2단계 상신 결과는 담당자 확인이 필요하다. 외부 함수까지 포함한 저장 단위·동시 실행 안전성을 확정할 수 없다.

**[미검토]** GET_OVERTIME_DATA·일별 시간/단가 계산, 변경/상세 조회 함수, 삭제·회수 및 대휴 분할 보조 FORM의 전체 동작.

## F06. PA2010에서 FI 업무로 넘어가는 일부 연결

**[확인]** ZRPTH2012_M 메인은 전표처리/역분개·EDI·조회/재수행에 따라 FORM을 나눈다. `get_post_data`는 PA2010을 PA0000과 연결하여 선택 임금유형 P_LGART, 기준일 P_DATE, 사번 범위, AWREF 공백 등의 조건으로 조회한다. `update_pa2010`은 선택 구분별 subtype을 정하고 PA2010-AWREF에 전달된 전표번호를 기록한다. [S16](object-map.md#s16) 38–77행; [S17](object-map.md#s17) 42–94, 1204–1231행

**[추론]** F04가 만든 PA2010/8030 결과가 조건에 맞으면 전표처리 프로그램의 입력 후보가 될 수 있다. 두 프로그램 사이의 자동 호출·배치 순서나 실제 8030 설정 선택을 이번에 검증한 것은 아니다.

**[미검토]** 전표 생성 본체, BDC 화면, 역분개·EDI, 전표 후 정보형 생성, 오류 복구, 관련 FI 패키지. 헤더의 “F-63/IT0015/IT0267/EDI” 설명만으로 실제 회계 처리 전체를 확정하지 않는다. 이 항목은 FI 확장을 위한 조사 시작점이다.
